- 日期：2026-11-17
- 状态：**已实施（2026-11-17）**
- 实施验证：v3 专项套件 4 个脚本、83 项断言全通过（t1 28 / t2 13 / t3 28 / t4 14）；全量回归 6 套件全绿（spec-driven 141 项、oneclick-stress 76 项、command-visibility 69 项、dirs-space-path 91 项、hdd-align-field 233 项；memory-guard 6 个脚本 ALL PASS）
- 取代：`2026-11-17-cpu-mem-calibration-design.md`（v2，机型预设 + 双上限）
- 标定样本：用户提供的四组 2×海光 7380（64C/128T）案例
- 目标：任意新配置都能由硬件参数直接推导，不依赖机型查表；四组案例作为回归样本

## 0. 结论摘要

```text
CPU worker  = round(物理核数 C × 1.5625)                 # 64C → 100
VM worker   = DIMM 根数
单 worker   = 单条容量 − max(6G, 单条容量/8)             # 32→26, 64→56, 128→112
总量        = 单 worker × VM worker
上限        = min(模块总容量×88%, MemTotal×92%,
                  MemTotal − (盘数×hdd-bytes×1.2 + 8G))
hdd worker  = 每块数据盘 1 个（系统盘仅在 --sysdisk 时 +1）
```

`1.5625 = 100/64`，来自案例“64 物理核用 100 个 CPU worker”的标定；它等价于 SMT 开启时逻辑线程的 78%，SMT 关闭时是 1.56 倍超订。

## 2. 输入探测

| 输入 | 来源 | 失败兜底 |
|---|---|---|
| 物理核数 C | `lscpu -p=Core,Socket` 去重计数；或 `/proc/cpuinfo` 的 (physical id, core id) | 用 `round(nproc×78%)`；nproc 也失败则报错退出 |
| 逻辑线程 T | `nproc` | 同上 |
| DIMM 根数 | dmidecode 非空槽位；失败用 EDAC | 中止并提示手动 `--vm`（沿用现状） |
| DIMM 容量 | dmidecode `Size`，统一换算为 GiB（GB 按 GiB 处理） | 混合容量/无容量 → 回退总量法 |
| MemTotal | `/proc/meminfo`（MB） | 中止，要求显式 `--vm-bytes` |
| 盘数 D | `--dirs` 数量 + `--sysdisk` 时 +1 | D=0（纯 CPU/内存） |
| hdd 每轮字节 | `--hdd-bytes`，默认 10G | 默认 10G |

## 3. CPU 分配

### 3.1 公式

```text
CPU worker = max(1, (C × 25 + 8) / 16)      # 整数四舍五入，25/16 = 1.5625
```

| 物理核 C | CPU worker | 说明 |
|---|---|---|
| 64（2×32C） | 100 | 复现案例 |
| 96（2×48C） | 150 | 新配置自动推导 |
| 48 | 75 | |
| 32（单路 32C） | 50 | |
| 16 | 25 | |

### 3.2 为什么按物理核，而不是按逻辑线程

- 案例是 64C → 100，按物理核标定后，SMT 开/关都得到同一个 worker 数；
- SMT 开启（T=2C）时，100/128≈78%，留 22% 给 VM/hdd/内核；
- SMT 关闭（T=C）时，100/64≈156%，是案例口径的超订；若现场不希望超订，用 `--cpu` 显式覆盖；
- 机型（5380/7360/7380）不再参与 CPU 计算；`--model` 只保留线程数交叉校验告警。

### 3.3 兜底

- 物理核识别失败：`max(1, round(nproc × 78%))`；
- `--cpu` 显式值始终优先，不参与任何推导。

## 4. 内存分配

### 4.1 单根容量规则

```text
reserve  = max(6, 单条容量 / 8)        # 整数 GiB
单 worker = 单条容量 − reserve
VM worker = DIMM 根数
```

| 单条容量 | 预留 | 单 worker | 占单条 |
|---|---|---|---|
| 16G | 6 | 10G | 62.5% |
| 32G | 6 | 26G | 81.25% |
| 64G | 8 | 56G | 87.5% |
| 128G | 16 | 112G | 87.5% |

### 4.2 三道上限取最小

```text
cap_module = 模块总容量 × 88%
cap_mem    = MemTotal × 92%
cap_disk   = MemTotal − (D × hdd_bytes × 1.2 + 8G)     # D=0 时视为无穷大
cap        = min(cap_module, cap_mem, cap_disk)

若 单worker × 根数 > cap：逐 GiB 下调 单worker，直到 ≤ cap；<1G 则报错
```

- `cap_module`：保证不把模块容量吃穿；案例 2/3 的 87.5% 正好在 88% 内；
- `cap_mem`：防止 MemTotal 因保留内存/ECC 偏低时 OOM；
- `cap_disk`：给页缓存和脏页留空间，盘越多、内存越小，自动压得越低；
- 系数 1.2 与 8G 为工程余量常量，集中定义，便于后续调整。

### 4.3 兜底路径

| 情况 | 目标 | 上限 |
|---|---|---|
| 容量已知且一致，vm=DIMM 数 | 单根规则 | 三道上限 |
| 混合容量 / 无容量（EDAC） | MemTotal×82% 均分 | MemTotal×92% |
| 显式 `--vm` ≠ DIMM 数 | MemTotal×82% 均分 | MemTotal×92% |
| 显式 `--vm-bytes` | 原样保留 | 只告警，不裁剪（沿用现状） |

## 5. 硬盘分配

```text
每块数据盘 1 个 hdd worker，--hdd-bytes 默认 10G，循环到 timeout
系统盘仅在 --sysdisk 时额外 1 个 worker
```

- 盘数只影响 hdd 进程数和 `cap_disk` 的预留，不影响每盘写入量；
- 不做“每盘多 worker”：单盘一个顺序流即可压满，多 worker 只会增加队列深度与 CPU 争抢；
- 10h、500MB/s 估算约 18TB/盘，跑前确认 DWPD/TBW。

## 8. 新配置算例

**2×48C（96C）、512G（8×64G）、4 块数据盘**

- CPU = (96×25+8)/16 = 150；
- 单 worker = 64−8 = 56G，总量 448G；
- cap_module=450G，cap_mem=471G，cap_disk=512−(4×12+8)=456G，cap=450G；
- 结果：`--cpu 150 --vm 8 --vm-bytes 56G`，hdd 4 个。

同一台换 12 块盘：

- cap_disk=512−(12×12+8)=360G；
- 单 worker=360/8=45G，总量 360G；
- 结果：`--cpu 150 --vm 8 --vm-bytes 45G`，hdd 12 个。

## 9. 失败/未知兜底

| 情况 | 处理 |
|---|---|
| 物理核识别失败 | `round(nproc×78%)` |
| DIMM 容量混合 | 回退 `MemTotal×82%` 均分，上限 `MemTotal×92%` |
| EDAC 只有根数、无容量 | 同上 |
| DIMM 根数探测失败 | 中止并给出手动 `--vm` 示例 |
| MemTotal 不可读 | 中止，要求显式 `--vm-bytes` |
| `cap_disk ≤ 0` | 报错：内存不足以支撑当前盘数，请减少盘数或降低 `--hdd-bytes` |
| 显式 `--vm-bytes` | 原样保留，只告警不裁剪 |

## 10. 与现有实现的关系

- CPU：删除“机型预设覆盖 CPU”的分支；`CPU_MAX_PCT=78` 仅作物理核识别失败时的兜底；
- 内存：`MEM_MAX_PCT` 语义改为“模块总容量上限=88%”；新增 `MEM_TOTAL_MAX_PCT=92`、`DISK_CACHE_FACTOR=1.2`、`DISK_CACHE_MIN_G=8`；
- `MEM_TARGET_PCT=82` 仅用于兜底路径；
- `--vm-keep`：`mem` 与 `combo` 固定追加，`cpu`/`hdd` 不加（前序已确认）；
- CLI、监控、结论判定、hdd 默认 10G、默认 10h 不变；
- 显示与落盘：记录 C/T、DIMM 根数×容量、单 worker、总量、三道 cap、D、最终 argv。

## 11. 待确认项
