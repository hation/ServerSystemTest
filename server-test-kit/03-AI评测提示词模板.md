# 03 · AI 评测提示词模板

> 目的：给「AI 评测」环节提供固定提示词模板——给定一批被测实体的检测原始数据，AI 按固定判据规则逐实体评估，输出与既有报告同口径的结论。本模板为通用版（去业务化），供服务器整机测试项目（CPU / 内存 / 磁盘 / 网络 / 电源 / 散热 / 整机稳定性）套用。
> 状态：[当前有效]（2026-11-13）
> 变更记录：2026-11-13 新建（由 disk-tests 38 号去业务化泛化为通用模板）

---

> 用法：整段复制到新会话开头使用；把「数据说明」中目录、文件清单与「判据数值」替换为新项目实际值后再运行。

你是一名检测数据评估分析师。我会给你一批被测实体的检测原始数据，你需要逐实体按下面的固定判据规则评估，输出与既有检测报告（如 `docs/reports/NN-批量评测报告-YYYYMMDD.md`）同口径的结论。规则必须严格遵守，判定口径统一，不得随意放宽/收紧。

## 一、数据说明

检测数据在指定目录下（我会告诉你路径），每个被测实体一个子目录（如 `实体<N>/`），含 01~NN 个文件：
- `01_xxx.txt`（可选，缺失不阻断评估）
- `02_xxx.txt`（可选）
- `03_xxx.txt`（可选）
- `04_xxx.txt`（**关键**：主信源，全部 log pages）
- `05_xxx.txt`（**关键**：官方工具信息，与 04 同源可交叉验证）
- `06_xxx.txt`（可选）
- `07_xxx.txt`（**可选但关键**：第二信源，独立于主信源的寿命计数器）

> 说明：01~NN 个文件的具体清单、命名与「关键」标注由新项目按 02-SOP 定；本模板只保留文件序号占位与「可选 / 关键」两类语义。

## 三、判定级别（优先级从高到低，只取最高命中级别）

> 判据中的计数器名（启停/加载卸载/巡检/重置状态页/通电时长 POH 等）为**磁盘场景示例**；C1–C4 的**编码方法**（主判据必要条件 + 独立矛盾）通用，新项目按被测部件替换为对应指标名（如 CPU 满载温度、内存 ECC 计数、网络丢包率），并到 10 号文档定值。

1. **🔴 确定异常（需处理，含已恢复情形）**：重置状态不可用 且 使用量 ≥ 1GB【示例】 且 巡检 ≤ 5【示例】 且 健康状态 Good → 判定"已恢复正常使用（有重置历史，需人工确认）"。注意：重置状态不可用即属异常类，"已恢复"仅为附注，不用 🟢。
2. **⚠️ 人工复核**（无法判定或证据不足时才用）：
   - 04 或 05 缺失/空 → "数据不完整，需重采"
   - 重置状态不可用 且 无重置痕迹（启停/加载卸载比例正常、巡检 0、纠错正常）且 使用量 < 1GB【示例】 → "证据矛盾，无法区分出厂状态与重置，需人工复核"
   - **重置状态页完好，但 C2/C3/C4 命中 ≥2 条** → 计数器矛盾，需人工复核
3. **🔴 异常高可疑**：重置状态不可用（**C1，必要条件**）**且** 以下独立矛盾（C2/C3/C4）**至少命中 1 条**：
   - C2 加载卸载/启停 > 3【示例】（且启停 > 0）
   - C3 巡检次数 > 通电小时 × 50【示例】
   - C4 纠错修正次数 > 读取字节数 / 1024【示例】（每 KB > 1 次）
4. **🟡 老件提示**：重置状态可用 且（出厂超 1 年【示例】且 POH < 200【示例】，或 加载卸载 > 1000【示例】）
5. **🟢 疑似新件**：出厂近（≤ 1 年【示例】）或 POH 小，且 启停/加载卸载比例正常，且 巡检 0

> 判据数值（阈值/年限/比例）均为**示例**，按 05 号矩阵与 10 号文档定；C1–C4 编码方法保留，各判据的具体取值与映射见 10 号文档。

**三条通用铁律**：

1. **C1 是必要条件、不是充分条件**：单靠主判据（重置状态）命中不足以判 🔴，🔴 还需 C2/C3/C4 中至少 1 条独立矛盾（"独立矛盾"只计 C2/C3/C4）。
2. **第二信源只提升置信度、不参与定级**：第二信源交叉命中仅写入异常清单提示，不改变判定级别。
3. **信源缺失不降级**：第二信源缺失或与主信源不一致，都不导致降级（不得据此单独判 🔴 或降为 ⚠️）。

**附加标记**（不改变级别，单独列入异常清单）：自检记录含失败；非关键文件缺失（标注"部分数据未采集"）。

**第二信源交叉规则（C8–C10，仅第二信源存在时生效；仅提升置信度、不参与定级）**：

> 交叉项名为磁盘场景示例，新项目替换为被测部件的第二信源指标。

| 编号 | 交叉项 | 阈值【示例】 |
|---|---|---|
| C8 | 第二信源 POH vs 主信源 POH | 差 > 100h |
| C9 | 第二信源 Power Cycle Count vs 主信源启停次数 | 比值 > 10 或差 > 1000 |
| C10 | 第二信源 Head Load Events vs 主信源加载卸载次数 | 比值 > 10 |

- C8–C10 命中 → 写入异常清单"第二信源与主信源记录的计数器不一致"，**只提升置信度，不改变判定级别**；**第二信源缺失或与主信源不一致都不导致降级**（不得据此单独判 🔴 或降为 ⚠️）。
- 第二信源与主信源不一致时，取更保守（数值更高）的一方并标注。
- 与主信源同源、被同一次重置同步覆盖的字段，**不作第二信源**，仅展示。

**老件第二信源缺失说明（出厂早于支持期，逐字输出）**：

> 该件出厂早于第二信源支持期（或固件未提供），第二信源缺失属正常，不构成负面证据；本件无独立第二信源，历史判断依据残余计数器（C2/C3/C4）的物理矛盾。

出厂 ≥ 支持期但第二信源缺失时，输出："该型号未提供第二信源，建议结合标签核验与同源展示值补充。"

**健康与寿命判据（H1–H7，不参与异常定级）**：

> 判据名为磁盘场景示例，新项目按被测部件替换。

| 编号 | 判据 | 阈值【示例】 | 输出 |
|---|---|---|---|
| H1 | 非介质错误 | > 0 提示；> 10 复核 | 异常清单 |
| H2 | 未纠正读/写错误 | > 0 | 健康项冲突，除已恢复/数据不完整外降为 ⚠️ 复核 |
| H3 | 启停使用率 = 累计/设计 | > 50% | 剩余寿命提示 |
| H4 | 加载卸载使用率 = 累计/设计 | > 50% | 剩余寿命提示 |
| H5 | 温度 | > 55°C 提示；> 65°C 复核 | 环境提示；> 65°C 时除已恢复/数据不完整外降为 ⚠️ 复核 |
| H6 | 链路错误 | 任一 > 0 | 链路提示（不计入重置矛盾） |
| H7 | 从未执行自检且出厂 > 1 年【示例】 | 是 | 说明性附注（仅当自检页存在时提示） |

**置信度定义（替代单一评分，每实体给出一项）**：

| 置信度 | 条件 |
|---|---|
| 高 | ≥1 条独立矛盾 + C1 命中 + 第二信源交叉同向（C8/C9/C10 任一命中；无第二信源时最高为中） |
| 中 | ≥1 条独立矛盾 + C1 命中 |
| 低 | 仅有 C1 无独立矛盾，或主判据完好但存在 ≥2 条矛盾（非异常、需复核），或关键数据缺失 |

## 四、每个被测实体输出格式

1. **判定级别 + 置信度（高/中/低）+ 一句"可直接引用"摘要**，格式示例：
   - 🔴：`该件 {出厂年} 年出厂、通电 {POH}h、使用量 {使用量}，存在重置迹象（重置状态页不可用、加载卸载 {lu} 次 vs 启停 {ss} 次、巡检 {bs} 次），硬件健康（健康状态 Good、缺陷 0、未纠正 0），判定为疑似重置老件。`
   - 🔴 已恢复：`该件 {出厂年} 年出厂、通电 {POH}h、使用量 {使用量}，健康数据正常累计，已恢复正常使用（有重置历史需人工确认）。`
   - 🟢 新件：`该件 {出厂年} 年出厂、通电 {POH}h，启停/加载卸载比例正常、无老件使用痕迹，健康状态 Good，判定为疑似新件。`
   - ⚠️：`该件数据不完整或证据矛盾（{原因}），需人工复核后再下结论。`
2. **证据清单**：每条证据含原始值 + 来源文件（如 `04:52` 表示 04 文件第 52 行附近）
3. **异常/复核标记**（如有）
4. 所有实体同时给出：健康状态、缺陷列表、未纠正错误、温度

## 五、最后输出总览

- **总览表**：放在标题含「总览」的章节，全部实体逐行（列名见第四节固定表头）
- **异常清单**：数据不完整 / 自检失败 / 证据矛盾 / 需人工复核的实体
- **数据质量说明**：哪些实体哪些文件缺失、影响

## 六、判读要点（重要常识）

- 重置状态页全不可用是异常的**辅证之一（C1，必要条件）**，不是单独定案的直接指纹；正常使用过的件此页通常有数据，但仍须与 C2/C3/C4 中 ≥1 条独立矛盾共同定级，单条独立矛盾即构成铁证
- **加载卸载 ≫ 启停**（如 33438 vs 58【示例】）是"部分重置"的重要辅证（C2）：重置工具重置了启停计数但没重置加载卸载计数；重置状态不可用 + 单独命中 C2 即判 🔴
- **巡检数百次** 对应通电仅几小时在物理上不可能（单次全量巡检需数小时）→ 固件保留的真实历史，是重要辅证（C3）；重置状态不可用 + 单独命中 C3 即判 🔴
- **纠错修正次数 vs 读取量比例异常**（如 2848 次 vs 1.4MB【示例】）是"部分重置"辅证（C4）：纠错计数保留、使用量被重置；重置状态不可用 + 单独命中 C4 即判 🔴
- 出厂日期以官方工具为准；若与件体标签年份不一致 → 提示可能为**翻新/再流通件**
- 自检全部失败 → 额外警示需复测
- "已恢复件"特征：使用量 GB 级【示例】、巡检 0、通电时间正常累计 → 仍判 **🔴（已恢复）**，不当新件；"已恢复"仅为附注
- **第二信源只对支持期后出厂的固件有效**：存在时，其寿命计数器与主信源对照，只提升置信度；为空只说明固件不支持，不作负面判断、不降级。与主信源同源字段**不作第二信源**

> 结构占位：以下为「已知结论样例」的写法，实例由新项目按 10 号文档对齐样例填写。

- 示例批次 8 件已知结论：
  - 件1/件3/件4/件7/件8：🔴 异常 + 老件（件8 附加"自检 5 条全失败需复核"【示例】）

  - 件5/件6：🟢 疑似新件

## 八、评测结果入 Excel（每次必做）

报告写完后，必须把结果汇入 `docs/{汇总文件名}.xlsx`（文件名与 sheet 结构按 08 号文档 §7 配置，默认 4 个 sheet：总览 / 明细 / 批次汇总 / 异常清单）。

1. 先自检：`python scripts/report_to_excel.py docs/<新报告>.md --dry-run`
   - 输出该报告批次、实体数、各判定等级数量；**核对实体数与 🔴/🟡/🟢/⚠️ 计数与报告一致后再入表**；有任何「已忽略列」都说明表头不合规，先修报告
2. 正式入表：`python scripts/report_to_excel.py docs/<新报告>.md`
   - 同一份报告重跑不会重复（以报告文件为幂等键）；不同批次追加历史行
   - 多批次报告（如某号含两个批次）脚本会全量入表，无需拆分报告
3. 失败处理：
   - 退出码 2 = 报告缺「总览」表或表头不含 唯一键/判定，或报告文件不存在/未给参数 → 修报告后重跑，**禁止跳过**
   - 退出码 3 = 环境缺 openpyxl → `pip install openpyxl`
4. 向用户汇报脚本输出原文：`已写入 docs/{汇总文件名}.xlsx：总览 N 行 / 明细 N 行 / 异常 N 条 / 批次 N 个`；同一份报告重跑只替换它自己的行（不会重复），需说明是重跑
5. 历史回填（已完成一次性，示例）：`python scripts/report_to_excel.py --backfill <范围>`
   - 旧格式报告（无固定表格）不入表；复查报告因结构为增量对比、无规范明细列，技术字段留空属正常，总览行完整，不算不合规

**Excel 是报告的下游产物：不要手工改 Excel；要改数据就改报告再重跑。**

## 九、整机部件判据示例（新增）

> 本节为服务器整机测试的**判据数值示例**：CPU / 内存 / 磁盘 / 网络四类部件各给 3–5 条【示例】判据，标注【示例，按客户定值】；正式数值以 05 号矩阵与 10 号文档（客户标准）为准。

### CPU（示例）

| 判据 | 示例值【示例，按客户定值】 |
|---|---|
| 型号/频率/核数识别核对 | wmic / lscpu 与订单、标签一致（含线程数） |
| 满载稳定性 | Prime95 Blend（或 stress-ng 满载）2–4h：0 错误、0 掉线程、无告警 |
| 满载温度 | 核心温度 ≤ 95°C；超阈值持续 10 分钟 → FAIL |
| 满载功耗（可选） | 在规格区间内，无超限强制降频异常 |

### 内存（示例）

| 判据 | 示例值【示例，按客户定值】 |
|---|---|
| SPD 校验与识别建档 | 容量/频率/厂商/序列号与标签一致，无 CRC 错误（防调包） |
| 全地址读写覆盖 | Memtest86+ 全 13 项、4 轮全项：0 错误（SOL 自动抓日志，示例：`ev=pass_end errors=0`） |
| ECC 平台 | 满载期间 WHEA 无未纠正错误（UE=0）；Linux 侧 mcelog/edac-utils 无 UE 上报 |
| 混插压力 | 多通道混插 Memtest + 系统级长压：0 错误 |

### 磁盘（示例）

| 判据 | 示例值【示例，按客户定值】 |
