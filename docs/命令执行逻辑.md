### 1.2 调用关系

```
用户 ── oneclick.sh（菜单/子命令 all|hdd|full|sysdisk|cpu|mem|status|review）
          │
          ├─ 调 stress-test.sh start <type> --timeout <T> [extra...]   # 每个任务一个子命令窗口/后台（内部子命令 __task）
          ├─ 调 stress-test.sh status / review --dir <结果目录>         # 状态查询与逐个复盘
          ├─ 调 disk-mount.sh mount --disks all --yes [--rebuild]      # 自动挂载（all/hdd/full 模式）
          └─ 内部子命令 __task <batch> <id> <timeout> <type>            # 窗口/后台内实际启动任务

用户 ── install.sh        → 安装 stress + dmidecode + nvme-cli（RPM 存在性 + SHA256 锁定校验）
用户 ── verify.sh         → 验证安装（install.sh 之后运行）
用户 ── stress-test.sh    → 独立使用（start/status/stop/review/snapshot）
用户 ── disk-mount.sh     → 独立挂载测试盘（stress-test.sh start hdd 前置条件之一）
用户 ── mount-iso.sh      → U 盘挂载 / yum 源构建与配置
用户 ── usb-eject.sh      → U 盘弹出
```

关键依赖方向：

- **oneclick.sh 是编排层**，`stress-test.sh` 是执行层；oneclick 的所有压测动作最终都落到 `stress-test.sh start ...`，复盘落到 `stress-test.sh review --dir ...`（oneclick.sh L11-12 用环境变量 `ONECLICK_STRESS_TEST_SH` / `ONECLICK_DISK_MOUNT_SH` 定位脚本）。
- **install.sh 提供前置依赖**：`stress`（压测本体）、`dmidecode`（内存条根数自动探测）、`nvme-cli`（check-nvme-health.sh 的 NVMe SMART 读取）；`stress-test.sh` 启动前置校验 `command -v stress` 失败即提示"请先运行 bash install.sh"（stress-lib-commands.sh L171）。
- **disk-mount.sh 提供数据盘挂载**：`stress-test.sh start hdd` 默认 glob `/mnt/HDD*`，未发现时提示"请先运行 bash disk-mount.sh mount"（stress-lib-commands.sh L195）；oneclick all/hdd 模式自动调用 disk-mount。
- **stress-test.sh 内部自组织**：`start` 后台拉起 `monitor-loop`（内部子命令，stress-lib-commands.sh L655；入口分发见 stress-test.sh L114），monitor-loop 每轮巡检并落盘运行时证据。

## §2 stress-test.sh 命令执行逻辑

### 2.1 脚本总览

#### 2.1.1 命令形态（usage，L58-91）

```
bash stress-test.sh start <cpu|mem|hdd|combo> [--model <品牌-型号|auto>] [--timeout 10h] \
    [--cpu N] [--vm N] [--vm-bytes X] [--hdd-bytes X] [--dirs "d1 d2"] [--sysdisk] [--sysdisk-only] \
    [--peer-disks N]
bash stress-test.sh status
bash stress-test.sh stop
bash stress-test.sh review [--dir <结果目录>]
bash stress-test.sh snapshot <结果目录>   # 立即抓取一次运行时证据快照
```

子命令分发（L106-116）：`start`→cmd_start、`status`→cmd_status、`stop`→cmd_stop、`review`→cmd_review、`snapshot`→cmd_snapshot、`monitor-loop`→cmd_monitor_loop（内部子命令，start 后台调用）；未知命令打印 usage 退出 1。

usage 中的推导规则摘要（原文 L69-80，细则见 §2.12）：

```
CPU worker 数 = max(1, round(逻辑线程数 × 25/32))，逻辑线程 = 物理核 × 每核线程数（SMT 探测，未知默认开）；
               SMT 关闭（每核1线程）时逻辑线程减半，worker 相应减半（5380→25、7360→38、7380→50）；
               物理核识别失败回退 nproc × 78%（环境变量 CPU_MAX_PCT）
内存单 worker = 单条容量 − max(6G, 单条容量/8)，VM worker = DIMM 根数
内存上限 = min(模块总容量 × 88%, MemTotal × 92%,
              MemTotal − (盘数 × hdd-bytes × 1.2 + 8G))，超限逐 GiB 下调单 worker
混合容量 / EDAC 无容量 / 显式 --vm ≠ DIMM 数 → MemTotal × 82% 均分（上限 92%）
mem / combo 固定追加 --vm-keep（内存常驻）；hdd 每块数据盘 1 个进程
内存条根数 = --vm（默认按 DIMM 自动探测，等于实际内存条根数；探测失败时可手动 --vm N）
--peer-disks N（仅 combo/mem）：对端并发 hdd 流数，cap_disk 按 max(实际盘数, N) 预留；
                    只影响内存推导与展示，不启动 hdd 进程；出现即不再自动扫描 /mnt/HDD*
```

usage 示例（原文 L82-90）：

```
bash stress-test.sh start cpu                # 按逻辑线程推导跑 CPU 压测（默认 10h）
bash stress-test.sh start mem                # 按实测 MemTotal 与内存条根数推导跑内存压测（默认 10h）
bash stress-test.sh start hdd --dirs "/mnt/HDD01 /mnt/HDD02"
bash stress-test.sh start hdd --sysdisk       # 仅压系统盘（无数据盘时）
bash stress-test.sh start hdd --sysdisk-only  # 仅压系统盘（无论是否有数据盘）
bash stress-test.sh start combo --dirs "/mnt/HDD01 /mnt/HDD02" --sysdisk  # CPU+内存+每盘 hdd+系统盘
bash stress-test.sh review --dir /root/stress-test/20261113-143000-cpu
```

另有 4 条 usage 说明（L7-10）：① hdd 模式无 `/mnt/HDD*` 挂载点时加 `--sysdisk` 可仅压系统盘；② `--sysdisk-only` 无论是否有数据盘都只压系统盘；③ combo 无数据盘时降级为 CPU/内存（或配合 `--sysdisk`）；④ combo/mem 的 `--peer-disks N` 只声明对端并发 hdd 流数（参与内存预留），不启动 hdd 进程，出现即不再自动扫描 `/mnt/HDD*`（仅显式 `--dirs` 才在 combo 内启动 hdd），0 表示纯 CPU+内存。

### 2.2 start 通用流程（cmd_start，stress-lib-commands.sh L3-689）

所有 start 子类型共享的执行序列（细节按类型分述见 2.3~2.7）：

1. **校验压测类型**（stress-lib-commands.sh L6-10）：`cpu|mem|hdd|combo`，否则报错并打印 usage 退出 1。
2. **参数解析**（stress-lib-commands.sh L12-35）：支持 `--model`、`--timeout`、`--cpu`、`--vm`、`--vm-bytes`、`--hdd-bytes`、`--dirs`、`--peer-disks`（均需取值，缺值报错）、`--sysdisk`、`--sysdisk-only`（无取值）；未知参数报错退出。缺省：`model=auto`、`timeout=10h`。
3. **`--peer-disks` 校验**（stress-lib-commands.sh L37-48）：必须非负整数；仅 `combo/mem` 生效，`cpu/hdd` 收到时提示并忽略（`peer_given=0`）。
4. **`--sysdisk` / `--sysdisk-only` 语义校验**（stress-lib-commands.sh L50-68）：`--sysdisk` 在 cpu/mem 下仅提示无效；`--sysdisk-only` 仅 hdd 模式生效（combo 下报错退出、cpu/mem 下忽略、与 `--dirs` 同用报错退出）。
5. **创建结果根目录**（stress-lib-commands.sh L72）：`mkdir -p $STRESS_TEST_ROOT`（作为 operations.log 落脚点）。
6. **机型解析**（stress-lib-commands.sh L74-133）：见 2.12.3（auto 判定 + 仅标注与交叉校验）。
7. **CPU 参数推导**（stress-lib-commands.sh L135-164）：hdd 模式不推导不校验；其余见 2.9.1。显式 `--cpu` 直接使用（cpu_note="（显式 --cpu）"）。
8. **`--hdd-bytes` 默认值**（stress-lib-commands.sh L168）：未传时 `10G`。
9. **前置校验：stress 已安装**（stress-lib-commands.sh L171）：`command -v stress` 失败 → "未找到 stress，请先运行 bash install.sh" 退出 1。
10. **数据盘目录收集与校验**（stress-lib-commands.sh L176-223）：见 2.9.4；任一无效整体退出（不启动任何 stress、不建结果目录，防孤儿进程）。
11. **`--sysdisk` 空间预检**（stress-lib-commands.sh L225-239）：`mkdir -p /stresstest-hdd`；`--hdd-bytes` 必须以 G 为单位；根文件系统可用空间需 ≥ `gb×1.2`（`need_kb=$(( gb * 12 * 1048576 / 10 ))`），不足整体退出。
12. **盘流计数**（stress-lib-commands.sh L241-259）：`disk_streams = 数据盘目录数 + (--sysdisk 时 +1)`，仅 hdd/combo 计入；`disk_streams_eff = max(实际盘数, --peer-disks)`（仅 combo/mem 的 peer 参与，hdd/cpu 只用实际盘数）；来源标记 `actual/peer/max`。
13. **内存计划**（stress-lib-commands.sh L261-489）：仅 mem/combo；见 2.9.3。探测/推导失败直接退出，不留下结果目录。
14. **资源计划汇总**（stress-lib-commands.sh L491-500）：`res_plan_line`（physical_cores/nproc/cpu_workers/dimms/per_worker_g/per_worker_mb/per_worker_raw/mem_total_g/cap_module_g/cap_mem_g/cap_disk_g/disk_streams/peer_disks/disk_streams_eff/disk_streams_source/vm_keep/smt）显示并 `log_op resource-plan`。
15. **建结果目录**（stress-lib-commands.sh L502-510）：`$STRESS_TEST_ROOT/<时间戳>-<type>`（`date '+%Y%m%d-%H%M%S'`）；同秒冲突 `sleep 1` 顺延。
16. **组装 stress 参数**（stress-lib-commands.sh L512-519）+ 超时秒数（stress-lib-commands.sh L520）：
    - cpu：`--cpu N --timeout T`
    - mem：`--vm N --vm-bytes X --vm-keep --timeout T`
    - hdd：`--hdd 1 --hdd-bytes X --timeout T`
    - combo：`--cpu N --vm N --vm-bytes X --vm-keep --timeout T`
17. **写 run-config.txt**（stress-lib-commands.sh L523-590）、**写 devices.txt**（stress-lib-commands.sh L592-598，仅 hdd/combo）、**写 disk-map.txt**（stress-lib-commands.sh L600-602，全部 type 均生成，全机数据盘定位表，见 2.13 产物清单）、**写 info-before.txt**（stress-lib-commands.sh L604-625）、**初始化 error.log**（stress-lib-commands.sh L628）：见 2.10 产物清单。
18. **后台启动 stress**（stress-lib-commands.sh L630-652）：nohup 包裹；见 2.9.5。

### 2.3 start cpu

在通用流程之上，cpu 类型特有逻辑：

- **CPU 参数推导**（stress-lib-commands.sh L135-164）：`smt_status` 探测一次 → `logical_cpus` 实测逻辑线程 → `check_model_threads` 与机型标称交叉校验（仅提示）→ 无显式 `--cpu` 时 `cpu_workers_auto`（见 2.9.1）。推导失败（nproc 与物理核均不可用）报错退出，提示"请检查 nproc/lscpu 或用 --cpu 显式指定"（stress-lib-commands.sh L146）。
- **无内存推导**：cpu 不进入内存计划段（stress-lib-commands.sh L267 条件仅 mem/combo）。
- **stress 命令**：`stress --cpu N --timeout T`（stress-lib-commands.sh L515），不加 `--vm-keep`。
- **run-config.txt 特有字段**（stress-lib-commands.sh L534-541）：物理核数、CPU 逻辑线程、SMT 状态、CPU worker 数（含推导注记）、VM keep、HDD 进程数、资源计划。
- **产物**：`stress.log`（stdout）、`error.log`（stderr 实时 + monitor 巡检追加）、`stress.exitcode`。

### 2.4 start mem

在通用流程之上，mem 类型特有逻辑：

- **内存参数推导**（stress-lib-commands.sh L261-489）：见 2.9.3 全流程。
- **固定 `--vm-keep`**（stress-lib-commands.sh L267、stress-lib-commands.sh L516）：`vm_keep=yes`，stress 命令 `--vm N --vm-bytes X --vm-keep --timeout T`。
- **DIMM 探测失败时**（stress-lib-commands.sh L286-302）：打印中止信息，并给出手动命令建议（`start mem --vm 16 --vm-bytes <N>G` 等；`mem_plan` 以 16 worker 预演）；`exit 1`。
- **MemTotal 缺失且无显式 --vm-bytes**（stress-lib-commands.sh L307-310）：报错退出。
- **cap_disk ≤ 0**（stress-lib-commands.sh L321-324）：报"内存不足以支撑当前盘流"退出（mem 模式下 `disk_streams` 恒为 0，除非传了 `--peer-disks`）。
- **run-config.txt 特有字段**（stress-lib-commands.sh L543-557）：在 cpu 字段基础上追加内存条根数（含来源）、单根容量、内存目标、内存分配上限、VM worker 数、VM 字节、VM keep（"mem 固定追加 --vm-keep"）、内存需求核对。
- **推导依据打印**（stress-lib-commands.sh L668-684）：`推导: CPU N（...）; 内存 N 根 × X = 总量（上限 ...；--vm-keep 常驻）`。
- **产物**：`stress.log`、`error.log`、`stress.exitcode`（mem 为单进程 wrapper，无 HDDxx 分文件）。

### 2.5 start hdd

在通用流程之上，hdd 类型特有逻辑：

- **不推导 CPU**（stress-lib-commands.sh L139）：hdd 模式跳过 CPU 参数段（`cpus=""`、不调用 `smt_status`/`cpu_workers_auto`）。
- **数据盘枚举与校验**（stress-lib-commands.sh L176-223）：
  - `--sysdisk-only`：`dirs=()` 强制为空，不扫描 `/mnt/HDD*`、不校验挂载。
  - 显式 `--dirs`：逐目录校验存在性 + 已挂载独立文件系统 + 底层设备非根设备（`findmnt SOURCE` 与 `df -P /` 的根设备比对，stress-lib-commands.sh L202-217）；任一无效整体退出。
  - 默认 glob `/mnt/HDD*`（stress-lib-commands.sh L188）：未发现时——有 `--sysdisk` → 仅压系统盘；无 → 提示"请先运行 bash disk-mount.sh mount 或使用 --dirs 指定"退出 1。
  - 空 `--dirs`（空串）+ 无 `--sysdisk`：报"未指定任何压测盘目录"退出（stress-lib-commands.sh L218-219）。
- **每盘 1 进程**（stress-lib-commands.sh L638-644）：`cd <目录> && stress --hdd 1 --hdd-bytes X --timeout T`，每盘独立 stdout/stderr/exitcode 文件（`stress-HDD<序号>.log` / `error-HDD<序号>.log` / `stress-HDD<序号>.exitcode`，序号 `%02d`）。
- **`--sysdisk` / `--sysdisk-only`**（stress-lib-commands.sh L645-648）：系统盘压测在 `/stresstest-hdd` 目录执行，文件为 `stress-SYSDISK.log` / `error-SYSDISK.log` / `stress-SYSDISK.exitcode`；run-config 追加"压测对象: 系统盘（根文件系统压测）"与覆盖边界说明（stress-lib-commands.sh L583-587，FR-10）。
- **默认不清盘**：脚本只负责写入压测文件，不重建分区（重建是 disk-mount.sh `--rebuild` 的职责）。
- **写文件缓冲说明**：stress `--hdd` 使用缓冲写，页缓存/脏页会累积，因此内存推导的 cap_disk 按 `盘数×hdd-bytes×1.2+8G` 预留（见 2.9.3 公式）。
- **run-config.txt 特有字段**（stress-lib-commands.sh L559-563）：HDD 字节、HDD 进程数、VM keep、资源计划。

### 2.6 start combo

- **定义**：CPU+内存组合压测，单结果目录；`stress_args="--cpu N --vm N --vm-bytes X --vm-keep --timeout T"`（stress-lib-commands.sh L518）——即一个 stress 进程同时带 `--cpu` 与 `--vm`。
- **编排来源**：oneclick 全测模式生成 `COMBO|combo|--peer-disks|<N>` 计划（oneclick-lib-run.sh L181），N=数据盘数+1；也可手动 `start combo --dirs ... --sysdisk`。oneclick `full`（整机压测）模式生成同结构的计划行，**按朋友规则推导中高强度参数** `--cpu|<FULL_CPU>|--vm|<FULL_VM>|--vm-bytes|<FULL_VMBYTES>`（显式 FULL_* 优先、未设置项由推导补齐；推导值作为显式参数下发、不裁剪，见 §3.5）。
- **数据盘集合可为空**（stress-lib-commands.sh L176-200）：无数据盘时降级为仅 CPU/内存，或配合 `--sysdisk` 压系统盘；显式空 `--dirs` 时警告并继续（stress-lib-commands.sh L220-221）。
- **`--peer-disks` 语义**（stress-lib-commands.sh L183-186）：出现即视为显式声明外部盘流，`combo` 不再自动 glob `/mnt/HDD*`（避免 combo 内重复压盘），且不启动 hdd 进程；`0` 表示纯 CPU+内存。
- **启动顺序**（stress-lib-commands.sh L633-648）：先起 CPU/内存组合进程（`stress.log`），再逐盘起 hdd 进程（`stress-HDDxx.*`），最后按需补系统盘（`stress-SYSDISK.*`）。
- **内存推导**：与 mem 相同（2.9.3），但 `disk_streams` 计入数据盘目录数+sysdisk，cap_disk 预留更大。
- **run-config.txt 字段**（stress-lib-commands.sh L565-581）：cpu 字段 + mem 字段 + HDD 字节/进程数合并输出。
- **产物**：`stress.log` + 各 `stress-HDDxx.*` +（可选）`stress-SYSDISK.*`。

### 2.7 status

命令：`bash stress-test.sh status`（cmd_status，stress-lib-commands.sh L693-716）

执行流程：

1. 遍历 `$STRESS_TEST_ROOT` 下 `*-cpu`、`*-mem`、`*-hdd`、`*-combo` 目录（stress-lib-commands.sh L695）。
2. 对每个有 `stress.pids` 的目录调用 `alive_pids`；存活数 >0 即视为运行中，调用 `print_status_dir`（stress-lib-commands.sh L709-746）打印：

   - 错误日志状态（error.log 行数 >1 视为有报错并 tail -5，=1 表头视为无报错；旧目录无 error.log 显示"未生成"）；

### 2.8 stop

命令：`bash stress-test.sh stop`（cmd_stop，stress-lib-commands.sh L750-769）

执行流程：

1. 遍历 `*-cpu/-mem/-hdd/-combo` 目录，对 `stress.pids` 存活数 >0 **或** monitor 进程存活的任务调用 `stop_one`（stress-lib-commands.sh L771-806）。
2. **停止顺序**（先监控后压测，保证结束状态落盘）：
   - 向 monitor 进程发 `TERM`（置位 stop_flag，打断 sleep 等待），最多轮询 2 秒等 `status.txt` 落盘（stress-lib-commands.sh L779-784），仍存活则 `KILL`；
   - 对 `stress.pids` 中每个 wrapper PID：先 `pkill -TERM -P <pid>` 杀其子进程，再 `TERM` 自身，轮询最多 3 秒后 `KILL`（stress-lib-commands.sh L791-803）。
3. `log_op stop dir=<目录>`（stress-lib-commands.sh L805）。
4. 全部结束后，monitor 循环会在收到 TERM 后立即 `write_status STOPPED manual-stop` 并 `write_runtime_final`（stress-lib-monitor.sh L131/L133）——因此手动停止的目录会留下 `status.txt`（`state=STOPPED`）与 `runtime-final.txt`。
5. 无运行任务 → 输出"没有运行中的压测，无需停止"。

**stress.\* 文件清理说明**：stop 只终止进程，**不删除**结果目录及其中文件（stress.log、stress.pids、monitor.csv 等保留，供复盘追溯）；如需清理结果目录需手动删除 `$STRESS_TEST_ROOT/<时间戳>-<type>`。

### 2.9 review --dir

命令：`bash stress-test.sh review [--dir <结果目录>]`（cmd_review，stress-lib-commands.sh L810-1292）

#### 2.9.1 前置与数据准备

1. `--dir` 缺省时取 `$STRESS_TEST_ROOT` 下最新一个 `*-cpu/-mem/-hdd/-combo` 目录（`ls -1d ... | sort | tail -1`，stress-lib-commands.sh L819）；无任何目录报错退出；目录不存在报错。
2. 必须存在 `monitor.csv`，否则报"未找到监控数据"退出（stress-lib-commands.sh L824）。
3. **monitor.csv 统计**（stress-lib-commands.sh L828）：行数 `rows`（跳过表头）、CPU 均值/峰值（第 3 列）、内存峰值（第 5 列 mem_used）、磁盘读/写峰值（第 8/9 列）。
4. **监控覆盖时长**（stress-lib-commands.sh L831-838）：间隔取 run-config"监控间隔"，非法/0 回落 30 秒；`duration=(rows-1)×interval`（rows≥2）、`=interval`（rows=1）、0（无行）。
5. **结束时间估算**（stress-lib-commands.sh L847-850）：run-config"开始时间"epoch + duration，避免 date 字符串歧义。
6. **采样空洞判定**（stress-lib-commands.sh L852-874）：以 run-config"开始时间"为锚点，monitor.csv 末行时间−开始时间=实际跨度 `span_sec`；`expected=span_sec/interval`（≥1）；`coverage=rows×100/expected`（展示封顶 100%，不影响判定）；`coverage<90` → 空洞"是"，否则"无"；开始/末行时间无法解析 → "不可判定"。**按跨度而非行数估算**，避免长时间无采样（仅 1 行）时严重高估覆盖率。

#### 2.9.2 结论判定（FR-7，严格顺序，stress-lib-commands.sh L876-934）

前置计算：`pids_count`（stress.pids 行数）与 `ec_count`（`*.exitcode` 文件数）；pids>ec → 异常；否则逐一检查 exitcode，非 0 → 异常（stress-lib-commands.sh L882-893）。`error.log` 命中 `检测到 stress|dmesg` → `err_hit`；命中 `dmesg io:` → `io_hit`（stress-lib-commands.sh L894-897）。`error.log`/`error-HDD*.log`/`error-SYSDISK.log` 含 `No space left on device` → `enospc`（stress-lib-commands.sh L899-902）。

判定优先级（命中即定结论）：

| 优先级 | 条件 | 结论 |
| --- | --- | --- |
| a | `error.log` 含 `dmesg io:` | 异常（内核 I/O 错误，见 error.log）——盘故障优先，不被 ENOSPC 掩盖 |
| b | 任一错误日志含 ENOSPC | 异常（空间不足 ENOSPC，非磁盘故障） |
| c | `error.log` 命中 `检测到 stress\|dmesg` | 异常（压测进程/内核报错，见 error.log） |
| d | 有 `status.txt` | 按 `state=`：OK→正常；FAILED→异常（退出码非 0）；ABORTED→按 `reason=`（`oom-killed`→内存耗尽被内核杀死；`missing-exitcode`→进程异常退出未留退出码；其他→进程异常退出）；STOPPED→已手动停止；其他→沿用前置 abnormal 判定 |
| e | 无 `status.txt` | 旧判定：exitcode 缺失/非 0/error.log 命中 → 异常，否则正常 |

> 注：`dmesg io:`（归因到 devices.txt 设备的 I/O 错误）优先于 ENOSPC，符合"内核 I/O 错误 > 磁盘空间 > error.log > status.txt"的判定层级；未归因 I/O 错误写 `error-unattributed.log`，**不计入**本盘结论（仅提示，stress-lib-commands.sh L1232/L1255）。

#### 2.9.3 执行一致性（计划 vs 实际运行证据，stress-lib-commands.sh L936-1211）

- **证据门槛**（stress-lib-commands.sh L964-983）：`actual-params.txt` 存在、`found>0`、且 `label` 为 `60s/600s/periodic`（`is_evidence_label`）才可判定；`start/manual` 快照（含任务结束后手动 snapshot）只作展示，不足判 FAIL；缺任一条件 → 该维度 UNKNOWN（不改变结论）。
- **对比维度**（每个维度输出 PASS/FAIL/UNKNOWN/不适用）：
  1. **CPU worker**（stress-lib-commands.sh L1016-1030）：计划 `cpu_workers` vs 实际 `main_cpu`（hdd 模式不适用）。
  2. **VM worker**（stress-lib-commands.sh L1032-1046）：计划 `dimms` vs 实际 `main_vm`（非 mem/combo 不适用）。
  3. **vm_keep**（stress-lib-commands.sh L1048-1063）：mem/combo 计划与实际必须同为 yes；否则 FAIL。
  4. **hdd 进程数**（stress-lib-commands.sh L1065-1099）：实际 `hdd_processes` 与快照 cwd 集合数 `hdd_cwd_n` 必须一致；再与计划 `disk_streams` 对照（`peer_disks`/`disk_streams_eff` 不参与判定）；60s 快照出现 0 个 hdd 进程视为子进程刚启动的竞态 → 仅 UNKNOWN。
  5. **每个 hdd cwd 在 dirs 集合内**（stress-lib-commands.sh L1102-1133）：从快照 `cwd=` 行解析（保留空格/逗号），越界 → FAIL。
  6. **常驻内存 RSS**（stress-lib-commands.sh L1138-1190）：计划总量 `dimms×per_worker_mb` 与实际快照 `rss_kb` 总和偏差 ≤15% 判 PASS；仅 `600s/periodic` 快照（`is_mature_label`）可判。
- **汇总**（stress-lib-commands.sh L1197-1211）：`cons_fail` → 整体 FAIL，且仅当原结论为"正常"时改写为"异常（执行与计划不一致）"（已异常/已停止保留原结论）；`cons_unknown` → UNKNOWN；否则 PASS。

#### 2.9.4 输出

- 生成 `summary.txt` 于结果目录（stress-lib-commands.sh L1213-1291）并 `cat` 打印：结论、异常点、生成时间、结果目录、类型、机型、压测对象/覆盖边界（run-config 原样回显）、开始时间、计划超时、预计结束时间、监控采样行数/覆盖时长、运行状态（state+reason）、OOM 是否、采样空洞、CPU 均值/峰值、内存峰值、磁盘读/写峰值、退出码清单、error.log 摘要、执行一致性明细、原始数据文件清单。
- `summary.txt` 在结果目录内，不修改任何既有文件。

### 2.11 monitor-loop（内部子命令，start 后台调用）

命令形态：`stress-test.sh monitor-loop <结果目录>`（cmd_monitor_loop，stress-lib-monitor.sh L92-277）。由 `start` 以 `nohup bash "$SCRIPT" monitor-loop "$dir"` 启动（stress-lib-commands.sh L655），随 stress 全部结束自动退出。

执行流程（循环体每 `MONITOR_INTERVAL` 秒一轮）：

1. **初始化**：写 `monitor.csv` 表头 `时间,load1,cpu_usage%,mem_total,mem_used,mem_avail,swap_used,disk_read_MBps,disk_write_MBps`（stress-lib-monitor.sh L97）；取 `/proc/stat`（cpu 合计+idle）与 `/proc/diskstats`（r/w sectors）基线（stress-lib-monitor.sh L100-104）；解析 run-config"开始时间"为快照调度基准 `start_epoch`（stress-lib-monitor.sh L110-114）；`dmesg` 可用性探测（失败则后续检测整体跳过）与首轮基线游标（行数写 `.dmesg.cursor`、最大时间戳写 `.dmesg.ts`，stress-lib-monitor.sh L115-123）。
2. **TERM 陷阱**（stress-lib-monitor.sh L125-133）：`trap 'stop_flag=1' TERM`；循环体内收到 TERM → 立即 `write_status STOPPED manual-stop` + `write_runtime_final` + 退出（stop 依赖此快速落盘）。
3. **每轮采样**：
   - `sleep "$interval" & wait $!`（可被打断，stress-lib-monitor.sh L132）；
   - 二次采样 `/proc/stat`、`/proc/diskstats`；`ts`、`load1`（/proc/loadavg）、内存（MemTotal/MemFree/MemAvailable/SwapTotal/SwapFree，stress-lib-monitor.sh L143）；
   - **CPU%** = 两次 /proc/stat 采样差值非空闲占比（stress-lib-monitor.sh L147）；
   - **磁盘 IO** = 全部设备 sectors 差值 ×512 / 间隔 /1048576（stress-lib-monitor.sh L149）；
   - 追加一行到 `monitor.csv`（stress-lib-monitor.sh L151）。
4. **进程退出巡检**（stress-lib-monitor.sh L155-168）：存活数减少 → 检查 `*.exitcode`，非 0（异常退出）实时追加 `error.log`（"检测到 stress 进程异常退出..."）；`logged` 清单防止同一文件重复追加；正常自然结束（0）不记录。
5. **运行时快照调度**（stress-lib-monitor.sh L171-187）：以 `start_epoch` 为锚（监控重启不重复采样）：运行 ≥60s 抓 `60s` 快照一次、≥600s 抓 `600s` 一次、之后每 600s 抓 `periodic` 一次（进程全部退出则不抓）。
6. **dmesg 增量检测**（stress-lib-monitor.sh L189-236）：每轮一次快照，逐行判定（同一行只记一次）：
   - 优先时间戳游标（`.dmesg.ts`），无法解析时间戳回退行数游标（`.dmesg.cursor`）；时间戳回退（ring 清空/重启）→ 从头处理；总行数下降视为 ring 回绕 → 从头读；
   - 命中 `DMESG_IO_RE`：按 `devices.txt` 设备边界正则归因——匹配 → `error.log` 记 `dmesg io:` + `io_seen=1`；不匹配 → `error-unattributed.log` 记 `dmesg io 未归因:`（devices.txt 为空/缺失即不过滤，旧目录兼容）；**报错行带 SN 标注**：`dmesg_io_label`（stress-lib-monitor.sh L83-90，内部 `dmesg_hit_dev` L66-80 按 devices.txt 命中设备名 + `sn_of_dev`（stress-lib-devices.sh L58-76）取 SN）生成 ` (dev=X SN=Y)` 标注，归因行 `dmesg io: (dev=nvme2n1 SN=SH231801357) <原始行>`、未归因行 `dmesg io 未归因: (dev=X SN=Y) <行>`；无命中/无 SN 保持原样；
   - 命中 `DMESG_OOM_RE`：`error.log` 记 `dmesg:` + `oom_seen=1`。
7. **退出条件**（stress-lib-monitor.sh L239）：`alive_pids` 为 0 → 循环 break。

**收尾**（stress-lib-monitor.sh L241-277）：

1. 退出码补齐检查：`pids_count > ec_count` → `error.log` 记"检测到 stress 进程异常退出（未生成退出码文件...）"；否则全部 exitcode=0 且 error.log 无 `检测到 stress|dmesg` → 记"压测结束：全部正常（exitcode=0）"（stress-lib-monitor.sh L242-257）。
2. **结束状态判定**（顺序，stress-lib-monitor.sh L259-273）：
   - 任一 exitcode 非 0 → `write_status FAILED nonzero-exitcode`；
   - 否则 `oom_seen=1` 且 exitcode 数 < pids 数 → `write_status ABORTED oom-killed`；
   - 否则 exitcode 数 < pids 数 → `write_status ABORTED missing-exitcode`；
   - 否则 → `write_status OK all-exitcode-zero`。
3. `write_status`（stress-lib-monitor.sh L4-18）写 `status.txt`：`state= / reason= / pids= / exitcodes= / oom= / io= / unattributed= / end_time=`（oom/io 来自循环内 `oom_seen`/`io_seen`，即 **OOM 标记**以 status.txt `oom=yes` 落盘）。
4. `write_runtime_final`（stress-lib-monitor.sh L21-46）写 `runtime-final.txt`：最终 status.txt 内容、全部 exitcode、actual-params.txt 副本。

#### 2.12.2 CPU worker 推导（唯一公式，`cpu_workers_auto`，stress-lib-common.sh L97-120）

```
CPU worker = max(1, round(逻辑线程 × 25/32))
逻辑线程   = 物理核 × 每核线程数（SMT 探测；未知默认按开 tpc=2）
```

- round 实现（stress-lib-common.sh L108）：`w=$(( (logical * 25 + 16) / 32 ))`（整数除法四舍五入）。
- 数值示例（与 usage 一致）：5380（64 线程）→ 50、7360（96 线程）→ 75、7380（128 线程）→ 100；SMT 关闭（每核 1 线程）时逻辑线程减半 → 5380→25、7360→38、7380→50。
- 物理核识别失败回退（stress-lib-common.sh L112-115）：`w=$(( (n * CPU_MAX_PCT + 50) / 100 ))`，即 `round(nproc × 78%)`。
- 物理核与 nproc 均不可用 → 返回 1（调用方报错退出）。
- 成功时设置全局 `CPU_WORKERS_AUTO / CPU_PHYS_CORES / CPU_LOGICAL_THREADS / CPU_SMT_TPC`。
- **显式参数优先**：传 `--cpu N` 直接使用（cpu_note="（显式 --cpu）"），不触发推导（stress-lib-commands.sh L144-149）。

**机型交叉校验**（`nominal_threads` stress-lib-common.sh L145-156 + `check_model_threads` stress-lib-common.sh L160-181）：标称映射表——海光 5380→64、7360→96、7380→128；AMD EPYC-7763→128、EPYC-7543→64；Intel Xeon-6338→64、Xeon-8380→112；未知型号返回空（跳过校验、不误报）。实测与标称偏差 >10% 时打印警告并 `log_op model-check`，**不改变任何参数**；实测约等于标称一半时结合 SMT 状态区分提示口径（SMT 关闭属预期，否则疑似单路 CPU）。

#### 2.12.3 机型 auto 判定（stress-lib-commands.sh L74-133）

`auto` 优先从 CPU 信息**智能识别多品牌型号**：`detect_cpu_model`（stress-lib-common.sh L127-141）从 `lscpu "Model name"`（或 `/proc/cpuinfo "model name"`）按品牌提取，兼容中英文输出（Model name / 型号名称）、大小写与多空格——海光 `C86-3G` 后型号数字（如 `Hygon C86-3G 9800` → 9800）、AMD `EPYC` 后型号（如 `AMD EPYC 7763` → `EPYC-7763`）、Intel `Xeon` 后型号（如 `Intel(R) Xeon(R) Gold 6338` → `Xeon-6338`）；无品牌匹配返回空、不误报。识别成功时启动日志打印"检测到机型 X（来源: 智能识别 CPU 信息）"并 `log_op model-detect`，识别值经 `model` 变量写入 `run-config.txt` 机型字段（stress-lib-commands.sh L525），复核可溯源。识别失败（lscpu/cpuinfo 均不可用或无品牌匹配）才回退逻辑线程分界，线程不可用（n=0）时按内存兜底，来源标注"逻辑线程分界/内存兜底"：

```
lscpu/cpuinfo 识别到品牌-型号（海光 数字 / EPYC-数字 / Xeon-数字）→ 直接用识别值
回退逻辑线程：≥ 120 → 7380；≥ 90 → 7360；≥ 64 → 5380
n=0 兜底：MemTotal ≥ 800G → 7380；≥ 450G → 7360；否则 5380
```

**交叉校验与修正**（stress-lib-commands.sh L88-111）：识别结果与实测逻辑线程比对（标称 5380=64 / 7360=96 / 7380=128、EPYC-7763=128、Xeon-6338=64 等，未知型号如 `EPYC-9999` 跳过），偏差 >10% 时打印"型号识别结果与实测线程不符（检测到机型 X 标称 N 线程，实测 M 线程，偏差 P%）"；**仅海光四位数字型号标称与实测矛盾时才按实测线程分界修正**（≥120→7380、≥90→7360、≥64→5380）并提示"已按实测线程修正机型：X → Y"（如检测 5380 但实测 128 线程 → 修正为 7380）；AMD/Intel 品牌型号（EPYC-xxxx / Xeon-xxxx）无海光型号概念，**保留品牌标注、不做分界修正**（避免把 EPYC/Xeon 误标成海光档位）；标称未知型号保留品牌标注、跳过标称校验不误报。机型白名单（stress-lib-commands.sh L130-133）接受 `[0-9]{4}` / `EPYC-[0-9]+` / `Xeon-[0-9]+` 三种品牌-型号格式，显式 `--model 9800`、`--model EPYC-7763`、`--model Xeon-6338` 均放行。判定结果**仅用于报告标注与交叉校验**，不参与参数推导。

#### 2.12.5 内存计划（mem/combo，stress-lib-commands.sh L261-489）

**worker 数**（stress-lib-commands.sh L276-303）：显式 `--vm N` 优先（前导零十进制归一化，`10#$vm_opt`）；否则 = DIMM 根数；探测失败且无显式 → 打印中止信息与手动命令建议并退出。

**三道 cap 取最小**（stress-lib-commands.sh L305-327）：

```
cap_module = 单条容量 × 根数 × 88%（MEM_MAX_PCT）
             —— 仅 dmidecode 且全部 token 一致且 vm 数 == DIMM 根数时生效
cap_mem    = MemTotal × 92%（MEM_TOTAL_MAX_PCT）
cap_disk   = MemTotal − (盘流 × hdd-bytes × 1.2 + 8G)
             其中盘流 = max(实际盘数, --peer-disks)（disk_streams_eff）
             1.2 = DISK_CACHE_FACTOR_PCT/100，8G = DISK_CACHE_MIN_G
             （disk_need_mb = disk_streams_eff × hdd_mb × 120/100 + 8×1024，stress-lib-commands.sh L319）
cap_mb     = min(cap_module, cap_mem, cap_disk)   （cap_disk ≤ 0 直接报错退出）
```

**单 worker 字节**（三选一，stress-lib-commands.sh L344-414）：

1. **显式 `--vm-bytes X`**（bytes_from_preset=0）：原样保留，只告警不裁剪；需求超上限时警告"可能触发 OOM；按显式参数继续"。
2. **单根规则**（uniform 容量且 vm 数==DIMM 根数且 cap 存在）：`单 worker = 单条容量 − max(6G, 单条容量/8)`（stress-lib-commands.sh L358-377：`reserve_g=$(( uniform_g / 8 )); [ "$reserve_g" -lt 6 ] && reserve_g=6`）——32G→26G、64G→56G；超 cap 逐 GiB 下调（`clamped`，stress-lib-commands.sh L364-366，下调即 `log_op mem-clamp`）；降至 1G 仍超 → 报错退出。
3. **兜底**（混合容量 / EDAC 无容量 / 显式 --vm ≠ DIMM 数，stress-lib-commands.sh L378-414）：`mem_plan`（stress-lib-common.sh L290-306）——target=MemTotal×82%（MEM_TARGET_PCT），`单 worker = round(target/根数)`，回落至 MemTotal×92% 以内；再按 cap_mb 逐 GiB 下调。兜底原因写 `fallback_reason`（未探测到 DIMM 容量 / EDAC 无容量 / 显式 --vm 与 DIMM 根数不一致 / DIMM 容量混合或无法解析）。

**需求核对与描述**（stress-lib-commands.sh L434-472）：`need_mb = vm × per_mb` ≤ cap → "未超限"；超限按 bytes_from_preset 区分提示（显式参数继续 / 按当前参数继续）。`log_op mem-plan` 完整记录推导（stress-lib-commands.sh L487）。

**固定 `--vm-keep`**（stress-lib-commands.sh L268、stress-lib-commands.sh L516）：mem/combo 的 stress 命令固定追加 `--vm-keep`（内存常驻，避免压力回落）。

#### 2.12.6 --peer-disks 语义（stress-lib-commands.sh L37-48、stress-lib-commands.sh L241-259、stress-lib-commands.sh L183-186）

- 仅 combo/mem 生效；cpu/hdd 收到只告警不改变行为。
- 取值非负整数；`0` = 纯 CPU+内存。
- **只影响内存推导与展示**：`disk_streams_eff = max(实际盘数, peer)` 参与 cap_disk 预留；**不启动 hdd 进程**。
- combo 收到该参数后不再自动扫描 `/mnt/HDD*`（仅显式 `--dirs` 才在 combo 内启动 hdd）。
- review 的执行一致性判定中 peer_disks/disk_streams_eff **不参与** hdd 进程数对照。

## §3 oneclick.sh 全部模式执行逻辑

> 行号引用以拆分后各文件为准：`oneclick.sh` 拆为入口 + `oneclick-lib-basic.sh` / `oneclick-lib-run.sh`，函数按组位于对应 lib，行号按函数所在文件计。

### 3.1 脚本总览

- **用途**：一键压测入口（菜单/子命令）。编排内容：参数/菜单、前置检查、自动挂载、任务计划、终端窗口或后台启动、内部子命令 `__task`、就绪握手、失败即停，外加等待全部结束、自动逐个复盘、批次结束自动清空本批数据盘与汇总（oneclick.sh L2-9）。
- **调用形态**（usage，oneclick-lib-basic.sh L1-59）：

```
bash oneclick.sh                                   # 菜单（推荐）
bash oneclick.sh all|hdd|full|sysdisk|cpu|mem|clean [--timeout 10h]
bash oneclick.sh clean                             # 清空数据盘：卸载并 wipefs 全部非系统盘、非U盘（交互 y/N 确认；不进批次）
bash oneclick.sh --high [--timeout 10h]            # 一键中高强度整机压测（等价 full，不弹菜单）
bash oneclick.sh status
bash oneclick.sh review
bash oneclick.sh --help
```

- **选项**：`--timeout <时长>`（所有任务统一超时，默认 `10h`，数字 + 可选 d/h/m/s）、`--rebuild`（重新分区并格式化数据盘，会清空数据盘；仅 all/hdd/full 生效）、`--no-hdd`（仅 all 模式生效：排除所有硬盘，仅测 CPU+内存（COMBO peer=0）；跳过自动挂载，与 `--rebuild` 互斥）、`--no-cleanup`（批次结束不自动清空本批数据盘，默认自动清空；仅影响 all/full/hdd 且非 --no-hdd 的批次，oneclick.sh L206-209）、`--high`（一键中高强度整机压测，等价 `full`；仅 all/full 生效，与 `--no-hdd` 互斥；cpu/mem/hdd/sysdisk 带 `--high` 时提示忽略）、`--quiet`（不在终端打印实际执行命令，命令仍写入批次目录，等价 `ONECLICK_SHOW_CMD=0`）、`--help`。
- **退出码**（oneclick-lib-run.sh L741-744）：批次正常且全部任务复盘为"正常"且自动挂载正常 → `0`；`ABORTED`（COMBO 启动失败中止整批）或 `START_FAILED`（单盘/系统盘启动失败）或 `review_rc≠0`（复盘存在非"正常"结论）或 `MOUNT_RC≠0`（自动挂载存在跳过/失败盘）→ `1`。未启动任何任务（n=0）→ `1`（oneclick-lib-run.sh L727）。**批次结束自动清理的失败不改变退出码**（只标注 summary 并提示手动命令，见 §3.3 步骤 12）。
- **依赖脚本定位**（L12-22）：`ST`（默认同目录 `stress-test.sh`，可用 `ONECLICK_STRESS_TEST_SH` 覆盖）与 `DM`（默认同目录 `disk-mount.sh`，可用 `ONECLICK_DISK_MOUNT_SH` 覆盖）；相对路径规范化为绝对路径，存在性由 precheck 检查。
- **全局参数**（L24-71）：`POLL_INTERVAL` 默认 30（`ONECLICK_POLL_INTERVAL`，非法回落 30）、`READY_TIMEOUT` 默认 180（`ONECLICK_READY_TIMEOUT`）、`ONECLICK_SKIP_ROOT_CHECK` 默认 0、`SHOW_CMD` 默认 1、`REBUILD` 默认 0（L47）、`NO_HDD` 默认 0（`--no-hdd`，L48-49）、**`CLEANUP` 默认 1**（批次结束自动清空本批数据盘，`--no-cleanup` 置 0，L50-52；自动清理接缝 `FINDMNT_BIN`/`LSBLK_BIN`，L54-55）、`HIGH` 默认 0（`--high` 一键中高，L56-57）、`MOUNT_RC` 默认 0、`START_FAILED` 默认 0；**`FULL_CPU` / `FULL_VM` / `FULL_VMBYTES` 默认空（未设置）**（full 整机压测中高强度参数，未设置时按朋友规则推导：CPU≈round(逻辑线程×70%)、VM=DIMM 根数、vm-bytes=脚本单根推导 单条容量−max(单条/8,6G)，推导值显式下发不裁剪；可用环境变量显式覆盖、显式优先，L60-65；探测接缝 LSCPU_BIN/NPROC_BIN/CPUINFO/DMI_BIN/EDAC_ROOT 默认与 stress-test.sh 一致，L67-71）。

### 3.2 参数解析与菜单（main，L176-283）

1. `__task` 内部子命令优先分发（L177-185），参数不足（<4）报错退出。
2. 选项循环（L188-244）：`-h|--help` → 打印 usage 退出 0；`--quiet` → `SHOW_CMD=0`；`--rebuild` → `REBUILD=1`；`--no-hdd` → `NO_HDD=1`；`--no-cleanup` → `CLEANUP=0`（L206-209）；`--high` → `HIGH=1`；`--timeout <V>` / `--timeout=<V>`；子命令 `all|hdd|full|sysdisk|cpu|mem|clean|status|review`；未知参数 → 打印 usage 退出 1。
3. 互斥校验（L246-258）：`--high` 与 `--no-hdd` 互斥（中高强度必含硬盘）→ 报错退出；`--no-hdd` 仅 all 模式支持 → 报错退出；`--no-hdd` 与 `--rebuild` 互斥 → 报错退出。
4. `--timeout` 合法性校验（L260-263）：`^[0-9]+[dhms]?$`，非法（如裸字母）报错退出。
5. **--high 归一**（L266-275）：`HIGH=1` 时按模式归一——无模式（`""`）/ `all` / `full` → 直接 `mode=full`（无模式即一键直达中高整机压测，跳过菜单）；`status`/`review` 不受影响；`cpu`/`mem`/`hdd`/`sysdisk` → 打印提示"--high 仅对整机（all/full）生效，本次忽略"并复位 `HIGH=0`。
6. 无模式参数（且非 --high）→ 进入菜单 `menu_loop`（L150-172）：菜单项 1)求稳强度压测（all，参数自动推导保守）2)中高强度整机压测（full，参数按朋友规则推导，FULL_* 显式设置可覆盖）3)测 CPU+内存（排除硬盘）4)只测硬盘（数据盘）5)只测系统盘 6)只测 CPU 7)只测内存 8)查看状态 9)生成复盘 10)清空数据盘（run_mode clean，交互 y/N 确认、不进批次）0)退出（show_menu，L117-133）。项 1/2/4 且未带 `--rebuild` 时先执行 `ask_rebuild`（仅 `y|Y` 置 `REBUILD=1`，其余置 0，L136-148）；项 3 直接 `NO_HDD=1; REBUILD=0; run_mode all`（等价 CLI `all --no-hdd`，不询问 rebuild）；项 1/2/4 前显式复位 `NO_HDD=0` 防串味。
7. `status`/`review`/`clean` 分发（L277-282）：`status`/`review` 直接分发到对应子命令，不进 `run_mode`；`clean` 进 `run_mode clean`（run_mode 开头直接 `exec bash "$DM" clean`，见 §3.3）。

### 3.3 运行类模式统一流程（run_mode，oneclick-lib-run.sh L624-745）

所有运行模式（all/hdd/full/sysdisk/cpu/mem）共享的执行序列；`clean` 模式不经批次——run_mode 开头 `mode=clean` 时直接 `exec bash "$DM" clean`（交互 y/N 确认、不进批次、不依赖压测环境，oneclick-lib-run.sh L627-630）：

1. **--rebuild 口径**（oneclick-lib-run.sh L631-646）：all/hdd/full 打印提示；其他模式提示"仅对 all/hdd/full 生效，本次忽略"并复位 `REBUILD=0`。
2. **前置检查 precheck**（oneclick-lib-run.sh L647；函数 oneclick-lib-run.sh L3-20）：root 检查（`ONECLICK_SKIP_ROOT_CHECK=1` 跳过）→ `command -v stress` 失败即"未找到 stress，请先运行：sudo bash install.sh"退出 1 → ST/DM 脚本文件存在检查。
3. **导出命令显示开关**（oneclick-lib-run.sh L649）：`export ONECLICK_SHOW_CMD="$SHOW_CMD"`，保证窗口/后台里的 `__task` 同样遵守 `--quiet`。
4. **批次目录准备**（oneclick-lib-run.sh L651-661）：`mkdir -p $STRESS_TEST_ROOT`；批次名 `oneclick-<YYYYMMDD-HHMMSS>`（同名冲突追加 `-<k>`，oneclick-lib-run.sh L654-657）；写 `start.time` / `timeout.txt`。
5. **命令清单先行**（oneclick-lib-run.sh L663-673）：先建空 `commands.txt`（do_mount 在 write_plan 内执行，必须早于挂载建好），再生成可重放 `commands.sh`（shebang + 批次路径 + 重放警告 + `set -u`，`chmod 0644`）。
6. **终端探测**（oneclick-lib-run.sh L675-678；pick_terminal，oneclick-lib-run.sh L24-43）：见 3.6；`TERM_KIND=none` 时提示"未检测到图形终端，改为后台并行执行；实时数据：tail -f <结果目录>/monitor.csv"。
7. **环境快照**（oneclick-lib-run.sh L679-680）：`write_env_file` → `env.txt`；打印批次目录。
8. **生成任务计划**（oneclick-lib-run.sh L682-683；write_plan，oneclick-lib-run.sh L255-380）：见 3.5；`plan.txt` 为空 → die "任务计划为空，未启动任何任务"。
9. **逐条启动 + 就绪握手**（oneclick-lib-run.sh L685-721）：见 3.6 / 3.7。
10. **等待全部结束**（oneclick-lib-run.sh L732；wait_all，oneclick-lib-run.sh L463-480）：见 3.8。等待期间主终端 Ctrl-C 只退出等待（`trap INT` → 打印提示 + exit 130），压测仍在后台运行（oneclick-lib-run.sh L731）。
11. **自动逐个复盘**（oneclick-lib-run.sh L734-736；run_review_all，oneclick-lib-run.sh L485-555）：见 3.9。
12. **批次结束自动清理数据盘**（oneclick-lib-run.sh L738-739；run_auto_clean，oneclick-lib-run.sh L181-251）：仅 all/full/hdd 且非 `--no-hdd`、`CLEANUP=1`、批次有数据盘时执行——按批次 `cleanup-devices.txt`（write_plan 末尾 `record_cleanup_devices` 写入，oneclick-lib-run.sh L370-377；函数 L161-174）逐盘预检：盘已不存在、或盘上出现非 `/mnt/HDD*` 挂载点（业务数据）→ 跳过该盘并在 summary 标注、不整批失败；剩余盘经 `show_run` 展示并落 commands.txt，执行 `bash "$DM" clean --disks <列表> --yes`，输出写 `$BATCH/clean.log`（独立挂载日志 `clean.mount.log`）；结果以 `数据盘清理: ...` 追加进 summary.txt；清理失败只标注并提示手动命令，**不改变 review 结论与批次退出码**（oneclick-lib-run.sh L188-249）。
13. **最终退出码**（oneclick-lib-run.sh L741-744）：见 3.1。

### 3.4 前置流程细节

- **自动挂载 do_mount**（oneclick-lib-run.sh L127-135）：`bash "$DM" mount --disks all --yes`（`REBUILD=1` 时追加 `--rebuild`），输出 `tee` 到 `$BATCH/mount.log`，`MOUNT_RC=${PIPESTATUS[0]}`。write_plan 在 all/hdd/full 模式下调用（oneclick-lib-run.sh L259-277）；`rc≠0` 时记录 `MOUNT_RC` 并警告"自动挂载返回非 0（$rc），继续按当前已挂载盘执行；挂载日志：$BATCH/mount.log"（oneclick-lib-run.sh L274）；hdd 模式 `rc≠0` 且无任何已挂载盘 → die "未发现已挂载的数据盘（/mnt/HDD*），请先运行 bash disk-mount.sh mount"（oneclick-lib-run.sh L269-273）。
- **本批数据盘记录 record_cleanup_devices**（oneclick-lib-run.sh L161-174）：write_plan 末尾对 all/full/hdd 且非 `--no-hdd` 调用（oneclick-lib-run.sh L370-377）——对每个 `/mnt/HDD*` 目录 `findmnt -n -o SOURCE --target` 取设备 → `basename` → `cleanup_parent_disk`（oneclick-lib-run.sh L142-156）归一父整盘名（优先 `lsblk PKNAME`，无父盘按分区后缀兜底剥离）→ 去重写 `$BATCH/cleanup-devices.txt`；目录未挂载（findmnt 失败/无输出）不记录。该文件是批次结束自动清理（§3.3 步骤 12）的范围依据。
- **数据盘枚举 collect_hdd_dirs**（oneclick-lib-run.sh L109-125）：`df -P` 输出经 awk 跳过前 5 个空白分隔字段后匹配 `^/mnt/HDD[^/]*$`（只算顶层挂载点，`/mnt/HDD01/sub` 嵌套挂载点不算，避免重复任务；挂载点含空格也支持，`\040` 转义还原）；`sort -u` 去重。
- **前置检查 precheck** 见 3.3 第 2 步。

### 3.5 write_plan 计划生成（按模式，oneclick-lib-run.sh L255-380）

计划行格式：`<任务ID>|<类型>|<附加参数...>`（启动时以 `IFS='|'` 解析，oneclick-lib-run.sh L688）。**计划顺序即启动顺序**。

| 模式 | plan.txt 内容（逐行，按序） |
| --- | --- |
| `all` | `COMBO\|combo\|--peer-disks\|<N>`（N=数据盘数+1，oneclick-lib-run.sh L297）→ 每数据盘 `HDDxx\|hdd\|--dirs\|<挂载点>`（oneclick-lib-run.sh L305）→ `SYSDISK\|hdd\|--sysdisk-only`（oneclick-lib-run.sh L308） |
| `full` | `COMBO\|combo\|--peer-disks\|<N>\|--cpu\|<FULL_CPU>\|--vm\|<FULL_VM>\|--vm-bytes\|<FULL_VMBYTES>`（朋友规则推导值或显式值，非空总是写入；N=数据盘数+1，oneclick-lib-run.sh L338-342）→ 每数据盘 `HDDxx\|hdd\|--dirs\|<挂载点>`（oneclick-lib-run.sh L350）→ `SYSDISK\|hdd\|--sysdisk-only`（oneclick-lib-run.sh L353） |
| `hdd` | 每数据盘 `HDDxx\|hdd\|--dirs\|<挂载点>`（oneclick-lib-run.sh L362） |
| `sysdisk` | `SYSDISK\|hdd\|--sysdisk-only`（oneclick-lib-run.sh L365） |
| `cpu` | `CPU\|cpu\|`（oneclick-lib-run.sh L366） |
| `mem` | `MEM\|mem\|`（oneclick-lib-run.sh L367） |

- **all 模式**（oneclick-lib-run.sh L280-309）：先 `collect_hdd_dirs` 计数（目录名含 `|` → die "目录名含 | 不受支持"，oneclick-lib-run.sh L293/L303），再写计划；无数据盘时打印"未发现数据盘，跳过数据盘任务（COMBO peer=1 + 系统盘）"（oneclick-lib-run.sh L298-299）；系统盘任务**固定**追加（无论是否有数据盘）。
- **full 模式（整机压测，oneclick-lib-run.sh L310-354）**：与 all 的**结构完全一致**（先 do_mount 挂载 → COMBO 先启动 → 每盘 HDDxx → SYSDISK），仅 COMBO 行的参数来源不同：`--peer-disks` 始终写入；`--cpu <FULL_CPU>` / `--vm <FULL_VM>` / `--vm-bytes <FULL_VMBYTES>` **按朋友规则推导或显式设置（非空，总是写入）**（oneclick-lib-run.sh L315-325 调用 `full_params_friend`，函数定义在 oneclick.sh L88-113；FULL_* 默认空，L60-65）。朋友规则（中高强度）：CPU≈round(逻辑线程×70%)（如 64→45、128→90）、VM=DIMM 根数、vm-bytes=脚本单根推导 单条容量−max(单条/8,6G)（32G 条→26G、64G 条→56G）；**显式 FULL_* 优先，未设置项由推导补齐**；推导失败（硬件探测不可用）时告警并回退 stress-test.sh 自动推导（同 all 口径）。这些参数经 `stress_argv` **原样透传**到 `bash <ST> start combo --timeout <T> --peer-disks <N> --cpu <V> --vm <V> --vm-bytes <V>`，走 cmd_start 的"显式参数优先"路径（见 §2.12.7）：`--cpu` / `--vm` 原样使用（stress-lib-commands.sh L277-283）、`--vm-bytes` **只告警不裁剪**（stress-lib-commands.sh L345-357），故朋友规则推导/显式设置的高强度值（如 5380 的 45/12/26G=312G）不受自动推导/三道上限裁剪影响；安全兜底仍生效：MemTotal 不可读且无显式 `--vm-bytes` 才中止（朋友规则推导失败回退自动推导时可能因此中止，推导成功/显式设置则不会）、`cap_disk ≤ 0`（盘流预留超内存）仍拒绝启动（stress-lib-commands.sh L321-324）。
- **COMBO 的 `--peer-disks N`**：N=数据盘数+1（固定含系统盘）；combo 收到该参数后不再自动扫描 `/mnt/HDD*`、不启动 hdd 进程（每块数据盘由各自的独立 hdd 任务压），`cap_disk` 按 `max(实际盘数, N)` 预留（语义见 §2.12.6）。
- **任务实际执行 argv** 统一为 `bash <ST> start <type> --timeout <T> [extra...]`（`stress_argv`，oneclick-lib-basic.sh L77-82）；主终端 `show_run` 显示并落盘 `commands.txt` / `commands.sh`（oneclick-lib-run.sh L698-699）。
- 计划打印：`sed 's/^/  /'` 缩进输出（oneclick-lib-run.sh L378-379）；末尾对 all/full/hdd 且非 `--no-hdd` 调用 `record_cleanup_devices` 写 `cleanup-devices.txt`（oneclick-lib-run.sh L370-377，见 §3.4）。

### 3.6 启动方式：终端探测、launch_task、__task、就绪握手

- **终端探测 pick_terminal**（oneclick-lib-run.sh L24-43）：`ONECLICK_GUI=0` → `none`；`DISPLAY` 与 `WAYLAND_DISPLAY` 均未设置（SSH/无图形环境）→ `none`；否则按 `gnome-terminal` → `mate-terminal` → `xterm` 顺序探测，都没有 → `none`。
- **终端标题 task_title**（oneclick-lib-run.sh L45-54）：

| 任务 ID | 窗口标题 |
| --- | --- |
| `COMBO` | `压测-组合CPU+内存` |
| `HDDxx` | `压测-HDDxx` |
| `SYSDISK` | `压测-系统盘` |
| `CPU` | `压测-CPU` |
| `MEM` | `压测-内存` |

- **launch_task**（oneclick-lib-run.sh L58-74）：构造 `cmd="bash <PKG_DIR>/oneclick.sh __task <BATCH> <id> <TIMEOUT> <type> [extra...]"`；有终端时 `gnome-terminal --title="$title" -- bash -c "$cmd"`（mate-terminal/xterm 同构，xterm 为 `-T "$title" -e bash -c "$cmd"`）；`none` 时降级后台并行：`ONECLICK_NO_TAIL=1 bash -c "$cmd" >> "$BATCH/$id.out" 2>&1 < /dev/null &`（输出写批次目录 `<任务>.out`）。
- **内部子命令 __task**（cmd_task，oneclick-lib-run.sh L384-427）：重建本任务 argv → 打印启动 banner → 执行 `"${STRESS_ARGV[@]}" 2>&1 | tee "$batch/$id.start.log"` → 退出码写 `$id.startrc`；`rc≠0` → 建 `$id.fail` 退出 1；从启动输出解析结果目录（`sed -n 's/^已启动 .*压测：//p'`，对应 stress-lib-commands.sh L686 的"已启动 ${type} 压测：$dir"）→ 写 `$id.dir`；`ONECLICK_NO_TAIL=1` → 立即退出（后台模式）；否则 `tail -f --pid=<monitor.pid> monitor.csv` 实时监控，结束打印结果目录并"按回车关闭窗口"（oneclick-lib-run.sh L414-426）。
- **就绪握手 wait_ready**（oneclick-lib-run.sh L86-105）：轮询至多 `READY_TIMEOUT` 秒（默认 180）：`$id.dir` 出现 → 追写 `tasks.txt`（`id|type|结果目录`）返回 0；`$id.fail` 出现 → 打印启动输出末尾 20 行（`show_start_log_tail`）返回 1；超时 → "任务 $id 启动超时"返回 1。

### 3.7 失败策略

- 任一任务启动失败（wait_ready 返回 1）：打印可直接复制重跑的命令（`LAST_TASK_CMD`）→ 写 `failed-tasks.txt`（格式 `任务ID|完整命令`，oneclick-lib-run.sh L708）→ 打印已启动任务清单（oneclick-lib-run.sh L709）。
- **COMBO 启动失败 → 中止整批**（oneclick-lib-run.sh L710-716）：`ABORTED=1`，写 `$BATCH/aborted` 文件（"任务 COMBO 启动失败，已停止启动后续任务"），`break` 不再启动后续任务（COMBO 是核心 CPU+内存负载）。
- **单盘/系统盘启动失败 → 记录后继续**（oneclick-lib-run.sh L718-719）：`START_FAILED=1`，打印"已跳过并继续启动后续任务（记录：$BATCH/failed-tasks.txt）"。
- 批次最终退出码（oneclick-lib-run.sh L741-744）：`ABORTED=1` 或 `START_FAILED=1` 或 `review_rc≠0` 或 `MOUNT_RC≠0` → `exit 1`；否则 `exit 0`。全部启动失败（n=0）→ `exit 1`（oneclick-lib-run.sh L727）。**批次结束自动清理失败不改退出码**（见 §3.3 步骤 12）。

### 3.8 wait_all（oneclick-lib-run.sh L463-480）

- 读 `tasks.txt` 逐行调用 `task_done`（oneclick-lib-run.sh L438-460）：`status.txt` 存在 → 完成；结果目录/`stress.pids` 缺失 → 视为"无需等待"直接放行（由复盘输出未知/异常）；否则"全部 PID 退出（`kill -0` 判定）且 `*.exitcode` 文件数 ≥ pids 行数" → 完成。
- 每 `POLL_INTERVAL` 秒（默认 30）打印"进行中 N 个：<id 列表>"；`pending=0` → 返回。

### 3.9 自动复盘（run_review_all，oneclick-lib-run.sh L485-555）

- 对 `tasks.txt` 每个任务执行 `bash "$ST" review --dir <结果目录>`，输出写 `$id.review.txt`（复盘命令去重落盘 commands.txt，`show_once_argv` oneclick-lib-basic.sh L70）。
- 解析"结论: "行；结论非"正常" → `bad+1`；`failed-tasks.txt` 非空 → 再 +1（oneclick-lib-run.sh L540）。
- **summary.txt 内容**（oneclick-lib-run.sh L495-551）：一键压测汇总 / 批次目录 / 开始时间（start.time）/ 结束时间 / 超时（timeout.txt）/ 自动挂载状态（`MOUNT_RC≠0` → "存在跳过/失败盘（退出码 N，未挂载盘未参与压测）"）/ `任务-类型-结论` 表 / 启动失败清单 / 结果目录清单，末尾 `cat` 打印；批次结束自动清理再追加 `数据盘清理: ...` 段落（见 §3.3 步骤 12）。
- 返回 0 当且仅当 `bad=0`（全部"正常"且无启动失败）。

### 3.10 status / review 子命令（基于最近批次）

- `latest_batch`（oneclick-lib-run.sh L560-562）：`ls -1d "$STRESS_TEST_ROOT"/oneclick-* | sort | tail -1`。

## §4 辅助工具脚本执行逻辑

### 4.1 install.sh（共 62 行）

- **用途**：离线安装 `stress`、`dmidecode`、`nvme-cli` 三个 RPM（Kylin V10 SP3，服务器无网络）。dmidecode 用于自动探测内存条根数；nvme-cli 用于 check-nvme-health.sh 健康检查（`nvme smart-log` / `nvme list`）。
- **调用形态**：`sudo bash install.sh`。
- **退出码**（L4）：0=成功（含已装同版本）；1=失败（非 root / 校验失败 / 安装失败）。
- **执行流程**：
  1. 解析自身目录并 `cd`（任意位置调用，L8-9）。
  2. **安装清单** `RPM_LIST`（L14-18）：`rpm 路径 | 锁定 SHA256 | 包名 | 已安装判定串`，顺序即安装顺序（stress 先、dmidecode 后、nvme-cli 最后）。锁定 SHA256：stress `0090571FD05C307DBE894E0FCF1E9804DBB27EA64D11A6D0248FFA61AE93EFDA`、dmidecode `CD2F140BD1718B4403AD66568155264B69231748A3C813E2FEAAC1B704DA62C6`、nvme-cli `691F4B28D1E1668CABD38A01952F6E877FBFE0D53491E49790808C8878703FA0`。
  3. **root 检查**（L20-24）：非 root 且未设 `INSTALL_SKIP_ROOT_CHECK=1` → 提示退出。
  4. **文件存在检查**（L26-35）：任一 RPM 缺失 → 整体退出（避免装一半）。
  5. **SHA256 锁定校验**（L37-44）：`echo "$locked_sha  $rpm_file" | sha256sum -c -`，任一不匹配 → "RPM 校验失败...文件可能损坏"整体退出。
  6. **逐个安装**（L46-59）：`rpm -q <pkg> | grep -q <判定串>` 命中 → "已安装：..."跳过；否则 `rpm -Uvh`，成功打印安装结果，失败 → 提示检查上方 rpm 输出并退出 1（NOKEY 签名警告属正常现象，以退出码判定成败）。
  7. 收尾打印"下一步运行 bash verify.sh"退出 0（L61-62）。
- **产物/日志**：无独立日志文件，结果直接打印到终端。

### 4.2 verify.sh（共 66 行）

- **用途**：install.sh 之后验证安装（五项检查）。
- **调用形态**：`bash verify.sh`；`VERIFY_SKIP_SMOKE=1` 跳过冒烟压测（检查 C 输出 SKIP）。
- **退出码**（L4）：0=全部通过（PASS）；1=任一检查失败（FAIL）。
- **预期常量**（L11-13）：`EXPECTED_RPM_QUERY="stress-1.0.4-24.el8.x86_64"`、`EXPECTED_VERSION="1.0.4"`、`SMOKE_CMD="stress --cpu 2 --vm 1 --vm-bytes 256M --timeout 10"`。
- **五项检查**（全程不 `set -e`，命令缺失也走 FAIL 分支不崩溃）：
  - **检查 A**（L19-24）：`rpm -q stress` 输出精确匹配 `stress-1.0.4-24.el8.x86_64`（`grep -qx`）。
  - **检查 B**（L27-32）：`stress --version` 输出包含 `1.0.4`。
  - **检查 C**（L35-42）：冒烟压测 `SMOKE_CMD` 退出码 0；`VERIFY_SKIP_SMOKE=1` → "SKIP 检查C"。
  - **检查 D**（L46-50）：`command -v dmidecode` → PASS（附 `dmidecode -V` 版本）；**缺失只 WARN 不判 FAIL**——start mem/combo 将回退 EDAC（`/sys/devices/system/edac/mc`），仍不可用时会给出手动 `--vm` 建议命令；EDAC 是内核接口而非软件包，不在此校验。
  - **检查 E**（L52-57）：`command -v nvme-cli` → PASS（附 `nvme version` 版本）；**缺失只 WARN 不判 FAIL**——install.sh 已含 nvme-cli，提示重跑 install.sh 或手动安装。
- **汇总**（L59-66）：全部 PASS → 输出 "PASS" 退出 0；任一 FAIL → 输出 "FAIL" 退出 1。

### 4.3 disk-mount.sh（拆分后：入口 + disk-mount-lib-detect/plan/commands.sh）

- **用途**：硬盘压测前挂载测试盘（`stress-test.sh start hdd` 前置条件之一）；压测后一键清空数据盘（`clean`）。
- **调用形态**（usage，disk-mount-lib-detect.sh L3-32）：

```
bash disk-mount.sh list
bash disk-mount.sh mount [--disks sdb,sdc] [--yes] [--rebuild] [--dry-run]
bash disk-mount.sh umount [--all]
bash disk-mount.sh clean [--disks sdb,sdc] [--yes] [--dry-run]
```

- **退出码**（disk-mount.sh L18）：0=全部成功（含取消/无需操作）；1=用法/前置错误、含系统盘、存在跳过或失败盘（clean 的 `--disks` 指定系统盘 / U 盘 / 不存在盘同样退出 1）。
- **系统盘识别**（disk-mount-lib-detect.sh L53-91）：`df /` 取底层设备 → 沿 `lsblk` 的 `pkname` 逐层上溯到 `TYPE=disk` 整盘（覆盖 LVM/mapper 布局）；`SYS_ID_OK` 可靠性标记 fail-closed（不可靠时 mount / clean 流程拒绝任何写操作，disk-mount-lib-commands.sh L99-110 / L247-254）；`is_sys_disk_or_part` 硬排除系统盘及其分区（disk-mount-lib-detect.sh L94-102）。
- **数据盘收集**（disk-mount-lib-detect.sh L111-146）：`TYPE=disk` 的 `sd*`/`nvme*`/`vd*`/`mmcblk*`；首分区 = 第一个"非扩展分区"（排除 msdos 扩展容器 0x5/0xf/0x85，disk-mount-lib-detect.sh L116-120）。
- **list**（disk-mount-lib-commands.sh L3-30）：列出全部块设备并标注系统盘（"系统盘，跳过"）；非系统盘逐盘状态说明（`disk_status`：已挂载（跳过）/ 有分区（默认测首个分区）/ 未分区但已有文件系统（直接挂载不重新格式化）/ 未分区空盘（mkfs.ext4 -m 0））。
- **mount**（disk-mount-lib-commands.sh L34-220）：
  1. 参数解析 + `root_check` + 收集非系统盘（disk-mount-lib-commands.sh L36-47）；无非系统盘 → "未发现非系统盘...无需挂载"退出 1（disk-mount-lib-commands.sh L49-52）。
  2. **选择盘**（disk-mount-lib-commands.sh L55-69）：`--disks`（`all`=全部或逗号列表）优先；否则交互输入（`all` 全部）；非交互模式（无终端）必须 `--disks`，否则退出。
  3. **校验**（disk-mount-lib-commands.sh L86-97）：含系统盘 → "拒绝：$c 是系统盘（$SYS_BASE），永不纳入测试"退出 1；盘不存在/不是非系统块设备 → 报错退出。
  4. **前置**（disk-mount-lib-commands.sh L99-117）：`SYS_ID_OK≠1` 且非 DRY_RUN → 中止不执行写操作；`--rebuild` 需系统自带 `parted`，缺失退出。
  5. **生成并打印完整执行计划**（build_plan disk-mount-lib-plan.sh L57-141 + print_plan disk-mount-lib-plan.sh L143-174）：
     - **默认模式（不清盘）决策树**：子树已挂载 → 跳过（非测试挂载点显式提示并计失败）；仅扩展分区容器 → 跳过计失败；有分区表但无分区 → 跳过计失败；`blkid` 探测（probe_fs_retry，最多 5 次间隔 1 秒，disk-mount-lib-detect.sh L265-279）失败 → 跳过计失败、**绝不格式化**；有文件系统 → `mount`；无文件系统 → `mkfs_mount`（`mkfs.ext4 -m 0` + mount）。有分区 → 测**首个分区**；无分区 → 测整盘。
     - **`--rebuild`**（disk-mount-lib-plan.sh L67-83）：存在非 `/mnt/HDD*` 挂载点（业务数据）→ 整盘跳过**绝不重建**；已在 `/mnt/HDD*` 挂载 → 先卸载后原地重建；否则分配新编号。步骤（do_rebuild，disk-mount-lib-plan.sh L232-287）：umount 旧挂载 → `parted mklabel gpt` → `mkpart primary ext4 1MiB 100%` → `partprobe` → `udevadm settle`（缺失则 sleep 1）→ `lsblk` 解析分区设备（不盲拼 "1"，NVMe/mmcblk 按实际名称，disk-mount-lib-detect.sh L283-295）→ `mkfs.ext4 -m 0` → mount。
  6. **DRY_RUN**（disk-mount-lib-commands.sh L123-132）：只打印计划（等价 `DRY_RUN=1`），按计划风险给出与真实执行一致的退出码。
  7. **无动作项**（disk-mount-lib-commands.sh L134-143）：全部跳过且均为良性"已挂载"→ "所选盘均已挂载，无需操作"退出 0；存在计失败跳过项 → 打印汇总退出 1。
  8. **确认**（disk-mount-lib-commands.sh L145-154）：单个 `y` 确认（`--yes` 跳过，供 oneclick.sh 调用）；取消 → "已取消，未执行任何操作"退出 0。
  9. **执行**（disk-mount-lib-commands.sh L156-207）：逐盘按计划动作执行（mount / mkfs_mount / rebuild / skip），失败逐条收集进 `fails` 数组。
  10. **汇总**（disk-mount-lib-commands.sh L209-220）：有失败 → 打印"跳过/失败汇总"+"全部完成（存在跳过/失败盘，未挂载的盘不参与压测）"退出 1；否则"全部完成"退出 0。
  - **挂载点编号**（disk-mount-lib-plan.sh L3-46）：已占用编号（`df -P` ∪ lsblk 中 `/mnt/HDD[0-9]*` 的数字）不复用；`alloc_mount_number` 分配最小可用编号，挂载点 `printf '/mnt/HDD%02d'`（/mnt/HDD01...）。
  - **日志** `MOUNT_LOG`（默认 `/root/stress-test/mount.log`）：`run_log` 每步实时 tee 到控制台与日志，末尾追加 `[时间] cmd: ... 结果:$?`（disk-mount-lib-plan.sh L220-226）；`assign_log` 记录编号分配（disk-mount-lib-plan.sh L210-214）。
- **umount**（disk-mount-lib-commands.sh L404-456）：`df -P` 收集 `/mnt/HDD[0-9]*` 挂载点；无 → "没有已挂载的测试盘（/mnt/HDD*）"退出 0；列出 → `y` 确认（`--all` 跳过）→ 逐个 `umount`（失败打印"卸载失败...见 mount.log"不中断）→ "全部完成。挂载日志：..."。
- **clean**（cmd_clean，disk-mount-lib-commands.sh L222-401，函数 L231-400）：一键清空非系统盘、非U盘，供 oneclick 批次结束自动清理与菜单项 10 调用——
  - **范围**：`--disks` 显式指定（分区经 `disk_parent` 归一为整盘，disk-mount-lib-detect.sh L176-181；系统盘 / U 盘 / 不存在盘一律拒绝退出 1，disk-mount-lib-commands.sh L268-279）或默认枚举全部非系统盘、非U盘（`disk_is_usb` 排除，disk-mount-lib-detect.sh L158-172；含业务挂载点盘，计划中醒目标注，L317-330）；
  - **语义**：逐盘 `umount` 全部子树挂载点（`disk_mountpoints`，disk-mount-lib-detect.sh L228-230）→ `wipefs -a <整盘>` 清空文件系统/分区表签名（disk-mount-lib-commands.sh L376-380）→ `partprobe` 刷新（L381-385），盘回到**空白状态**（无分区、无签名）；只清理、**不重建分区表**（重建用 mount `--rebuild`）；
  - **安全**：系统盘识别不可靠（`SYS_ID_OK≠1`）且非 dry-run → 中止零写（disk-mount-lib-commands.sh L247-254，dry-run 仅告警）；空白盘（`wipefs -n` 无输出）跳过（L309-315）、`wipefs -n` 不可用/失败 fail-safe 照清；执行期任一步失败只跳过该盘、其他盘继续，退出码 1（L360-398）；`--dry-run` 只打印计划、零写操作、不写 mount.log（L336-339）；`--yes` 跳过 y 确认（L347-355，供 oneclick 自动清理调用）；**不影响 SMART 数据**——wipefs 只清块设备签名，不读写 SMART 属性（通电时间/通电次数不变）。
- **测试接缝**（disk-mount.sh L23-35）：`DRY_RUN` / `SKIP_ROOT_CHECK` / `MOUNT_LOG` / `LSBLK_BIN` / `BLKID_BIN` / `PARTED_BIN` / `PARTPROBE_BIN` / `UDEVADM_BIN` / `MKFS_BIN` / `MOUNT_BIN` / `UMOUNT_BIN` / `DF_BIN`，clean 新增 `WIPEFS_BIN`（L35）。

### 4.4 mount-iso.sh（拆分后：入口 + mount-iso-lib-usb/repo/commands.sh）

- **用途**：U 盘挂载 + yum 源构建/复制/配置一键脚本（无外网服务器）。
- **调用形态**（L33-55）：

```
bash mount-iso.sh build [--rpm-dir /path/to/rpms]   # 构建 yum 源（createrepo 生成 repodata）
bash mount-iso.sh mount                              # 一键：U盘挂载 → 复制源目录到 /opt/kylin-repo → 配置本地yum源
bash mount-iso.sh status                             # 查看挂载与本地源状态
bash mount-iso.sh umount                             # 卸载U盘（确认后执行；不影响已复制的本地源）
```

- **退出码**（L18）：0=正常（含取消/DRY_RUN 计划）；1=用法错误/前置不满足/无 USB 盘/RPM 或 repodata 缺失。
- **系统盘硬排除**（mount-iso-lib-usb.sh L4-50）：`findmnt -no SOURCE /` 取 / 设备（失败回退 `df /`）→ `lsblk -s -P` 反解析到 `TYPE=disk` 整盘；兜底正则去分区号；`is_sys_disk_or_part` 基于 NAME/PKNAME 精确判定。
- **U 盘识别**（mount-iso-lib-usb.sh L103-139）：`TYPE=disk` 且 `TRAN=usb`（`usb_disk`，硬排除系统盘）；首个有效分区（`TYPE=part` 且 `FSTYPE` 非空，跳过扩展容器），无有效分区则挂整盘（`usb_first_part`）。
- **build**（mount-iso-lib-commands.sh L4-84）：
  1. **RPM 来源优先级**（mount-iso-lib-commands.sh L17-37）：U 盘内（已挂载且含 `*.rpm`，`locate_rpm_dir` 优先 `<root>/rpms` 再 root 下 maxdepth 2）> `--rpm-dir` > 包内 `rpms/`；均无 → 退出。
  2. **createrepo 可用性**（mount-iso-lib-commands.sh L39-47）：缺失 → 提示"yum install createrepo 或 dnf install createrepo_c"（DRY_RUN 只提示不退出）。
  3. **构建**（mount-iso-lib-commands.sh L48-56）：`$CREATEREPO_BIN --update <src>` 生成 `repodata/`。
  4. **落盘 $REPO_DEST**（默认 `/opt/kylin-repo`，mount-iso-lib-commands.sh L58-65）：`is_path_inside` 防止源/目标同一导致自我复制；`copy_dir_into`（目标已存在非空 → 交互"覆盖合并（y）/跳过（N）"）。
  5. **写入 U 盘一份**（mount-iso-lib-commands.sh L67-80）：`$USB_MOUNT_POINT/kylin-repo`（U 盘已挂载时）；未挂载 → 提示可稍后 `mount` 拷贝。
- **mount**（mount-iso-lib-commands.sh L88-155）四步：
  1. **1/4 检测并挂载 U 盘**（`mount_usb`，mount-iso-lib-commands.sh L91-103）：无 USB 盘 → 给出手动挂载示例（`mkdir -p /mnt/usb`、`mount /dev/sdX1 /mnt/usb`）退出；已挂载到 `$USB_MOUNT_POINT` → 跳过；挂在别处 → 提示先 umount。
  2. **2/4 定位 U 盘内 yum 源目录**（`find_repodata_dir`，mount-iso-lib-commands.sh L105-111）：U 盘内 `maxdepth 3` 找 `repodata` 父目录（多个取第一个并提示）；无 → "可用 bash mount-iso.sh build 从 RPM 包构建源后再 mount"退出。
  3. **3/4 复制到系统**（mount-iso-lib-commands.sh L113-117）：`copy_dir_into` → `$REPO_DEST`。
  4. **4/4 配置本地 yum 源**（mount-iso-lib-commands.sh L119-135）：校验 `$REPO_DEST/repodata`（缺失则不写 repo 退出）→ `write_repo_file`（文件已存在 → 返回 2 不覆盖，打印实际 baseurl；内容 `[kylin-local]` / `baseurl=file://$REPO_DEST` / `enabled=1` / `gpgcheck=0`）。
  5. **验证**（mount-iso-lib-commands.sh L137-154）：`ls $REPO_DEST | head`、`yum repolist`（失败仅提示"不影响已完成的复制与配置"）。
- **status**（mount-iso-lib-commands.sh L159-207）：U 盘挂载状态（检测到/挂载点/实际挂载位置）、`$REPO_DEST`（存在/条目数/含 repodata）、`$YUM_REPO_FILE`（存在/baseurl）、操作日志路径。
- **umount**（mount-iso-lib-commands.sh L211-255）：未挂载 → "未挂载，无需卸载"退出 0；设备 `TRAN≠usb` → "拒绝卸载"退出 1；`y` 确认；`umount $USB_MOUNT_POINT`；打印"本地源 $REPO_DEST 与 $YUM_REPO_FILE 未受影响（U 盘可拔）"与手动清理命令（`rm -rf $REPO_DEST`、`rm -f $YUM_REPO_FILE`）。
- **测试接缝**（L21-29）：`DRY_RUN` / `SKIP_ROOT_CHECK` / `MOUNT_LOG` / `LSBLK_BIN` / `CREATEREPO_BIN` / `USB_MOUNT_POINT`（默认 `/mnt/usb`）/ `REPO_DEST` / `YUM_REPO_FILE` / `PKG_RPMS_DIR`。

### 4.5 usb-eject.sh（拆分后：入口 + usb-eject-lib.sh）

- **用途**：U 盘安全弹出（卸载该盘全部挂载点，可选断电弹出）。
- **调用形态**（L26-43）：

```
bash usb-eject.sh                  # 自动检测（单盘直卸；多盘交互选择），仅卸载
bash usb-eject.sh --poweroff       # 卸载后断电弹出（udisksctl power-off，失败回退 eject）
bash usb-eject.sh --disk sdb       # 直接指定 U 盘整盘名（非交互环境用）
```

- **退出码**（L13）：0=已卸载（含 DRY_RUN、断电失败但卸载成功）；1=用法错误/未检测到 USB 盘/非 USB 盘/卸载失败。
- **选盘**（main，L63-160）：只处理 `TYPE=disk` 且 `TRAN=usb` 的设备；系统盘一律拒绝（`sys_disk_list_all` 收集 / 链路全部整盘，解析失败 fail-closed——只允许 `--disk` 显式指定并跳过校验，L80-90）；单盘自动选中；多盘交互选择（序号或盘名，30 秒超时；非交互环境提示用 `--disk` 退出 1）；`--disk` 指定非 USB 盘/系统盘 → 拒绝退出。
- **卸载范围**（unmount_disk，usb-eject-lib.sh L176-242）：该盘及其全部子分区的所有挂载点（`disk_mps`，**先子分区后整盘**；含桌面自动挂载 `/run/media/...`）；`swap` 分区先提示"请先执行 swapoff /dev/xxx"（usb-eject-lib.sh L199-204）；单点失败不中断，统一汇总后返回 1；完成后重新读取校验（无剩余挂载点 + 无失败 + 无 swap）→ "U 盘 /dev/xxx 已卸载，可安全拔出"。
- **占用处理**：`umount` 失败（可能 target is busy）打印占用排查提示——`fuser -vm <挂载点>` / `lsof +f -- <挂载点>`，以及"可先执行 cd / 离开挂载点，或结束占用进程后重试"（usb-eject-lib.sh L168-171）。**脚本本身不主动切换目录**，仅提示。
- **断电弹出**（poweroff_disk，usb-eject-lib.sh L245-268）：`$POWEROFF_BIN power-off -b /dev/<盘>`（默认 `udisksctl`）；失败回退 `eject /dev/<盘>`（命令存在时）；均失败仅警告"断电失败，但已卸载，可安全拔出"仍返回 0（断电失败不改变退出码）。
- **日志** `MOUNT_LOG`：`run_log` 每步写 `[时间] cmd: ... 结果:$?`；日志不可写只告警、不阻止命令执行（usb-eject-lib.sh L6-21）。
- **测试接缝**（L17-21）：`DRY_RUN` / `SKIP_ROOT_CHECK` / `MOUNT_LOG` / `LSBLK_BIN` / `POWEROFF_BIN`。

## §5 端到端流程串讲

### 5.1 总体流程

从装机/挂盘到报告归档的一条龙：

```
U 盘挂载拿包（mount-iso.sh mount / usb-mount-guide.md 手动命令）
   → 拷贝 offline-stress-pkg 到服务器（保持目录结构）
   → install.sh（装 stress + dmidecode + nvme-cli，SHA256 锁定）
   → verify.sh（五项校验）
   → disk-mount.sh list（确认数据盘）→ oneclick all（内部：自动挂载 → COMBO → 每数据盘 hdd → 系统盘 → 等待 → 自动复盘 summary.txt → 自动清空本批数据盘（--no-cleanup 可关））
   → 运行中监控（oneclick.sh status / stress-test.sh status / tail -f monitor.csv）
   → 报告归档（docs/压测报告/<批次>-<日期>/，文件名含机型与机器唯一标识）
```

### 5.2 典型完整命令序列（可直接复制执行）

```bash
# ① 挂载 U 盘拿离线包（U 盘刚插入未挂载时；或按 usb-mount-guide.md 手动执行）
sudo bash mount-iso.sh mount        # 也可手动：sudo mkdir -p /mnt/usb && sudo mount /dev/sdb1 /mnt/usb

# ② 把整个 offline-stress-pkg 目录拷贝到服务器（保持目录结构不变），然后进入包目录
cd offline-stress-pkg

# ③ 安装 stress + dmidecode + nvme-cli（已是 root 可去掉 sudo）
sudo bash install.sh                # 已装同版本会提示"已安装"；SHA256 校验失败会拒绝安装

# ④ 验证安装
bash verify.sh                      # 全 PASS 退出 0；检查 D/E 缺失只 WARN（dmidecode 缺失不影响压测，DIMM 探测会回退 EDAC；nvme-cli 缺失只影响 check-nvme-health.sh）

# ⑤ 查看数据盘与挂载状态（确认哪些盘可压）
bash disk-mount.sh list

# ⑥ 一键全测：CPU+内存组合 + 每块数据盘独立任务 + 系统盘（复盘后自动清空本批数据盘，--no-cleanup 可关）
bash oneclick.sh all                # 或 bash oneclick.sh 菜单选 1；要清盘重建分区加 --rebuild（会清空数据盘）

# ⑦ 运行中监控（可另开会话）
bash oneclick.sh status             # 批次内各任务状态 + 底层 stress-test.sh status
tail -f /root/stress-test/<时间戳>-combo/monitor.csv   # 具体结果目录以 status/summary 为准

# ⑧ 复盘（oneclick all 已自动逐个复盘并生成批次 summary.txt；需要重跑时）
bash oneclick.sh review             # 对最近批次逐个复盘并生成汇总（退出码反映是否存在异常结论）
bash stress-test.sh review --dir /root/stress-test/<时间戳>-combo   # 单任务细看

# ⑨ 报告归档：写入 docs/压测报告/<批次标识>-<归档日期>/（每批次目录含 README.md 汇总 +
#    逐机分析报告 压测分析报告-<机型>-<机器标识>-<归档日期>.md，机型与机器标识在文件名中可直接辨认来源机器）
```

### 5.3 各阶段说明

- **阶段①（挂载/拿包）**：`mount-iso.sh mount` 会挂 U 盘、复制源目录到 `/opt/kylin-repo` 并配置本地 yum 源（`/etc/yum.repos.d/kylin-local.repo`）；也可以先用 `mount-iso.sh build` 从 U 盘 RPM 构建源再 mount。U 盘弹出用 `usb-eject.sh`（可选 `--poweroff`）。
- **阶段③④（安装验证）**：`install.sh` 三个 RPM 各自 SHA256 锁定校验、已装同版本跳过；`verify.sh` 五项检查中检查 D/E 缺失只 WARN（检查 D 回退 EDAC，见 §4.2）。
- **阶段⑤⑥（挂盘与一键编排）**：`oneclick all` 内部先 `disk-mount.sh mount --disks all --yes`（`MOUNT_RC` 记录跳过/失败盘，见 §3.4）；计划 `COMBO(--peer-disks 数据盘数+1) → HDDxx → SYSDISK`（见 §3.5）；有图形终端时每个任务独立窗口（标题固定，见 §3.6），无图形环境自动降级后台并行；COMBO 失败中止整批、单盘失败记 failed-tasks.txt 继续（见 §3.7）；批次结束自动清空本批数据盘（`--no-cleanup` 可关，结果写批次 summary.txt 与 `clean.log`，见 §3.3 步骤 12），手动随时可用 `bash disk-mount.sh clean` 一键清空（见 §4.3）。
- **阶段⑦（监控）**：每个任务实际是 `bash stress-test.sh start ...`（产物 run-config.txt / monitor.csv / status.txt / error.log 等见 §2.13）；等待期间主终端 Ctrl-C 只结束等待，压测继续（§3.8）。
- **阶段⑧（复盘）**：`run_review_all` 逐任务执行 `stress-test.sh review --dir`，结论落批次 `summary.txt`（含自动挂载异常标注与启动失败清单，见 §3.9）；结论非"正常"时 oneclick 退出码 1。
- **阶段⑨（归档）**：按 `docs/压测报告/README.md` 的归档规则——目录 `docs/压测报告/<批次标识>-<归档日期>/`，每批次一份 `README.md`（数据来源、汇总表、共性问题），逐机报告命名 `压测分析报告-<机型>-<机器标识>-<归档日期>.md`（如 `压测分析报告-7380-0003-20261116.md`），原始快照保留在 `tmp/<批次>/<机器>/` 供逐条复核（run-config.txt、monitor.csv、stress*.log、*.exitcode、error.log）。

### 5.4 关键产物流向（一次 oneclick all 的完整证据链）

```
批次目录 /root/stress-test/oneclick-<时间戳>/
  ├─ plan.txt / tasks.txt / commands.txt / commands.sh / env.txt / start.time / timeout.txt
  ├─ mount.log（自动挂载输出）
  ├─ cleanup-devices.txt（本批数据盘父整盘名，自动清理范围）
  ├─ clean.log / clean.mount.log（批次结束自动清理输出与挂载日志）
  ├─ failed-tasks.txt / aborted（异常时）
  └─ summary.txt（自动复盘汇总；含 MOUNT_RC 挂载异常标注）
        │  每任务对应一个结果目录
        ├─ /root/stress-test/<时间戳>-combo/   （run-config/devices/monitor.csv/status.txt/error.log/summary.txt...）
        ├─ /root/stress-test/<时间戳>-hdd/      （各 HDDxx 盘）
        └─ /root/stress-test/<时间戳>-hdd/      （SYSDISK 系统盘，--sysdisk-only）
              │  复盘结论与原始证据
              └─ docs/压测报告/<批次>-<日期>/README.md + 压测分析报告-<机型>-<机器标识>-<日期>.md
```
