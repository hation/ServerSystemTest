# 2026-11-18 体检报告「分析汇总」置顶章节 — 设计文档

## 背景与意图（Why）

现有体检报告是"标题 → 1 整机信息 → 2 健康状态 → 3 异常详情 → 4 修复建议 → 5 AI 综合分析 → 附录"的顺序，打开报告要先翻到第 2/3 章才知道整体好坏。用户希望**先汇总、后展开**：报告开头放一段"电梯摘要"，让读者一眼看清机器是谁、整体健康如何、核心结论是什么，需要细节再往下翻。

## 目标（Goals）

- 在报告标题之后新增置顶章节 `## 0. 分析汇总`，详情章节（1-5 + 附录）保持现状与编号不变
- 汇总章节包含**三个要点**（用户选定）：
  1. **整机概览**：机型 / 序列号 / 固件版本（BIOS·HDM·CPLD）一行式呈现
  2. **健康总览**：正常 X · 异常 Y · 提示 Z 计数
  3. **核心结论**：最重要的一条异常链路推断——**AI 优先 + 规则兜底**（用户选定）
- 现有行为不回退：30 个测试全绿，报告章节验收锚点（`## 1. 整机信息` 等）不变

## 非目标 / 反目标（Non-goals / Anti-goals）

- **不加入**用户未选的三项：异常/提示清单表格、修复动作速览、采集信息（后续要可再加）
- **不改动**详情章节内容与 AI 综合分析章节本身
- 核心结论规则兜底不做"智能推理"：只做确定性的一句话（由异常组件推导），复杂推理留给 AI

## 约束（Constraints）

- 纯 Python 3.12 标准库；代码位于 `sds-log-parser/`（主要改 `sds_report.py`，必要时 `sds_parser.py`）
- 中文输出；标题 `## 0. 分析汇总`
- 核心结论来源优先级：**AI 优先**（`--ai` 且调用成功时，取 AI 综合分析正文的首个要点句，截断 ≤120 字）→ **规则兜底**（未启用 `--ai` 或调用失败/无内容时，按异常组件生成确定性一句话）
- 无异常组件时核心结论输出"未发现异常组件"类文案，不报错
- 测试追加到 `tests/run_tests.py`（自研运行器，追加后整体运行）
- Git 约定（延续）：身份 env 注入 `ganxin01 <ganxin01@local>`、main 分支直提、提交只 add 涉及文件
- 密钥安全：不引入任何新密钥/落盘

## 方案设计（How，已定）

### 章节结构（渲染后）

```
# 服务器体检报告
- 机器标识：<机型>（序列号：<SN>）      ← 现有标题块，保持不动
- 采集时间：<时间>
## 0. 分析汇总
### 整机概览
- 产品型号: ... / 序列号: ... / 固件: BIOS=..., HDM=..., CPLD=...
### 健康总览
- 正常 50 · 异常 4 · 提示 1
### 核心结论
- <AI 优先或规则兜底的一句话>
## 1. 整机信息
...（原样）
```

**布局裁定（controller）**：现有标题块（机器标识 + 采集时间两行）**原样保留**作为报告头部元信息，`## 0. 分析汇总` 紧跟其后、`## 1.` 之前。整机概览要点聚焦标题块没有的**固件版本**信息（机型/SN 与标题块轻微重叠可接受）。

### 模块改动

**`sds_report.py`**：
- 新增 `render_summary(inv, health, ai_markdown=None) -> str`：返回 `## 0. 分析汇总` 章节 Markdown
- `render_report(...)` 签名不变，内部在标题块后、`## 1.` 之前插入 `render_summary` 输出
- 健康总览计数：`正常 X · 异常 Y · 提示 Z`；**未知 > 0 时**追加 `· 未知 W`（裁定：未知仅在有值时才展示，避免噪声）
- 核心结论规则兜底逻辑（新函数，如 `_rule_conclusion(health) -> str`）：取异常/提示组件，按类别优先级（硬盘 > PCIe > 电源 > 背板 > 内存 > CPU > 风扇 > 温度 > 其他）取第一个，生成如 `最可能问题集中在 硬盘（Disk_F23_Status）链路：盘丢失/Drive Fault。`；无异常/提示组件则输出 `未发现异常组件。`
- AI 优先：`ai_markdown` 非空时，取其首个非空段落/要点句，去 Markdown 标记、截断 ≤120 字，作为核心结论

**`sds_parser.py`**：
- 编排不变，`render_report` 调用处透传已算好的 `health` 与 `ai_markdown`（现状已具备）；健康总览计数在 `render_summary` 内部由 `health` 统计（正常/异常/提示/未知）

### 验收标准

- 用真实样例运行：报告含 `## 0. 分析汇总`，且含三要点——整机概览（H3C UniServer R4930 G5 H3 / SN / 固件版本）、健康总览（正常 50 · 异常 4 · 提示 1）、核心结论（不启用 --ai 时为规则一句话，含"Disk_F23_Status"或"硬盘"）
- 启用 `--ai` 且配置真实后端 → 核心结论为 AI 首要点句；未配置 → 规则兜底（AI 章节缺失不影响汇总章节）
- 无异常组件的最小数据 → 核心结论"未发现异常组件"，不崩溃
- 回归：现有 30 个测试全绿；`test_report_sections` 断言新增 `## 0. 分析汇总` 仍通过（需同步该测试断言）

## 设计决策记录（我的决定，可推翻）

- **汇总三要点**（用户选定）：整机概览 / 健康总览 / 核心结论
- **核心结论 AI 优先 + 规则兜底**（用户选定）：AI 成功取首要点句截断 120 字；否则规则一句话
- **类别优先级**（我拍板）：硬盘 > PCIe > 电源 > 背板 > 内存 > CPU > 风扇 > 温度 > 其他——与"最可能影响业务/最常见故障"的直觉一致
- **标题块保留**（构建者检查提出，我拍板）：现有 `# 服务器体检报告` + 机器标识 + 采集时间两行原样保留，`## 0.` 紧跟其后（满足"现有行为不回退"）
- **未知计数按需展示**（构建者检查提出，我拍板）：健康总览仅在未知 > 0 时追加 `· 未知 W`
- **规则结论不含证据全文**：只给组件名+类别+关键事件关键词，细节在详情章节
