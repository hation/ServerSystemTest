## 4. 参数合理性核查

### 4.1 CPU

| 机器 | 推导规则 | 计算结果 | 覆盖度 | 判定 |
|---|---|---|---|---|
| stress-test-3/4 | 逻辑线程 128 × 25/32（SMT 感知） | 100 worker | 64 物理核全部覆盖 + 36 个 SMT 兄弟核 | 合理 |
| stress-test-5 | 逻辑线程 96 × 25/32 | 75 worker | 48 物理核全部覆盖 + 27 个 SMT 兄弟核 | 合理 |

说明：25/32 = 78.1% 逻辑线程，是 SMT 开启时的常规饱和策略（既占满物理核，又避免同一物理核双线程抢占过度）。

### 4.2 内存

| 项目 | 数值 |
|---|---|
| 内存条 | 16 根 × 32 GiB = 512 GiB |
| 单 worker 推导 | 32G − max(6G, 32G/8) = **26G** |
| 内存目标 | 16 × 26G = **416 GiB**（占 MemTotal 502G 的 82.9%，符合 82% 设计约定） |
| 上限 1（模块） | 512 × 88% = 450G |
| 上限 2（MemTotal） | 502 × 92% = 462G |
| 上限 3（磁盘预留） | 不生效（peer-disks=0，无 hdd 流） |
| 分配上限（取最小） | **450G** |
| 需求 vs 上限 | 416G < 450G → **未超限** |
| 常驻 | `--vm-keep` 固定追加，内存常驻生效 |

判定：内存目标落在模块上限（88%）之内，且为 MemTotal 的 82.9%，既达到压测强度又保留约 86 GiB 安全余量，**分配合理、无超限**（此前 `--vm-bytes` 显式超限的问题在本批不存在）。

### 4.3 模式选择

- `--peer-disks 0`：combo 不再扫描 /mnt/HDD*，不启动 hdd 进程，**只测 CPU + 内存**，与需求一致；
- `--timeout 10h`：长稳设计，符合验收场景。
