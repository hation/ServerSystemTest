# 单实体专项分析 SOP 模板（使用时长 / 使用历史反推）

> 目的：当用户给出**某被测实体的唯一键**（示例：SN/资产号），要求"分析该实体用了多久 / 是否全新 / 找它的报告"时，按本 SOP 执行，保证口径统一、证据可追溯（被测实体示例：服务器/整机）。
> 状态：**当前有效**
> 变更记录：v1（2026-11-13）——源自《222-单盘硬盘分析SOP.md》去业务化改造（单盘 → 单实体），供服务器整机测试项目套用。

> 术语约定：被测实体（被测对象）、唯一键（示例：SN/资产号）、源数据（原始采集文件）、批次（batch）、计数器（固件累计计数器：主计数 = 寿命/通电类计数器，次级计数 = 上下电类计数器）。专词仅出现在「示例」语境。

---

## 0. 触发条件与总原则

**触发**：用户消息中出现某实体的唯一键（示例：SN/资产号），且意图为以下任一类——
1. "这个测过吗 / 报告是哪份" → 走 §1 定位；
2. "用了多久 / 是不是全新 / 状态如何" → 走 §1–§5 全流程并产出独立文档。

**总原则**：
- 只读源数据，不执行任何写操作（示例：源项目为不执行任何写盘命令）；
- 每个数字必须标注出处（文件/页/行，示例：日志页 0x0E / 0x15 / 0x03 / 0x08 / 文件 05）；
- **给区间和置信度，不给"精确值"**；
- 结论用"建议性结论"表述，不替代供应商/客户最终判定；
- 不改既有批量报告与汇总表，除非用户明确要求；
- **独立分析不横向对比**：只使用本实体源数据，不与其他实体/唯一键/批次做横向对比（不写对比表、不以他实体数值作为论据）。

## 1. 第一步：定位报告与原始数据

### 1.1 找报告（必做）

1. `Grep` 工作区唯一键（大小写不敏感），范围：`docs/`、`results/`、`logs/`、`test-data/`、`tmp/`、`scripts/extract/process_out/`；
2. 汇总表（Excel）需单独查（二进制不可 grep）：用 `openpyxl` 遍历**所有 sheet**（源项目为 4 个 sheet：总览 / 逐盘明细 / 批次汇总 / 异常清单【示例】）；
3. 未命中时：再查唯一键前缀近似（示例：SN 前 6–8 位），列出前缀相近的实体，供用户核对是否输错；
4. 明确回复"未测过"时，必须说明检索范围（报告数、汇总表行数、原始目录），不能只回一句"没有"。

### 1.2 找原始数据（必做）

从报告的头部"数据来源"行或汇总表「报告文件」列拿到批次号，再定位原始采集目录（二者都可能存在）：

```
results/<Batch>/collect/<EntityID>/
tmp/0test/<Batch>/collect/<EntityID>/
scripts/extract/process_out/<NN>-batch_data.json   ← 结构化字段（唯一键/主计数/次级计数/后台任务/纠错/...）
```

- 实体映射：报告中的编号 ↔ 目录 `<EntityID>`；
- 每实体应有 01~NN 个文件；**缺第二信源文件属正常**，但必须在报告中披露"无第二信源，置信度上限为中"。

### 1.3 读取顺序（主 → 辅）

| 优先级 | 文件 | 取什么 |
|---|---|---|
| 主 | 计数/状态页文件（示例 04） | 错误计数 / 关键状态页 / 出厂+上下电计数 / 后台任务 / 电源状态迁移 / 厂商主计数 |
| 辅 | 主计数文件（示例 01、02） | 主计数、读写量、纠错、状态；两次快照对比可发现计数器实时增长 |
| 辅 | 官方信息文件（示例 05） | 官方出厂日期、主计数、总读写、年均工作量、状态 |
| 辅 | 自检/健康文件（示例 03、06） | 自检历史是否为空、官方健康判定 |
| 可选 | 第二信源文件（示例 07） | 第二套独立计数器 |

> 采集时若后台任务正在跑，纠错、吞吐量等计数会实时增长（源项目实测 1 秒内纠错 +2,394【示例】）。以最后一次读数为准，并在文档中说明"快照间计数在变"。

## 2. 第二步：先判主计数是否可信（决定后续一切）

| 代号 | 判据（通用） | 数据来源 | 示例（源项目口径） |
|---|---|---|---|
| C1 | 关键状态页全部不可用/无数据（含状态页内时间字段） | 关键状态页 | Format 状态页（0x08）全 `<not available>`（含 Format 后通电时间） |
| C2 | 次级计数器 ≫ 主计数器（比值 > 3，且主计数 > 0） | 上下电计数页 | 加载卸载 / 启停 > 3（0x0E） |
| C3 | 后台任务计数远超主计数（> 主计数 × 50） | 后台任务页 | 后台扫描次数 > 通电时间 × 50（0x15） |
| C4 | 纠错计数与吞吐量比例异常（每 KB > 1 次） | 错误计数页 | ECC 纠正次数 / 读取 KB > 1（0x03） |

判定：
- **主计数不可信（完全/部分重置）** = C1 且（C2 或 C3 或 C4 命中）→ 本次分析的核心前提；
- **主计数可信** = 关键状态页可用、主/次级计数关系正常、后台任务 ≈ 0 → 可直接用主计数作为使用时长，无需反推（文档中给"直接读数 + 交叉验证"即可）；
- **证据矛盾** = C1 命中但 C2/C3/C4 全不命中 → 标注"无法区分出厂状态与重置，需人工复核"，不给时长结论。

补充两个高价值判据：
- **电源状态迁移全为 0**【示例：0x1A 电源状态迁移全 0】→ 次级计数更可能来自真实上下电而非空闲节电（支撑口径 B）；
- **自检日志为空 + 主计数极短**【示例：自检为空 + 通电时间极短】→ 生命周期数据被重置的旁证。

> 判据阈值（比值 3、×50、每 KB 1 次）为源项目经验值【示例】，新项目按《05-测试矩阵与分层模型》与《10-服务器整机测试专项规划》定值。

## 3. 第三步：多口径反推使用时长（核心方法）

> 全部计算写进文档附录 B，正文只放结果表。所有假设必须显式列出。

### 口径 A：后台任务计数（硬下限）

```
t_scan = bg × s
s = <单次后台任务耗时>（占位；源项目为 1 h 保守基线：1.2TB 盘单次全盘后台扫描 ≥1h【示例】）
场景：s = 2 / 4 / 6 h 给出上沿
```

- 含义：后台任务只在通电且相对空闲时执行 → 真实通电时间 **≥** 任务耗时总和；
- 这是最保守的下限，不含正常读写、待机与维护。

### 口径 B：次级计数（上下电折算，中位估计公式占位）

```
cycles = lu ÷ k        (k = 1 或 2，表示每次上下电产生几次次级计数)
t_power = cycles × h   (h = 2 / 4 / 8 / 12 小时，每次通电时长)
中位估计 = (lu ÷ 1.5) × 8h
```

- 前提校验：电源状态迁移为 0（否则次级计数可能含空闲节电，需下调权重）；
- 交叉校验：`cycles ÷ 出厂至今天数` 应落在 0.3–3 次/天；若 >5 次/天，说明假设不成立，需在文档中注明；
- **7×24 常开**的实体次级计数应很低；次级计数高说明该实体是"工位/测试台/间歇上下电"使用，因此"每次通电数小时"假设合理。

> 折算系数 k、每次时长 h 与中位公式为新项目占位，需按被测实体行为模式在 05/10 号文档定值（源项目：k = 1 或 2、中位 = (lu÷1.5)×8h）。

### 口径 C：出厂时间上限与任务频率

```
T_max = 检测日 − 出厂周首日（ISO 周）
任务频率 = bg ÷ 出厂至今天数
```

- T_max 是**绝对上限**，任何估计不得超过；
- 任务频率若明显高于默认（占位：源项目 7 天/次），说明该实体通电覆盖率很高（长期在使用），可作为"不是短期用过就闲置"的旁证。

### 口径 D：第二信源（仅当存在）

- 取第二信源的主计数、上下电次数、次级计数；
- 第二信源主计数与厂商主计数差值 > 阈值（占位：源项目 > 100 h）→ 置信度可提升为"高"；
- 无第二信源 → 置信度上限"中"，必须披露。

### 综合口径（固定写法）

| 输出项 | 取值规则 |
|---|---|
| 等效时长（最可能） | 口径 B 中位估计，取整（占位：源项目取整到千小时） |
| 等效时长（区间） | 下限 = max(口径 A 保守值, 口径 B 最低场景)；上限 = min(T_max, 口径 B 最高场景) |
| 自然时间跨度 | ≤ T_max |
| 使用强度 | 由 cycles/天 推断：≈1 次/天 = 间歇使用；≪1 次/天 = 常开；≫2 次/天 = 高频使用 |
| 置信度 | 有第二信源交叉=高；仅主源多条矛盾=中；仅 C1=低 |

**表述模板**（占位字段按新项目定值）：
> 显示主计数 {x} 不可信（{重置原因}）。按固件未清计数器反推：等效时长约 {下限}–{上限} 小时（约 {a}–{b} 年），最可能 {中位}（约 {c} 年）；自然时间跨度 ≤ {T_max} 年。该实体为已使用过的实体，非全新。

## 4. 第四步：产出独立文档（固定结构）

- 命名与存放：`single-analysis/NN-单实体使用时长分析-<EntityID>-YYYYMMDD.md`（示例：`docs/single-analysis/` 子目录），`NN` = 现有最大编号 +1（不足三位不补零，沿用现有习惯）；**单实体类文档统一放 `single-analysis/` 子目录，不要放根目录**；
- 若用户只要"报告在哪份"，不新建文档，直接给 §1 的定位表格；
- 固定章节（缺一不可）：

```
0. 一句话结论（含区间、最可能值、上限、置信度）
1. 数据来源与采集时点（文件 + 时间戳 + 缺口说明）
2. 与使用时长相关的原始数据（字段 | 数值 | 出处 | 解读）
3. 为什么不能直接采信主计数（矛盾表：C1–C4 + 电源状态迁移 + 自检为空）
4. 使用时长反推（口径 A / B / C，各含假设与结果表；有第二信源加 D）
5. 综合判断（表格：最可能 / 区间 / 自然跨度 / 使用强度 / 寿命消耗 / 健康 / 置信度）
6. 不确定性与边界（主动披露）
7. 建议（补采第二信源、核对标签/保修、复测标定、归档）
附录 A：关键原始输出摘录（按文件分块）
附录 B：计算口径（可直接复算的公式与数字）
```

- 文档中所有相对链接指向项目内兄弟文档，原始文件用相对路径（示例：`results/...`、`tmp/0test/...`）；
- **只分析本实体**：报告内不出现与其他实体/唯一键/批次的横向对比（含对比表、他实体数值引用）；项目阈值可引用，但论述只用本实体数据；
- 关联批量报告与汇总表时给出可点击链接。

## 6. 禁止事项（易犯错误）

1. **不得**把主计数当作真实使用时长（被重置的尤其）；
2. **不得**用被重置的吞吐量/读写字节数去换算纠错比例并据此定量（只能作异常提示）；
3. **不得**给出精确到小时/天的"真实使用时长"，只能给区间与最可能值；
4. **不得**把"后台任务 1 次"直接等同于"1 次全量任务"，需说明语义不确定性；
5. **不得**在未查汇总表的情况下回复"未测过"；
6. **不得**为单实体分析新建批量报告编号或覆盖原批量报告；
7. **不得**在单实体报告中与其他实体/唯一键做横向对比（含"与 XX 对比"表格、以他实体数值作为结论论据）。
