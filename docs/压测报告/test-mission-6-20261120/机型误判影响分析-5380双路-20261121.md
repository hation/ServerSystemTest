## 1. 受影响的机器

12 台中共 **6 台**（stress-test-7 ~ 12）被误判。其余 6 台（stress-test-1 ~ 6）机型判定正确。

| 机器 | 实际机型 | 逻辑线程 | 标注机型 | CPU worker | 判定 |
|---|---|---|---|---|---|
| stress-test-1 ~ 6 | 7380 | 128 | 7380 | 90 | ✓ 正确 |
| **stress-test-7** | 5380 双路 | 64 | 7380（误判） | 45 | 标注错误 |
| **stress-test-8** | 5380 双路 | 64 | 7380（误判） | 45 | 标注错误 |
| **stress-test-9** | 5380 双路 | 64 | 7380（误判） | 45 | 标注错误 |
| **stress-test-10** | 5380 双路 | 64 | 7380（误判） | 45 | 标注错误 |
| **stress-test-11** | 5380 双路 | 64 | 7380（误判） | 45 | 标注错误 |
| **stress-test-12** | 5380 双路 | 64 | 7380（误判） | 45 | 标注错误 |

**误判原因**：这些机器为 **5380 双路（32 物理核 × SMT2 = 64 逻辑线程）+ 16×64G = 994G 内存**。修复前的 `auto` 判定规则 `mem>=800G → 7380` 按内存判型，把大内存的 5380 判成了 7380（标称 128 线程），触发 `check_model_threads` 的"实测 64 vs 标称 128，偏差 50%"误报警。

## 2. 对参数分配的影响：无

机型**只用于 run-config 标注与交叉校验，不参与任何参数推导**（见 [stress-lib-commands.sh L104](file:///c:/Users/ganxin01/Documents/trae-work/ServerSystemTest/offline-stress-pkg/stress-lib-commands.sh#L104) 附近：CPU worker 由 `cpu_workers_auto` 按实测逻辑线程推导，函数体内不引用 $model）。

以 stress-test-10 为例（与误判机群一致）：

| 项 | 推导值 | 正确性 |
|---|---|---|
| CPU worker | 45 = round(64 × 70%) | ✓ full 规则对 5380 双路（64 线程）正确 |
| VM | 16 = DIMM 根数 | ✓ |
| vm-bytes | 56G = 64G − max(64/8, 6G) | ✓ |
| 内存目标 | 16 × 56G = 896G | ✓ |
| 上限 | min(16×64×88%=901, 915, 磁盘后) = 901G | ✓ 未超限 |

## 3. 对压测效果的影响：无

误判机群监控实测（stress-test-7 / stress-test-10）：

| 机器 | CPU% | 内存已用 | swap | 判定 |
|---|---|---|---|---|
| stress-test-7 | 98.8–98.9% | ~960 GiB | 0 | 负载达成 |
| stress-test-10 | 99.6–99.9% | ~976 GiB | 0 | 负载达成 |

CPU 45 worker 已把 64 线程压到满载（98.8%+），内存 896G 目标达成（含页缓存），swap 0。**压力效果与机型标注无关**，全部正常。

## 4. 修复与后续

- 修复已落地（本次会话，SDD 流程通过）：`auto` 判定改为**逻辑线程优先**（n≥120→7380、n≥90→7360、n≥64→5380），内存仅作 n=0 兜底。**下一次启动不会再误判**。
- 本批 6 台误判机**无需重跑**：参数与压测效果均正确，仅 run-config 里"机型"一列标注不实，复核时以实测逻辑线程为准。
