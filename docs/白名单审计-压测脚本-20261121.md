## 2. 每处详细说明

### A. 型号识别 / 标称映射（与"型号智能识别改造"直接相关，建议优化）

**#1 stress-lib-common.sh:133 `nominal_threads()`**
- 作用：型号→标称逻辑线程数映射，供报告标注与 `check_model_threads()` 交叉校验。
- 当前取值：仅 5380→64、7360→96、7380→128，其余返回空。
- 不扩展会怎样：AMD EPYC 7763（128 线程）识别成功但标称查不到 → 跳过校验，机型标注仍不可读；换品牌场景只能靠实测线程修正，无法核对标称。
- 建议：改为按品牌+型号的可扩展映射表（如 `EPYC-7763`→128、`Xeon-6338`→64），未知返回空；这正是计划 Task 1 的目标。

**#2 stress-lib-common.sh:128 `detect_cpu_model()`**
- 作用：从 lscpu/cpuinfo 提取 CPU 型号数字。
- 当前取值：正则 `s/.*[Cc]86-3[Gg][[:space:]]+([0-9]+).*/\1/p`，只认海光 C86-3G 前缀。
- 不扩展会怎样：AMD/Intel 机器返回空 → 回退线程分界，AMD 128 线程被标成 7380（机型误标）。
- 建议：按品牌分支提取（C86-3G / EPYC / Xeon），输出统一可读格式（计划 Task 1 已给示例）。

**#3 stress-lib-common.sh:94、149-151 关联文案**
- 作用：SMT 关闭时 worker 减半的注释与"疑似单路 CPU"提示，均以 5380/7360/7380 举例。
- 属于随映射表走的文案，不影响逻辑；改表时应同步，风险低。

**#4 stress-lib-commands.sh:94-96 实测线程→机型修正**
- 作用：auto 识别结果与实测线程偏差 >10% 时，按线程数把机型修正到 7380/7360/5380。
- 当前取值：≥120→7380、≥90→7360、≥64→5380（隐含"仅这三个档"）。
- 不扩展会怎样：AMD EPYC 7763（128 线程）即便识别为 EPYC 也会被"修正"成 7380，把多品牌识别结果覆盖掉——**这是多品牌改造的最关键冲突点**。
- 建议：修正逻辑只在"识别出的型号标称未知或与实测矛盾"时按实测线程分界回填；识别成功且标称匹配时不再改写（计划 Task 2）。

**#5 stress-lib-commands.sh:110-116 识别失败回退**
- 作用：auto 且 detect_cpu_model 返回空时的兜底机型判定。
- 当前取值：线程 ≥120→7380、≥90→7360、≥64→5380；线程不可用按内存 ≥800G→7380、≥450G→7360、否则 5380。
- 不扩展会怎样：AMD/Intel 机器全部落进这个"海光三档"猜测，机型标注必错（虽然参数不受影响）。
- 建议：回退路径只用于"无品牌信息"时；有品牌信息但型号未知时标注"未知型号（品牌 XX）"而不是猜 7380（计划 Task 3 有对应用例）。

**#6 stress-lib-commands.sh:122-124 机型白名单校验**
- 作用：校验 `--model` 取值（含 auto 识别结果）必须是四位数字。
- 当前取值：`case "$model" in [0-9][0-9][0-9][0-9]) ;; *) ... exit 1`，错误文案列出 `5380|7380|7360`。
- 不扩展会怎样：多品牌识别输出 `EPYC-7763` / `Xeon-6338` 时直接 exit 1，整个压测启动失败。
- 建议：白名单放宽为"品牌-型号"格式或非空校验（计划 Task 2），错误文案同步多品牌。

### B. 参数默认值 / 设计常量（多数不必动，列全以便对照）

- 作用：结果根目录、监控间隔、CPU/内存各百分比上限、磁盘预留系数。
- 均为设计常量且已用 `${VAR:-默认}` 暴露为环境变量，换机器可调；**合理设计常量，不必动**。
- 唯一提醒：`CPU_MAX_PCT=78` 只在"物理核识别失败"兜底路径生效，多品牌下仍按 nproc 实测，不属白名单问题。

- 作用：hdd/combo 未传 `--hdd-bytes` 时的默认写入量；cap_disk 公式与空间预检都依赖它。
- 设计常量（CLI 可覆盖）；文档示例（README:145、operation-manual:419）按 10G 推算，属配套示例，不必动。

**#9 stress-lib-common.sh:108、115 CPU worker 公式**
- 108：`w=$(( (logical * 25 + 16) / 32 ))`（×25/32，全机型统一口径）。
- 115：物理核识别失败 `w=$(( (n * CPU_MAX_PCT + 50) / 100 ))`。
- 均为设计常量（"按实测推导，不按机型查表"的核心），多品牌改造明确不动（计划约束）。

**#10 stress-lib-commands.sh:350-353 单 worker 公式**
- `per_g = uniform_g − max(uniform_g/8, 6G)`（32G→26G、64G→56G、128G→112G）。
- 设计常量，与品牌无关；oneclick full 朋友规则（oneclick.sh:102）复用同一公式，不必动。

**#11 stress-lib-commands.sh:281-288 探测失败示例命令**
- 内存根数探测失败时，固定按 16 个 worker 出建议命令（`mem_plan "$sg_total_mb" 16`），示例值 `--vm-bytes 26G`。

## 3. 结论

### 建议优化（按优先级）

1. **高优先（多品牌改造核心，计划已覆盖）**：
   - `detect_cpu_model()` 多品牌分支（stress-lib-common.sh:128）
   - `nominal_threads()` 品牌+型号映射表（stress-lib-common.sh:133）
   - 线程修正逻辑只在标称未知/矛盾时回填，不再无条件覆盖识别结果（stress-lib-commands.sh:94-96）
   - 识别失败回退标注"未知型号"而非猜 7380（stress-lib-commands.sh:110-116）
   - 机型白名单放宽为品牌-型号格式（stress-lib-commands.sh:122-124）
   - 同步 operation-manual.md / README.md 机型描述（#36-#37）

2. **中优先（可选，非本次改造范围）**：
   - 系统盘目录 `/stresstest-hdd` 环境变量化（stress-test.sh:218）
   - `/mnt/HDD*` 三处命名约定（stress-test.sh:179、oneclick-lib-run.sh:116-124、disk-mount-lib-plan.sh）统一为可配置前缀（若未来换挂载命名）
   - install.sh RPM_LIST 的 SHA256 维护提示（换 rpm 时需人工更新，风险中）

3. **低优先（可保持）**：
   - 探测失败示例固定 16 worker（stress-lib-commands.sh:281）
   - DMESG 关键字清单提取为可配置变量（stress-test.sh:40-42）
   - verify.sh 固定版本串（换 rpm 时随 install.sh 一起改）

### 合理设计常量（不必动，明确排除）

- 全部 CPU/内存推导公式与百分比上限（×25/32、×78%、×88%/92%/82%、1.2 倍缓存预留、max(6G,容量/8)）——"按实测推导、不查机型"是既定口径，多品牌改造计划明确不动；
- 类型/模式枚举（cpu|mem|hdd|combo、all|full|sysdisk|cpu|mem|hdd、label 白名单）；
- 监控/快照节奏（30s 轮询、60s/600s 快照）；
- 设备前缀枚举（sd/nvme/vd/mmcblk，已覆盖主流总线）；
- USB 判据（TRAN=usb）、shebang 判定（bash|sh|dash）；
- 各环境变量默认值（均已提供 `${VAR:-默认}` 覆盖入口，换机器可调）。
