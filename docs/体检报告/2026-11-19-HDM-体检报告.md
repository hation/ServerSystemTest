## 结论速览

当前机器整体健康度尚可，CPU、内存、风扇、背板、RAID/HDD_BP3 等主要项多数正常。  
异常集中在三个维度：

1. **双 PSU 供电输入异常**（PSU1、PSU2 同时报过 `Power Supply input lost (AC/DC)`）
2. **Disk_F23 间歇性掉盘/硬盘故障**
3. **PCIe Slot3 HBA 无法获取模块信息**

另有 HDM 网络配置错误、登录失败、机箱侵入事件，属于管理/维护层面的伴生问题。

---

## ① 异常链路推断

### 主链路：供电输入异常 → 服务器反复 AC Lost / 冷重启

事件时间线中多次出现：

- `System Restart---AC lost`
- `Health: Management controller off-line---HDM cold reboot`
- `PSU1_Status / PSU2_Status: Power Supply input lost (AC/DC)`

并且 PSU1、PSU2 是**同时**丢失输入，而不是单电源故障。  
这说明问题更可能出在：

- 外部市电/PDU/供电回路异常
- 两路电源线同时松动或接入同一故障 PDU
- 维护过程中人为断开外部供电后未规范恢复
- 电源模块硬件故障（概率相对较低，因为两个 PSU 同时坏的概率不大）

> 注意：组件健康清单里 PSU 只列出了 `Presence detected`，但时间线中的 `Power Supply input lost (AC/DC)` 是 PSU 状态异常的真正来源。电源恢复后 PSU 会重新上报 Presence，但 SEL 中的 Major 事件仍会使状态保持异常。

---

### 存储链路：F23 间歇掉盘 + Slot3 HBA 未识别

关键事件：

- `Disk_F23_Status: The disk is missing`
- `Disk_F23_Status: Drive Fault`
- 后续又有 `Drive Presence`，说明 F23 是**间歇性掉盘**，不是完全永久离线。
- `PCIe_Card3_HBA: Device Disabled: PCIe module information not obtained---Slot: 3`
  在多次重启后反复出现，说明 Slot3 的 HBA 卡没有被正常识别。

可能的链路关系：

```text
机箱开盖/维护操作
        │
        ├── PCIe Slot3 HBA 未识别/故障/未插好
        │        │
        │        └── 如果 F23 由该 HBA 管控
        │                 └── F23 掉盘 / Drive Fault
        │
        ├── F23 硬盘本身故障 / 槽位接触不良 / 背板链路问题
        │
        └── HDD_BP3 背板整体状态正常，但不能排除单个槽位或线缆问题
```

另外，`HDD_BP3_Status` 和 `Riser1` 均正常，所以背板整体和 Riser 整体大概率没问题，但**单个硬盘槽位/连接器/HBA卡**仍可能异常。

### 独立配置/维护问题

- `eth1 Default Gateway Set: 255.255.255.0 Fail, Not Vaild`  
  说明 HDM 网络配置错误，把 `255.255.255.0` 当成了默认网关，实际它应该是子网掩码。
- `HTTPS login failed from IP: 192.168.1.10 user: admin`  
  存在一次 HDM 登录失败，可能是密码/账户策略问题。
- 多次 `General Chassis Intrusion`  
  说明机箱被打开过，大概率是维护操作，也可能是盖板未复位或入侵传感器误报。

整体来看，**电源问题、F23 硬盘问题、Slot3 HBA 问题可能并存，不一定全部是同一个根因**。

| 5 | BIOS/HDM 配置或维护类问题 | HDM 网关配置错误、登录失败、机箱侵入事件；不是硬件故障，但需整改 | 中低 |

## ③ 可执行的排查步骤

### 第 1 步：优先处理电源问题，避免反复掉电导致 RAID/磁盘二次故障

1. **检查外部供电链路**：
   - 确认 PSU1、PSU2 所接 PDU/插座是否有电。
   - 测量输入电压是否在额定范围内（通常 200–240V AC）。
   - 确认两路电源是否来自不同供电回路，避免两个 PSU 接在同一 PDU/同一空开下。

2. **检查电源线/电源模块**：
   - 确认电源线无破损、无松动。
   - 重新插紧 PSU1、PSU2 电源线。
   - 如果条件允许，将两个 PSU 互换槽位，观察故障是否跟随电源模块移动。

3. **在 HDM 中查看电源状态**：
   - 登录 HDM Web：查看电源健康状态、输入电压、输出功率。
   - 导出 SEL/事件日志，确认最近是否还有 `Power Supply input lost (AC/DC)`。

4. **如果外部供电稳定后，清除历史告警**：
   - 在 HDM 事件日志中清除/确认告警，再次查看 PSU1、PSU2 状态是否恢复为“正常”。

---

### 第 2 步：处理 Disk_F23 硬盘掉盘问题

1. **确认当前磁盘状态**：
   - 登录 HDM，查看 `Disk_F23_Status`。
   - 进入 RAID/HBA 管理界面，查看 F23 对应的物理盘状态：
     - 是否被识别？
     - 是 `Unconfigured Good`、`Failed` 还是 `Offline`？
   - 确认 F23 属于哪个逻辑盘/RAID 组，检查阵列是否 `Degraded`。

2. **物理重新拔插 F23**：
   - 在安全断电或热插拔允许的情况下，拔出 F23。
   - 检查硬盘金手指、背板槽位、连接线。
   - 重新插到底，确保盘位卡扣到位。

3. **交叉验证**：
   - 如果 F23 仍无法识别，可将 F23 换到其他空闲盘位测试。
   - 或用一块同型号好盘替换到 F23 槽位测试。
   - 如果“故障跟随硬盘走”，则硬盘本身故障概率大，更换硬盘。
   - 如果“故障跟随槽位走”，则检查背板/线缆/HBA 链路。

4. **注意**：
   - 阵列如果已降级，不要同时拔出多块盘。
   - 若更换硬盘，等待 RAID 重建完成后再观察稳定性。

---

### 第 3 步：处理 PCIe Slot3 HBA 未识别问题

1. **在 BIOS/HDM 中确认 Slot3 设备枚举**：
   - 重启进入 BIOS Setup。
   - 查看 PCIe 设备列表，确认 Slot3 是否识别到 HBA。
   - 检查 Slot3 / PCIe 端口是否被禁用：
     - 如果被禁用，改为 Enabled。
     - 保存重启。

2. **物理重插/更换槽位验证**：
   - 关机断电。
   - 取下 Slot3 HBA 卡，清洁金手指。
   - 重新安装到 Slot3；如果有其他可用 PCIe 槽位，可换槽测试。
   - 同时确认 Riser 卡连接正常。

3. **固件/驱动层面**：
   - 升级 HBA 固件。
   - 升级 BIOS/HDM 固件，当前 BIOS 版本为 `5.97 V500R001B01D097`、HDM 版本为 `3.66 HDM V100R001B05D110`，可咨询 H3C 是否有更新版本。

4. **关联验证**：
   - 如果 Slot3 HBA 恢复正常后，F23 也随之恢复，则说明 F23 掉盘可能是 HBA 链路导致。
   - 如果 Slot3 HBA 恢复正常但 F23 仍报错，则 F23 是独立故障，继续按第 2 步处理。

---

### 第 4 步：处理机箱/HDM 配置问题

1. **机箱侵入告警**：
   - 确认机箱盖板已正确合上。
   - 检查机箱侵入开关/线缆。
   - 如果只是维护开盖导致，可在 HDM 中清除该事件。

2. **HDM 网络配置错误**：
   - 登录 HDM Web。
   - 检查 `eth1` 的 IP、子网掩码、默认网关。
   - 当前事件显示 `Default Gateway Set: 255.255.255.0` 无效，说明网关配错。
   - 将默认网关改为真实网关地址，例如 `192.168.1.1`，不要填写 `255.255.255.0`。

3. **HDM 登录失败**：
   - 检查 admin 账户是否被锁定。
   - 检查密码策略。
   - 如有必要，重置 admin 密码并重新测试登录。

---

### 第 5 步：最终验证

完成上述排查后，建议执行一轮完整验证：

1. 重启服务器，等待系统完全启动。
2. 登录 HDM，确认：
   - `PSU1_Status`、`PSU2_Status` 恢复正常。
   - `Disk_F23_Status` 恢复为“正常/OK”。
   - `PCIe_Card3_HBA` 不再报 `Device Disabled`。
   - `HDD_BP3_Status`、`Riser1` 仍正常。
3. 导出 SEL，确认没有新增 `Major` 级别事件。
4. 观察 1–2 天，确认 F23 不再“掉盘”、电源不再“AC lost”。

如果以上步骤仍不能解决，建议联系 H3C 技术支持，并提供：

- 机器序列号：`210235A566526AN0000P`
- HDM/SEL 完整日志
- 当前 RAID/HBA 配置截图
- 上述排查结果与现象时间点
