## 本批共性问题

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| P1 | 内存达成度普遍偏低：14 台峰值集中在 73.9%–79.9% 之间，仅 1 台 ≥80% | 内存项几乎全部判“未达标”，状态以 `OK_LIMITED` 为主 | stress 1.0.4 vm worker 分配后立即释放，非保持型；改用保持型分配，或把达成度口径改为“MemAvailable 相对下降幅度” |
| P2 | 内存口径含 page cache（脚本取 `MemTotal − MemFree`） | 峰值混合了 stress 占用与写盘缓存，不能等同于单任务占用 | 单独采集 stress 进程 RSS 合计 |
| P3 | 磁盘写吞吐为整机 `/proc/diskstats` 汇总（含分区与 dm） | 同类机型单盘机实测 96–194 MB/s 差异较大，但无法归因到具体盘 | 增加按物理设备的写入统计 |
| P4 | 覆盖无法逐盘对应（run-config 不记 `--dirs`，日志按循环序号命名） | 15 台覆盖均只能记“不可判定” | 日志按挂载点命名并在 run-config 记录目标目录 |
| P5 | 本批产物无 `status.txt`、无 dmesg 快照 | OOM/内核事件缺少直接证据（L4） | 升级脚本后重新采集 |

## 单机要点

- `0010`：本批唯一内存达成度 ≥80% 的机器（709.7 GiB，82.1%），状态 `OK`。
- `000N`（690.0 GiB，79.9%，距门槛 1.2 GiB）、`000R`（687.8 GiB，79.6%，距门槛 3.4 GiB）：均为未达 80% 门槛的 `OK_LIMITED`，其中 `000N` 属临界情形。
- `0014` / `0015`：唯一两台双数据盘机器（2×3.5T），整机写吞吐 307.2 / 310.5 MB/s，明显高于单盘机（96–194 MB/s）；但该值为整机汇总（含两块数据盘与系统盘任务），不能折算单盘，也不能据此认定两块盘均已被覆盖。
- `000R`：任务编排顺序与其它机器不同（系统盘先起、数据盘 hdd 晚 156s），形式被拆成两个会话但实际重叠 10.0 小时，不改变判定。
- `stress-test-1`：系统时间为 2024-04-04，与其它机器相差约 955 天（约 2.6 年）；批内时间自洽，仅绝对时刻不可判定。
