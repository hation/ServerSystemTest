# server-test-kit —— 服务器整机测试通用方案包

> "把硬盘与内存两个项目的经验，打包成服务器整机测试的通用方案"
>
> 本包把 **disk-tests（硬盘测试）** 与 **memory-tests（DDR5 内存测试）** 两个项目沉淀的工程经验与文档体系，**去业务化**为可复用的通用模板与落地规划，供「服务器整机测试」（server-tests）新项目套用。被测对象 = 服务器整机，覆盖 7 类部件：**CPU / 内存 / 磁盘 / 网络 / 电源 / 散热 / 整机稳定性**。

## 新项目启动 10 步

1. **读 01**，答完 10 问 checklist（唯一键/防呆边界/分级/判定写死/报告对象/历史库/破坏性确认/断点/并发/平台）——答不完不开工。
2. **读 10**，定判据定值表（§4 占位表）：测试项/判据/阈值/来源，阈值一律【示例，按客户定值】，来源写清（客户规格/订单/行业标准）。
3. **抄骨架 templates/** → 新建 `server-tests` 项目（bin/conf/tests/scripts/src/docs/results 目录壳）。
4. **第一天建 tests/**（自动化测试框架，优先级高于任何单个功能——disk-tests 最痛的教训）。
5. **VERSION + build.ps1**（版本单一来源 + 单源构建出离线包，杜绝双目录漂移）。
6. **写 01-测试方案**（用 docs-template/01-测试方案.md 套用，替换占位符）。
7. **真机冒烟前置**（硬件类项目第 0 阶段就安排真机，不闭门开发；用 docs-template/XX-部署清单 §7 冒烟）。
8. **按 03 定 AI 提示词**（数据说明 + 判据数值替换为实际值）。
9. **superpowers 流程开工**：brainstorming → specs → plans → subagent 执行（07 号工作流规则；执行方式已固定为 subagent-driven development，不再询问）。
10. **维护触发词表（09）**：新功能上线时把触发词补进映射表，交付记录同步注明"已登记触发词"。

## 隔离说明

本包**与 disk-tests / memory-tests 完全隔离**：
- 不含两项目任何私有数据（批次清单、识别结果、测试报告、BMC 地址与凭据、历史库）。
- 工具名为「标准工具选型示例」、判据数值为【示例，按客户定值】——套用前必须替换为 server-tests 项目的实际值。
- 两项目私有实现细节参见各自仓库原文，本包只保留可复用的骨架与原则。
