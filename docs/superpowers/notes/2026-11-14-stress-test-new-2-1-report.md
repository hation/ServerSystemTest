## 7. 发现的问题（按影响排序）

1. **内存峰值低于设计值**
   固定按 16 × 54G = 864G 配置，与机型无关；实测峰值 708G（81.9%，已过 80% 门槛，但未到 90% 的设计值）。原因是 `stress --vm` 的 malloc/write/free 周期不同步，16 个 worker 峰值没有叠加。对 754Gi 机型则会直接打满 swap（此前已在其他批次观察到）。

2. **指标口径是整机汇总，无法归属到单盘**
   `monitor.csv` 把所有块设备（整盘、分区、dm、loop）的扇区数累加。写系统盘时同一份 IO 会被 `dm-0 + sda3 + sda` 计 3 次；同时无法回答"HDD01 的顺序写速度是多少"。

3. **盘与日志无法对应**
   `run-config.txt` 不记录 `--dirs`；日志名 `stress-HDD01.log` 中的 `01` 是循环序号。事后无法证明某个任务压的是哪块盘。

4. **显式 `--dirs` 不校验挂载**
   `--dirs` 分支只检查目录是否存在，不检查是否为独立挂载点。若目标盘未挂载，压测会静默写入根分区（此前在其他容器已观察到根分区 +16Gi 的现象）。

5. **`stress --hdd` 是缓冲写**
   1TB 内存的机器上，10G 文件可能部分停留在 page cache。本批写 0 窗口仅 0.3%，说明大部分确实落盘，但 126 MB/s 的均值不足以代表 NVMe 真实顺序写能力。

6. **草稿批次与正式批次混放**
   6 个短跑目录与正式批次同级，容易被 `review` 抓取并误判为异常。

## 8. 建议

| 优先级 | 建议 |
|---|---|
| 高 | 内存参数改为按机型计算（如 `min(90% 物理内存, 目标值)`），或改用 `stress-ng --vm-keep` 保持占用 |
| 高 | `monitor` 增加按设备统计列（至少区分被测盘与系统盘），避免跨设备累加与重复计数 |
| 高 | `run-config.txt` 增加 `压测目录` 字段；日志按挂载点命名（`stress-HDD03.log`） |
| 中 | 显式 `--dirs` 增加 `findmnt` 校验，目录未挂载直接报错退出 |
| 中 | 磁盘测试改用 O_DIRECT（fio `--direct=1` 或 `dd oflag=direct`），获得真实顺序写带宽 |
| 中 | 用 `systemd-run --scope` 启动，避免会话断开影响长稳任务 |
| 低 | 归档 6 个草稿批次（移入 `draft/` 或加 `INCOMPLETE` 标记） |

## 9. 方法与口径声明

- 判定遵循 v3 规则：先过 B（结束证据）、C（模式口径）、D（覆盖）、E（负载达成），再谈指标；
- 快照边界按 R-01 处理：末行早于计划结束时先记 `UNKNOWN`，确认抓取时刻后才可定级；
- 指标均为服务器本地时间与整机口径；
- 本报告未包含 SMART、内核日志、文件系统校验等现场信息，如需"设备健康"结论，应补充 `smartctl -a`、`dmesg -T`、`journalctl -k`。
