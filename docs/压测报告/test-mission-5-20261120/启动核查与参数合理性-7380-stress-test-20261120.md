## 1. 结论摘要

1. **启动全部成功**：combo + 7 个 hdd（HDD01~06 + SYSDISK）共 8 个任务 `startrc` 全为 0，`stress.log` 均有 dispatch 行，`monitor.csv` 在采样，`error.log` 全部为空。
2. **覆盖 1:1 正确**：6 块数据盘（nvme0n1~nvme5n1，7T 各一块）各 1 个 hdd 任务 + 1 个系统盘任务 = 7 任务，与已挂载盘数一致。
3. **参数配置存在两个偏低问题**：
   - **CPU 仅 45 worker（显式 --cpu 45）**：7380 有 128 逻辑线程，自动推导应为 100（128×25/32）；45 只覆盖 35% 线程，实测 CPU 使用率约 **50%**，**未达到组合负载 CPU ≥90% 的达标判据**；
   - **内存目标 288G（显式 --vm 12 --vm-bytes 24G）**：实际 16 根 64 GiB（可推导 16×56G=896G，约 80% MemTotal），288G 仅为 MemTotal 1121G 的 **25.7%**，内存压力明显不足；且 `--vm 12` 与实际 16 根 DIMM 不一致。
4. **运行本身健康**：内存 288G 未超上限（1028G），`--vm-keep` 生效，swap 0，无 OOM，无错误。

## 3. 参数核查（重点）

### 3.1 CPU —— 配置偏低

| 项目 | 实际 | 建议/推导 | 判定 |
|---|---|---|---|
| worker 数 | **45**（显式 --cpu 45） | 100（128×25/32 自动推导） | **偏低** |
| 线程覆盖 | 45/128 = 35% | 78% | 未满载 |
| 实测 CPU 使用率 | **49.7%–50.4%** | ≥90%（组合负载判据） | **未达标** |

说明：7380 为 64 物理核/128 逻辑线程，自动推导规则为逻辑线程×25/32=100。显式 `--cpu 45` 使 CPU 无法满载，组合负载下实测仅 ~50%，不满足“混合模式下 CPU 均值 ≥90%”的负载达成判据。

### 3.2 内存 —— 目标偏低且根数不符

| 项目 | 实际 | 建议/推导 | 判定 |
|---|---|---|---|
| worker 数 | 12（显式 --vm 12） | **16**（dmidecode 实测 16 根 64G） | 根数不符 |
| 单 worker | 24G（显式 --vm-bytes 24G） | 56G（64G − max(6G, 8G)） | 偏低 |
| 内存目标 | **288G** | 16×56G = **896G**（约 80% MemTotal） | **不足** |
| 占 MemTotal | 25.7% | 82%（设计约定） | 压力不足 |
| 上限 | 1028G（min 1031G MemTotal×92% / 磁盘预留后 1028G） | — | 未超限 |

说明：脚本探测到单根 64 GiB，但显式 `--vm 12` 与实际 16 根不一致；显式 `--vm-bytes 24G` 又绕过了推导，最终只压 288G。按设计（单根扣除预留、覆盖全部 DIMM）应可推导到 896G（16×56G），内存压力才能达到验收目标。

| 项目 | 结果 |

| peer_disks | combo 声明 7，与磁盘任务数一致（参与内存预留） |

## 6. 问题与建议

| 优先级 | 问题 | 建议 |
|---|---|---|
| P0 | CPU 仅 45 worker，实测 ~50%，无法判“CPU 达标” | 不要显式 `--cpu 45`，让脚本推导为 100；或确需手配则 `--cpu 100` |
| P0 | 内存目标 288G（25.7%），压力不足且 `--vm 12` 与实际 16 根不符 | 用 `--vm 16`（实际根数）且**不传 --vm-bytes**，让脚本推导 16×56G=896G（约 80%）；若需手配，`--vm 16 --vm-bytes 56G` |
| P1 | 若当前组合设计有意降低 CPU/内存以突出 7 盘并发 | 明确验收口径：组合负载下 CPU ≥90%、内存 ≥ 目标 80%（896G）；否则该机 CPU/内存项只能判“未压满” |
| P2 | 10h 未结束 | 结束后抓最终数据（`status.txt`、`*.exitcode`、完整采样）再判定 |
