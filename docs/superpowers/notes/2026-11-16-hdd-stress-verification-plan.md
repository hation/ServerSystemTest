# 硬盘压测逻辑核查（排查）方案

- 日期：2026-11-16
- 状态：待用户批准
- 目的：先确认“项目现在到底做了什么”，再判断是否符合现场口径；本方案不设计新方案
- 关联：`offline-stress-pkg/stress-test.sh`、`disk-mount.sh`、`oneclick.sh`、`cmd.txt`

## 1. 为什么要先排查

现场口径是一串具体动作：`lsblk → mkdir → mkfs.ext4 -m 0 /dev/sdb1 → mount → cd → stress`，每盘一个窗口，系统盘单独跑。

要回答“项目是否符合”，必须把每个动作落到**实际执行路径**上，并且有证据。仅凭通读代码容易漏掉：

- 分支条件（已有分区 / 已有文件系统 / 已挂载 / 空盘）；
- 参数默认值（时长、写入量）；
- 安全边界（系统盘、未知盘、`--yes`）；
- 判定逻辑（什么时候算“异常”）。

因此先定核查方法，再出结论。

## 2. 核查目标（只回答现状）

对现场 6 类动作逐条回答：

1. 是否枚举到正确的数据盘、是否排除系统盘；
2. 是否创建并使用 `/mnt/HDDxx` 挂载点；
3. 是否给每块盘建分区、分区表类型、分区设备名；
4. 是否执行 `mkfs.ext4 -m 0`、作用对象是整盘还是分区、什么条件下跳过；
5. 是否**进入挂载目录**执行 `stress --hdd 1 --hdd-bytes 10G --timeout ...`，是否每盘一个窗口/进程并发；
6. 系统盘在哪执行、是否参与分区/格式化；
7. 默认时长与写入量是多少、如何覆盖；
8. 压测结束后凭什么判定“正常/异常”，内核 I/O 错误是否覆盖；
9. 危险动作（格式化）在什么条件下发生、是否有确认。

**不在本次范围**：改代码、设计新方案、讨论“应该怎么做”。

## 3. 核查问题清单

| 编号 | 问题 | 对应的现场动作 |
|---|---|---|
| Q1 | 盘枚举规则：是否取 `/mnt/HDD*`、是否排除系统盘、NVMe/多分区如何处理 | `lsblk` |
| Q2 | 挂载点命名与创建：是否 `/mnt/HDD01..12`、是否只在内存挂载 | `mkdir -p /mnt/HDD{01..12}` / `mount` |
| Q3 | 分区行为：默认是否建分区、分区表类型、分区设备名如何得到 | `mkfs.ext4 /dev/sdb1` 的前提 |
| Q4 | 格式化行为：`mkfs.ext4 -m 0` 作用对象；已有分区/已有文件系统/已挂载时是否跳过 | `mkfs.ext4 -m 0 /dev/sdb1` |
| Q5 | 进入目录：是否 `cd` 到挂载点后再起 stress（决定临时文件落盘位置） | `cd /mnt/HDD01` |
| Q6 | stress 参数：`--hdd`、`--hdd-bytes`、`--timeout` 的实际取值与来源 | `stress --hdd 1 --hdd-bytes 10G --timeout 24h` |
| Q7 | 并发与窗口：是否每盘一个终端窗口、是否同时启动、失败是否即停 | 12 个命令行窗口 |
| Q8 | 系统盘：执行目录、是否分区/挂载、参数是否相同 | 系统盘在根目录跑 |
| Q9 | 监控与判定：采样内容、退出码判定、`error.log` 来源、dmesg 关键字覆盖范围 | “压测结果是否正常” |
| Q10 | 安全边界：格式化触发条件、确认机制、`--yes` 跳过了什么 | 防止误清盘 |

## 4. 核查方法（三层，逐层取证）

### L1 静态代码走查（本地，零风险）

- 逐条跟踪 Q1–Q10 的代码路径，记录 `file:line` 与关键片段。
- 重点看分支：空盘 / 有分区 / 有文件系统 / 已挂载 / 系统盘。
- 产出：每条问题的“代码证据”条目。

### L2 沙箱动态复现（本地，零风险）

在 WSL 临时目录用**假命令**替代真实系统命令，记录脚本实际调用的命令序列：

- 假件：`lsblk`、`blkid`、`findmnt`、`parted`、`partprobe`、`mkfs.ext4`、`mount`、`umount`、`stress`、`dmesg`、`df`。
- 覆盖盘态：空盘、有分区无文件系统、有分区有文件系统、整盘有文件系统、已挂载、系统盘。
- 断言方式：假件把收到的 argv 逐行写日志，按日志判定“脚本实际执行了什么”。
- 约束：全部在临时目录，绝不调用真实 `mkfs`/`mount`。

### L3 现场只读核查（可选，需要你授权并提供机器）

在麒麟 V10 SP3 上只执行只读命令，不挂载、不格式化、不压测：

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
blkid
findmnt
df -h
bash disk-mount.sh list
bash disk-mount.sh mount --disks all --dry-run   # 只打印计划
bash -n stress-test.sh oneclick.sh disk-mount.sh
```

- `--dry-run` 必须只打印、不执行；执行前会先确认这一点。
- 若你暂时没有可用机器，L1+L2 也能给出结论，但“现场盘态适配”一栏会标“未验证”。

## 5. 证据与判定标准

每条结论必须包含四项：

1. **现场步骤**（原命令）；
2. **实际行为**（代码路径 + 运行时的命令序列/输出）；
3. **证据**（`file:line`，以及沙箱或现场的命令输出）；
4. **判定**：

| 判定 | 含义 |
|---|---|
| 符合 | 动作、对象、参数与现场一致 |
| 部分符合 | 目的相同，但对象/参数/路径不同 |
| 不符合 | 缺少该动作，或作用对象不同导致结果不等价 |
| 无法确认 | 需要现场盘态才能判定 |

## 6. 风险分级标准

| 级别 | 判据 |
|---|---|
| 高 | 可能造成数据不可逆丢失，或坏盘被误判为正常 |
| 中 | 结果与现场口径不等价、需要人工补救，但不丢数据 |
| 低 | 文案、路径差异，不影响结论 |

每条风险必须写清：**触发条件 / 影响面 / 是否可逆 / 现有缓解**。

## 7. 交付物

1. **排查记录**：Q1–Q10 的代码证据与沙箱执行日志（可作为附件）。
2. **对比分析文档（定稿）**：矩阵形式 `现场步骤 | 实际行为 | 证据 | 判定 | 风险`。
3. **待确认口径清单**：仅列“现状无法回答、必须由你决定”的问题。
4. 明确声明**不包含**新方案设计。

## 8. 执行顺序

1. L1 静态走查，填满 Q1–Q10 的代码证据；
2. L2 沙箱复现，补齐运行证据；
3. （可选）L3 现场只读核查；
4. 汇总判定与风险，出对比分析定稿；
5. 与你确认口径后，才进入新方案需求梳理。

## 9. 约束

- 不修改任何项目代码、文档（除本方案与排查记录）。
- 沙箱不触碰真实块设备；不执行真实 `mkfs`/`mount`/`stress`。
- 现场核查只读；任何写操作需单独批准。
- 不预设结论：若证据推翻了初稿的判断，按证据改。

## 10. 需要你确认

1. 是否按本方案开始执行；
2. 是否有可用的麒麟测试机做 L3 只读核查（有则提供访问方式；没有则只做 L1+L2，并在结论中标注未验证项）。
