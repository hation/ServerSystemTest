## 1. 结论摘要

1. **运行正常**：两台机器（stress-test-3 / stress-test-4）各跑满 1 小时并正常收尾——`successful run completed in 3607s / 3604s`、`stress.exitcode=0`、`status.txt` 均 `OK / all-exitcode-zero / oom=no`。
2. **参数合规（与 11-17 批次的关键区别）**：这两台机器内存为 **2003 GiB**（此前为 1877 GiB），`--vm 32 --vm-bytes 56G`（1792 GiB）在本机位于上限之内：`内存分配上限 1802G（min(2048×88%, 2003×92%)）`，run-config 明确记录 **“内存需求: 实际 1792G（未超限）”**。上一次“超分配上限 66 GiB”的问题在这两台机器上不存在。
3. **功能有效**：稳态 112 个采样点 CPU **100.0%**（最低也是 100.0%）；内存常驻 **1798.9–1799.0 GiB（占本机 2003 GiB 的 89.8%）**，`--vm-keep` 生效，1 小时内无回落；结束后 30 秒内释放。
4. **稳定性好**：MemAvailable 全程 ≥ **198.9 GiB**（比 11-17 批次充裕得多），swap 全程 0，无 OOM、无非 0 退出码、无 dmesg 错误记录（`io=no`）。
5. **说明**：两个容器目录内还各带有一个 `20261117-*` 旧批次文件夹，内容与已分析的 11-17 批次（1877G 机器、超限运行）完全一致，属历史残留副本，本次不重复判定。

## 7. 稳定性与异常

- 112 个稳态点 CPU 始终 100.0%，load 稳定在 140±3，无抖动；
- 内存：启动约 90 秒爬满 1799.0 GiB，之后 59 分钟保持平稳，结束干净释放；swap 0、`oom=no`；
- **无任何 error.log 正文**（两批 `io=no`，连 11-17 批次那类挂载误报也没有）；
- 采样间隔最大 46s 共 6 次，与进程快照开销对应，无空洞。

## 9. 适用范围

- 仅说明“CPU + 内存组合负载下整机稳定 1 小时”，不代表单项性能上限；
- 未涉及磁盘、网络、文件系统校验，不构成整机验收结论；
- 内存指标口径为 `MemTotal − MemFree`（含 page cache），非单一 stress 进程占用；
- 1 小时短时测试，不能替代 10 小时长稳结论。

## 10. 问题与建议

| 优先级 | 问题 | 建议 |
|---|---|---|
| P1 | 显式 `--vm-bytes` 在本机恰好落在上限内（1792 < 1802），余量仅 10 GiB | 正式长稳（10h）建议改为脚本自动推导（`--vm 32` → 53G×32=1696G），或手填 52G 留足余量 |
| P1 | 采样间隔被 periodic 快照拉长到 46s（每 10 分钟一次） | 快照放后台执行，避免拖慢采样节拍 |
| P2 | 两容器目录残留 11-17 旧批次副本（1877G 机器数据） | 清理旧文件夹，避免误判为同一批 |
| P2 | 仅 1 小时 | 正式验收按 10h 长稳执行 |
