## 1. 结论摘要

1. **full 参数推导正确（本次修复生效）**：plan 自动生成 `--cpu 90 --vm 18 --vm-bytes 56G`——
   - CPU 90 = round(128 逻辑线程 × 70%)（留 ~30% 给 IO/系统，朋友规则）；
   - VM 18 = DIMM 根数（探测 18 根 64G）；
   - vm-bytes 56G = 64G − max(64/8, 6G)（脚本单根公式，未写死）。
2. **内存未超限**：目标 18×56G = **1008G**，上限 = min(1152×88%=1013, 1121×92%=1031, 磁盘预留后 1040) = **1013G**，1008G < 1013G → **未超限**；`--vm-keep` 常驻生效。
3. **中高强度达成（区别于 all）**：内存目标 1008G 占 MemTotal 的 **89.9%**（all 档同机为 896G/79.9%）；CPU 90（70%）而非 all 的 100（78%）——符合"整机中高强度、留 IO 余量"定位。
4. **启动成功**：`COMBO.startrc=0`，dispatch 行 `90 cpu, 0 io, 18 vm, 0 hdd`，监控在采样，`error.log` 空。
5. **覆盖 1:1**：5 数据盘 + 1 系统盘 = 6 个 hdd 任务，与已挂载盘数一致；sdb（外部挂载）正确跳过。
