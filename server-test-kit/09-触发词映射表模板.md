## 1. 使用规则（6 条）

1. 命中触发词 → 按"默认行为"执行（具体执行细节以对应脚本 / `docs/*SOP/提示词/规则` 为准）。
2. 未命中 → 先向用户确认意图（AskUserQuestion），不得自行猜测。
3. **破坏性操作必须用户明确确认**（脚本 `-Yes`），不得仅凭触发词直接执行。
4. **销售侧报告类**：仅当用户明确指定"出销售侧报告"后才开始（生成规则按新项目销售侧文档）。
5. **新功能上线时，把触发词补进本表**（提交 body / 交付记录同步注明"已登记触发词"）。
6. "执行后产物"列填写触发后产生的文件/落库结果；无文件产物时注明落库或"无文件"。

## 4. 维护约定

- **新增功能**：上线时补一行（触发词 + 功能 + 默认行为 + 入口 + 执行后产物），提交 body 注明"已登记触发词"。
- **改默认行为/产物**：同时更新本表与对应脚本/SOP/规则文档，保持两处一致（产物路径变化时重点核对"执行后产物"列）。
- **破坏性操作不豁免**：任何破坏性触发都必须先 `-DryRun` 预览并获用户 `-Yes` 确认，映射表触发词不豁免。
- **冲突时 AGENTS.md 优先**：`AGENTS.md`「技能使用限制」仍优先（默认不用的技能，除非用户主动点名，不因映射表触发）。
