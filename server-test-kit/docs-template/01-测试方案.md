## 5. 分层执行（L1/L2/L3）

> 三层模型引用 server-test-kit 05 号 §1：

| 层 | 覆盖 | 规模（示例） | 执行方式 |
| --- | --- | --- | --- |
| **L1 全量**（每台必测） | 识别建档、目检、全量压测、健康检查、整机稳定性 | 每台都做 | 编排器全自动 + 人工目检 |
| **L2 抽样**（每批抽 N 台） | 断电循环、老化、多平台兼容等 | 每批抽 N 台【示例：每 100 台抽 3–5 台，按客户定】 | 并行，多数软件可测 |

> 抽样规则按客户标准定；L3 一次送检同一实验室做齐。

## 7. 实施步骤

> 按 server-test-kit 10 号文档 §5.2 阶段 0–6 落地：

```
阶段 0 准备与校验  check_env.ps1 + diag_oob.ps1 + assess_capability.ps1（三步走）
阶段 1 建档        识别 + 预期清单比对 → 批次清单（唯一键）
阶段 2 目检/电性    目检 + 规格核对（电性复检需仪表到位）
阶段 3 全量压测     CPU/内存/磁盘/网络 全量 + 整机混压长压（编排器全自动）
阶段 4 抽样可靠     断电循环、老化、多平台兼容（并行）
阶段 5 外包送检     L3 全项同一实验室做齐
阶段 6 汇总报告     逐台 PASS/WARN/FAIL 总表 + 抽样报告 + 外包报告 → 验收结论
```

> ⚠️ 关键顺序：**必须先启动编排器（开 SOL 抓流）再引导被测机**；结果只产生在编排机的 `results\`（10 号文档 §7）。

## 8. 报告与归档

- 报告三件套（引用 server-test-kit 08 号报告与汇总表规则）：明细总表（CSV）+ 汇总 + 简表，判定规则写死、可审计。
- 评测报告按 server-test-kit 03 号 AI 评测提示词模板逐台评估，输出与既有报告同口径的结论。
- 归档位置：`results\<批次>\`（原始日志 / 报告 / 总表）；跨批次按唯一键累计到 `master_manifest.csv`。

## 9. 验收标准

**验收结论 = L1 全量 0 失败 + L2 抽样通过 + L3 外包报告合格，三者缺一不可。**

| 层 | 验收标准 |
| --- | --- |
| L1 全量 | 每台全量项 0 失败（错误 0、温度/性能达标、无未纠正错误） |
| L2 抽样 | 抽样项全部通过（断电循环、老化、多平台兼容） |
| L3 外包 | 外包样件报告合格（无硬件 = 标注"当前不能测"并给采购/外包计划） |

> 任一条件不满足 → 整体验收不通过，按失败件流程隔离复测后重新评估。
