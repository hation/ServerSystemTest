# 批量检测 SOP 模板（Standard Operating Procedure）

> 目的：对批量**被测实体**执行**标准化只读采集**，产出统一源数据文件，供分析端生成统一格式的分析报告（被测实体示例：服务器/整机）。
> 状态：**当前有效**
> 变更记录：v1（2026-11-13）——源自《36-批量硬盘检测SOP.md》去业务化改造（硬盘 → 被测实体），供服务器整机测试项目套用。

> 术语约定：被测实体（被测对象）、唯一键（示例：SN/资产号）、源数据（原始采集文件）、批次（batch）、计数器（固件累计计数器）。专词仅出现在「示例」语境。

---

## 1. 前置条件

| 项 | 要求（占位，按新项目定值） |
|---|---|
| 权限 | 管理员权限（读取底层数据需提权，按被测实体定） |
| 工具 | 部署包 bin 下标准工具（清单见 10 号文档）；采集脚本 `collect_report.ps1` |
| 连接方式 | 直连/透传；被控制器接管需先设直通（按被测实体接入方式定） |
| 环境 | 操作系统与版本要求（占位，示例：Windows PowerShell 5.1+） |

---

## 2. 采集流程（一键脚本）

```powershell
cd <部署目录>\bin          # 或部署包 bin
.\collect_report.ps1                                # 采集全部被测实体（默认自动生成批次 B+日期+时间，每次独立）
.\collect_report.ps1 -TargetList 1,2                # 只采编号 1、2（等价于 -DevList，指定编号列表）
.\collect_report.ps1 -DryRun                        # 先预览命令清单（推荐先跑）
.\collect_report.ps1 -Batch B20261113               # 覆盖某次结果：写入该批次目录（需重采时才传）
```

- 批次命名规则：默认不传 `-Batch`，脚本自动生成批次名（`B`+日期+时间，如 `B20261113_143000`），每次运行独立成批；**只有需要覆盖某次结果时**才显式传 `-Batch` 指定批次名，结果会写入该批次目录。
- 脚本自动识别被测实体（排除系统占用/USB/虚拟设备等，等价占位，按被测实体定）；
- 对每个被测实体执行 NN 条**只读**命令并将输出保存到文件；
- 结束后打印采集目录路径。

> **只读保证**：命令清单不得含任何写操作（源项目无 `-S on` / FORMAT / MODE SELECT 等写命令【示例】；新项目按被测实体核对）；DryRun 可预览核对。

---

## 3. 命令 → 文件 → 分析项对照

每实体一个子目录 `results\<Batch>\collect\<EntityID>\`，**01~NN 个文件**：

| # | 文件 | 来源命令 | 支撑的分析项 |
|---|---|---|---|
| 01 | `01_<占位>.txt` | `<工具A> --<参数> <目标>` | 占位（示例：主计数器、健康状态、缺陷信息） |
| 02 | `02_<占位>.txt` | `<工具B> --<参数> <目标>` | 占位 |
| … | … | … | … |
| NN | `NN_<占位>.txt` | `<工具C> --<参数> <目标>` | 占位 |

> 文件编号、命令、分析项由新项目按被测实体定。参考两项目示例：源项目为 7 文件（smartctl / sg_logs / openSeaChest / FARM），覆盖主计数器、后台任务、自检记录、官方健康判定、第二信源等分析项。

---

## 4. 目录与命名约定

```
results\<Batch>\collect\
├── <EntityID1>\
│   ├── 01_<占位>.txt
│   └── … NN_<占位>.txt
├── <EntityID2>\
│   └── …（同上）
└── …
```

- `EntityID` = 被测实体编号（示例：服务器资产号 / 盘位号）。

---

## 5. 交接清单（给分析端什么）

把 `results\<Batch>\collect\` **整个目录**（或打包成 zip）交给分析端，即包含生成完整报告所需的全部数据。

可选补充信息（提高报告准确性）：
- 被测实体的标签照片（示例：盘体标签照片，用于核对标签年份 vs 固件出厂日期）
- 来源/批次说明（供应商、采购信息）

---

## 6. 分析产出

分析端依据 `collect\` 目录逐实体生成统一格式的分析报告，包含：

1. **核心结论**（可直接引用）：状态判断 + 是否被重置 + 健康状态（结论维度按被测实体定义，占位）
2. **基本信息表**（唯一键/型号/固件/出厂日期/主计数器/读写量/状态）
3. **证据链**（每条含原始数据，可追溯到 01~NN 文件的具体行）
4. **结论摘要表**（多条独立证据）
5. **检测命令记录**（可复现）

> 分析端还可运行自动化判定脚本（占位：源项目为 `assess_disk_usage.ps1` / `assess_smart.py`，生成机器可读结果）作为自动判定的补充。

## 7. 判读速查（怎么从数据看出结论）

> 表中数值行均标【示例】：业务判据数值由新项目按《05-测试矩阵与分层模型》与《10-服务器整机测试专项规划》定值。

### 7.1 生命周期状态判读（是否被重置等取证）——编码 C1…

| 判读 | 数据出处 |
|---|---|
| **C1：关键状态页全部不可用/无数据**【示例：Format 状态页全 `<not available>`】 | 关键状态页文件 |
| **C2：次级计数器 ≫ 主计数器（比值 > 3，且主计数 > 0）**【示例：加载卸载 33,436 vs 启停 56】 | 上下电计数页文件 |
| **C3：后台任务计数远超主计数（> 主计数 × 50）**【示例：后台扫描计数 × 数百次 对应通电仅几小时】 | 后台任务页文件 |
| **C4：纠错计数与吞吐量比例异常（每 KB > 1 次）**【示例：ECC 1,066 次 vs 535 KB】 | 错误计数页文件 |
| 主计数远小于出厂年限应有值【示例：2016 出厂却通电 1 小时】 | 主计数/官方信息文件 |
| 读写量/年均工作量近乎为零【示例】 | 官方信息文件 |

> 定级口径（占位）：源项目为"C1 是必要条件 + C2/C3/C4 命中 ≥1 条独立矛盾即判重置；状态页完好但 ≥2 条矛盾判人工复核；C1 命中但无独立矛盾判人工复核"。新项目按 05/10 号文档定值。

### 7.2 身份核验（是否翻新/再流通）

| 判读 | 数据出处 |
|---|---|
| 官方工具出厂日期 ≠ 实体标签年份【示例】 | 官方信息文件 vs 标签照片 |
| 固件版权年份 ≈ 出厂日期年份【示例】 | 官方信息文件 |
| 部件序列号与唯一键的关系【示例】 | 官方信息文件 |

### 7.3 健康判读

> 健康判据统一编号见 03 号文档 H1–H7（不参与异常定级）；本表为常用判读项速查。

| 判读 | 数据出处 |
|---|---|
| 官方健康判定通过【示例：SMART Status: Good / SMART Check Passed】 | 官方信息/健康检查文件 |
| 缺陷列表为 0【示例：grown defect = 0】 | 主计数文件 |
| 不可纠正错误为 0【示例：uncorrected = 0】 | 主计数文件 |
| 温度正常【示例：20–45°C】 | 主计数/官方信息文件 |

### 7.4 第二信源交叉核验

| 编号 | 核验项 | 方法 | 判定 |
|---|---|---|---|
| C8 | 主计数器 | 第二信源值 vs 主计数 | 差值超阈值 → 写"第二信源与主记录不一致"，**仅提升置信度** |
| C9 | 上下电次数 | 第二信源 vs 计数页 | 比值超阈值 → 同上 |
| C10 | 次级计数器 | 第二信源 vs 计数页 | 比值超阈值 → 同上 |

> **通用原则一：第二信源交叉只提升置信度、不参与定级**——第二信源与主记录冲突时不得单独据此判定；第二信源缺失/不一致不导致降级。
> **通用原则二：信源缺失永不导致降级**——缺失只影响置信度上限，不构成负面证据（源项目：2019 年前固件无 FARM 属正常，不阻断评估【示例】）。

**第二信源缺失处理**（占位，参考源项目）：
- 缺失**永不导致降级**；
- 展示性同源页不作第二信源【示例：源项目 0x3E 与 05 文件主计数同源、永远同值，仅作展示】；
- 报告中输出固定说明（占位模板），并披露"无第二信源，置信度上限为中"。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 命令清单里读到的是控制器型号而非被测实体【示例：Vendor 为控制器】 | 被测实体被控制器接管，先设直通/透传（示例：storcli 或卡 BIOS 设直通/JBOD）再采集 |
| 某文件为空 | 对应工具缺失或被测实体不支持该项——在报告中标注"未采集到"，不影响其余项 |
| 状态字段显示不可用【示例：SMART Unavailable】 | 对部分接入方式为正常现象，仍需看文件正文数据；若正文也异常则正是异常痕迹 |
| 多实体并行 | 脚本当前串行；实体数多时可分多个 Batch 跑（每个 Batch 独立目录） |

## 9. 方法可信性边界（新项目必读，依据《检测方法可信性说明.md》通用化）

| 边界 | 说明 |
|---|---|
| 只读证据 | 结论基于只读采集的固件累计计数器与留档文件；任何写操作会破坏证据链；命令清单经 DryRun 核对 |
| 阈值经验性 | 判据阈值（比值 > 3、> 主计数 × 50、每 KB > 1 次等）为专家经验值，尚未用带标签样本统计标定——属"可复现的规则"，非"统计校准的模型"；新项目须定值 |
| 无历史快照 | 单次采集只能看到当前快照，无法区分"从未发生"与"已被重置"；历史结论依赖不同计数器之间的物理矛盾 |
| 工具差异 | 不同工具读取同一数据源的口径可能不同；多源一致只能证明"读取无误"，不构成多份独立物理证据（源项目：04 与 05 文件非完全独立信源【示例】；真正独立性来自不同计数器之间与第二信源） |
| 结论建议性 | 所有结论标注"建议、非最终结论"，不替代厂商/客户最终判定；定位是**使用历史取证**，不是故障/寿命预测 |
