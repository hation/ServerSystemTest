# 盘定位表与 SN 采集 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 压测出问题后从日志/报告直接定位物理盘 SN；HDM 日志解析补 NVMe 盘表（SN/槽位/链路状态）。

**Architecture:** 两块独立子项目：(1) 压测脚本（bash）启动时生成 disk-map.txt（设备名|SN|挂载点，SN 经 sysfs 零依赖采集），monitor-loop 写 error.log 时对报错设备标注 SN；(2) sds-log-parser（Python）专用解析器读 nvme_info.ini，报告与 ai-facts 附 NVMe 盘表。以 SN 为桥，HDM 信息按需补齐。

**Tech Stack:** bash（offline-stress-pkg，零第三方依赖）；Python 3.12 标准库（sds-log-parser，零第三方依赖）。

**Spec:** [2026-11-23-disk-map-design.md](../specs/2026-11-23-disk-map-design.md)

## Global Constraints

- 压测侧零第三方依赖，SN 采集只走 sysfs，不允许依赖 nvme-cli/smartctl（可作可选增强，装了用、没装降级）
- 新增 `SYSFS_ROOT="${SYSFS_ROOT:-/sys}"` 测试缝（仿 EDAC_ROOT 先例，stress-test.sh L28/L55）
- 不改现有归因/判定逻辑（I/O 错误优先于 status=OK），只在报错行上附加 SN 标注
- 旧结果目录（无 disk-map.txt / devices.txt 为空）优雅降级，不报错
- sds 侧：`nvme_info.ini` 专用解析器（ConfigParser 默认 `allow_no_value=False` 会因裸行解析失败，禁止复用 `_read_ini`）；链路状态读 BIT 行描述（`BIT3:The first port's PCIe link is up/down`），不读十六进制 Status Flags
- 修改脚本后同步 docs/ 行号引用（README.md / operation-manual.md / 命令执行逻辑.md，按函数所在 lib 计）
- 交付重新打包 offline-stress-pkg 并递增版本：v1.1.2 → **v1.2.0**（功能新增），产出 `offline-stress-pkg.zip` 与 `offline-stress-pkg-v1.2.0.zip` 两个一致 zip

## Review Focus

- 旧结果目录无 disk-map.txt（或 devices.txt 为空）时，error.log 标注 SN 必须退化为原样、不报错 —— Task 2 覆盖
- SATA/SCSI 盘 `device/` 目录无 serial：SN 留空、不中断枚举 —— Task 1 覆盖
- `nvme_info.ini` 含 "NVMe WEB Information" / "----" 等裸行：专用解析器过滤、不抛异常 —— Task 3 覆盖
- 链路状态断言：**Front slot 19 link down 仅对 23.sds 成立**（M_20261123.sds 的 19 号槽是 0xbb/up，禁止用其断言 down）—— Task 3/4 覆盖
- 换发行版 sysfs 布局差异：`readlink -f /sys/class/block/<dev>/device` 定位 nvmeX 再读 serial，经 SYSFS_ROOT 可注入 —— Task 1 覆盖
