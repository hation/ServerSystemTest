## 2. 功能需求

### FR-1 分区与格式化（必须）

- 当用户显式要求重建（`disk-mount.sh mount --rebuild` 或 `oneclick.sh ... --rebuild`）时：
  - 每块数据盘建 **1 个分区**（GPT）；
  - 对分区执行 `mkfs.ext4 -m 0 <分区设备>`；
  - 挂载**分区设备**到 `/mnt/HDDxx`，不得挂载整盘。
- 分区设备名必须由 `lsblk` 实际解析，支持 `/dev/sdX1`、`/dev/nvme0n1p1`、`/dev/vdX1`、`/dev/mmcblk0p1`。
- 系统盘在任何模式下都不得分区、不得格式化、不得挂载。

**验收**：沙箱断言命令序列为 `umount? → parted mklabel gpt → parted mkpart → partprobe → mkfs.ext4 -m 0 <分区> → mount <分区> /mnt/HDDxx`；NVMe 盘得到 `p1` 后缀。

### FR-2 分区存在但无文件系统（必须）

- 默认模式与 `--rebuild` 模式下，若选中盘存在分区、但该分区 `blkid` 无文件系统类型：
  - **自动**执行 `mkfs.ext4 -m 0 <分区>`，然后挂载该分区。
- 只格式化被选中的那个分区；不得触碰同盘其他分区。
- 若 `blkid` 返回非 0/超时/设备忙：**重试 5 次**（每次间隔 1 秒，可配合 `udevadm settle`）；仍失败则**不格式化**，跳过该盘并记录原因，继续处理其他盘。
- 批次结束若存在跳过盘，退出码为 1，并在输出中列出“因 blkid 失败跳过”的盘。

**验收**：沙箱中“有分区、无 fs”用例产生一次 `mkfs.ext4 -m 0 /dev/sdX1` + `mount /dev/sdX1`；`blkid` 连续失败用例产生 5 次调用、0 次 `mkfs`，该盘被跳过且其他盘正常处理。

### FR-3 挂载失败即终止该盘（必须）

- `mount` 返回非 0 时：该盘标记失败，**不得**继续对该目录启动压测。
- `stress-test.sh start hdd --dirs <dir>` 启动前校验：`<dir>` 必须是独立挂载点（`findmnt` 能解析且不是根文件系统）。
- 校验不通过：该目录不计入任务，报错说明，退出码非 0。

**验收**：沙箱中 mount 失败用例无 stress 启动；`--dirs /tmp/xxx`（非挂载点）用例被拒绝，且不写入根文件系统。

### FR-4 挂载点编号稳定（必须）

- 已挂载在 `/mnt/HDDxx` 的盘保持原挂载点，不重新分配。
- 新挂载的盘只使用**未被占用**的编号，不得覆盖已有挂载点。
- 同一批次内“物理盘 ↔ HDDxx”的对应关系写入日志，事后可追溯。

**验收**：先挂载 sdb→HDD01，再挂载 sdc：sdc 得到 HDD02（或下一个空闲编号），HDD01 仍指向 sdb。

### FR-5 内核 I/O 错误检测（必须）

- dmesg 增量检测除 OOM 外，新增 I/O 错误类别：
  `EXT4-fs error`、`I/O error`、`Buffer I/O error`、`blk_update_request`、`critical medium error`、`ata*` 失败/错误、`nvme*` 错误/超时/reset 失败。
- 命中写入 `error.log`（带时间与原始行），并保留现有 OOM 记录格式。

**验收**：假 dmesg 输出 `EXT4-fs error (device sdb1): ...` 时，`error.log` 出现该行。

### FR-6 I/O 错误按盘归因（必须）

- 每个压测任务记录自己的设备名（分区名 + 整盘名）。
- dmesg 命中行只写入与设备名匹配的任务；无匹配信息的旧任务不做过滤（兼容）。
- 系统盘任务按根文件系统底层设备归因。

**验收**：同一时刻 sdb1 与 sdc1 各报一条 I/O 错误，HDD01 任务的 `error.log` 只含 sdb1 行，HDD02 只含 sdc1 行。

### FR-7 结论优先级（必须）

- 结论判定顺序：`error.log` 命中（OOM 或 I/O 错误）→ 异常；否则按 `status.txt`；`status=OK` 不得覆盖已命中的错误。
- 异常时 `summary.txt` 列出命中的错误行（至少前 3 条）。

**验收**：`status=OK` + `error.log` 含 I/O 错误 → 结论“异常”；两者都无 → “正常”。

### FR-8 一键入口透传与确认（必须）

- `oneclick.sh all|hdd` 新增 `--rebuild`，透传给挂载阶段。
- 菜单选择 1/2 时询问一次“是否重新分区并格式化数据盘？(y/N)”，默认 N。
- 未指定 `--rebuild` 时保持现有复用行为，并输出提示。
- 命令展示与 `commands.txt/commands.sh` 自动包含 `--rebuild`。

**验收**：沙箱断言挂载命令参数与落盘内容一致；菜单输入 N 时无重建命令。

### FR-9 `--dry-run` 命令行参数（应该）

- `disk-mount.sh mount` 支持 CLI `--dry-run`，只打印计划，不执行任何写操作（保留 `DRY_RUN=1` 兼容）。

**验收**：`--dry-run` 下命令序列为空，输出含完整计划。

### FR-10 系统盘压测口径（必须）

- 系统盘（根文件系统所在物理盘）**永不**参与数据盘的分区、格式化、挂载流程；识别后硬跳过。
- 系统盘压测固定为“根文件系统压测”：`cd /stresstest-hdd` 后写 10G 临时文件，压测对象是根文件系统所在分区/LV，不是整盘 LBA。
- 明确覆盖边界：**不覆盖** `/boot`、`/boot/efi`、`swap`、盘上未分配空间；LVM/RAID 下实际写入可能跨多个物理盘，无法归因到单盘。
- 报告/汇总中必须注明“系统盘=根文件系统压测”，避免被理解为整盘介质测试。
- 根文件系统剩余空间不足导致 `ENOSPC` 时，结论需与“盘故障”区分（标注为空间不足）。

**验收**：沙箱断言系统盘任务 cwd 为 `/stresstest-hdd`、参数与数据盘一致；`disk-mount.sh` 对系统盘零命令；`summary.txt` 含覆盖边界说明。

### FR-11 多分区数据盘（必须）

- 默认模式：每块数据盘只使用**第一个分区**（`lsblk` 顺序），其余分区不挂载、不压测。
- 执行计划中必须显式提示：`本盘有 N 个分区，默认仅测第一个（<分区名>，<容量>）；需要整盘覆盖请用 --rebuild`。
- `--rebuild`：清空分区表，重建为 1 个占满整盘的分区。
- 第一个分区容量小于 `--hdd-bytes` 时，计划中提示可能 `ENOSPC`。

**验收**：沙箱中多分区盘用例只挂载第一个分区，计划输出含分区数量与“仅测第一个”提示；`--rebuild` 用例生成 1 个 100% 分区。

## 3. 非功能需求

- **NFR-1 兼容**：`stress-test.sh` 参数、结果目录结构、`monitor.csv` 列、`review` 输出字段不被破坏；旧结果目录仍可 `review`。
- **NFR-2 离线**：仅使用 Kylin V10 SP3 自带命令（`parted`、`partprobe`、`mkfs.ext4`、`mount`、`findmnt`、`lsblk`、`blkid`、`udevadm`）。
- **NFR-3 安全**：系统盘硬跳过；重建仅在显式 `--rebuild`（或菜单 y）时发生；不确定盘态不格式化。
- **NFR-4 可观测**：所有磁盘操作写入 `mount.log`（命令 + 输出）；任务结论写入 `summary.txt`。
- **NFR-5 测试**：新增用例覆盖 FR-1~FR-9；既有 76/135/命令可见性/空格路径测试全绿。

## 4. 反目标

- 默认路径自动重建或清空任何数据盘。
- 默认模式静默只测多分区盘的第一个分区（必须显式提示）。
- 在非挂载目录上压测（包括 mount 失败后的空目录）。
- 把系统盘纳入分区/格式化/挂载。
- 把“系统盘根文件系统压测”表述为“系统盘整盘通过”。
- 让一块盘的 I/O 错误污染其他盘的结论。
- 改变 CPU/内存压测逻辑与既有输出格式。

## 5. 遗留风险（需在设计中给出处理）

| 风险 | 说明 |
|---|---|
| 多分区盘 | 默认只测第一个分区（已确认：显式提示）；`--rebuild` 会清空整盘分区表。 |
| `blkid` 误判 | 已确认：失败重试 5 次，仍失败跳过该盘、不格式化、不中断其他盘；“无输出”才视为无文件系统并自动格式化。 |
| dmesg 归因 | LVM/mapper、软链接设备名可能不匹配；设计中需给出兜底（记录未归因错误，不静默丢弃）。 |
| 固定 10G | 小盘或空间不足会 `ENOSPC`；本次不改为自适应，设计中需在结果里区分“空间不足”与“盘故障”。 |
| 系统盘覆盖不全 | 系统盘只测根文件系统，`/boot`、EFI、swap、未分配空间不覆盖；报告中注明口径，不宣称“整盘通过”。 |
| 重启后挂载丢失 | 当前不写 `/etc/fstab`；重启后需重新挂载。 |
