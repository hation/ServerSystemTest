# 压测项目执行流程与日志规则

> CPU/内存参数以 2026-11-17 v3 设计为准；文中 110/机型预设为历史口径。

> 适用范围：`offline-stress-pkg/`（Kylin V10 SP3，stress 1.0.4 离线压测包）
> 依据版本：`install.sh` / `verify.sh` / `disk-mount.sh` / `stress-test.sh` 当前实现（2026-11-13）
> 说明：本文描述脚本的**实际执行顺序**与**日志落盘规则**；操作步骤的精简版见同包 `README.md` 与 `operation-manual.md`，两者冲突时以脚本实现为准。

---

## 1. 交付物与职责

| 文件 | 职责 | 是否写日志文件 |
|---|---|---|
| `install.sh` | 离线安装 stress：root 检查 → RPM 存在检查 → SHA256 校验 → 同版本已装检测 → `rpm -Uvh` | 否（仅控制台输出） |
| `verify.sh` | 安装验证：检查 A（`rpm -q`）/ B（`stress --version`）/ C（10 秒冒烟压测） | 否（仅控制台 PASS/FAIL/SKIP） |
| `disk-mount.sh` | 测试盘管理：`list` / `mount` / `umount`，系统盘硬跳过 | 是（`mount.log`） |
| `stress-test.sh` | 压测主控：`start cpu\|mem\|hdd\|combo` / `status` / `stop` / `review`，内部 `monitor-loop` | 是（结果目录内多份日志 + 根级 `operations.log`） |
| `rpms/stress-1.0.4-24.el8.x86_64.rpm` | 离线安装包 | 否 |

所有脚本共同约束：

- 全程**不使用 `set -e`**，单个命令失败不中断整体流程，按各步骤自行判断；
- 压测进程与监控进程均通过 `nohup` 后台运行，可脱离 SSH 会话；
- 控制台输出**不会自动保存**为文件，需要留档时由操作者自行重定向。

## 2. 端到端执行流程（操作视角）

### 2.1 流程总览

```text
U 盘拷贝整包
   │
   ├─ install.sh          安装 stress
   ├─ verify.sh           验证安装（版本 + 冒烟）
   │
   ├─ [硬盘/组合测试前] disk-mount.sh list → mount
   │
   ├─ stress-test.sh start cpu|mem|hdd|combo
   │        │
   │        ├─ 前置校验（全量通过才启动）
   │        ├─ 建结果目录、写配置/快照/错误日志表头
   │        ├─ nohup 启动 stress（stdout/stderr 分流落盘）
   │        └─ nohup 启动 monitor-loop（30s 采样 + 巡检）
   │
   ├─ 运行期间：status / tail -f monitor.csv / tail -f stress*.log
   │
   ├─ 结束：--timeout 到期自动结束，或 stop 手动停止
   │
   ├─ review              生成 summary.txt（复盘）
   │
   ├─ 拷回 U 盘
   │
   └─ [硬盘/组合测试后] disk-mount.sh umount
```

### 2.2 分阶段说明

| 阶段 | 命令 | 前置条件 | 主要产物 | 失败行为 |
|---|---|---|---|---|
| 安装 | `sudo bash install.sh` | root（或 sudo）；RPM 文件完整 | `/usr/bin/stress`；控制台输出 | 非 root / 文件缺失 / SHA256 不符 / rpm 失败 → 退出码 1 |
| 验证 | `bash verify.sh` | stress 已安装 | 控制台 PASS/FAIL/SKIP | 任一检查失败 → 退出码 1 |
| 挂载 | `bash disk-mount.sh list/mount` | root；存在非系统盘 | `/mnt/HDDxx` 挂载点；`mount.log` | 选择含系统盘/无效盘 → 退出码 1；单盘格式化或挂载失败 → 提示后继续 |
| 启动 | `bash stress-test.sh start <type>` | stress 已安装；hdd/combo 的盘目录有效；`--sysdisk` 空间充足 | 结果目录 + 配置/快照/日志/PID | 任一前置校验失败 → 退出码 1，**不建结果目录、不启动进程** |
| 运行 | `status` / `tail -f` | 已 start | 只读展示，无新文件 | — |
| 停止 | `bash stress-test.sh stop` | 存在运行中任务 | 进程终止；`operations.log` 追加 | 无任务 → 提示，退出码 0 |
| 复盘 | `bash stress-test.sh review [--dir …]` | 结果目录存在且含 `monitor.csv` | `summary.txt` | 目录/监控文件缺失 → 退出码 1 |
| 卸载盘 | `bash disk-mount.sh umount` | 存在 `/mnt/HDD*` 挂载 | 卸载；`mount.log` | 无挂载点 → 提示，退出码 0 |

## 3. 脚本内部执行流程

### 3.1 install.sh

按固定顺序执行，任一步失败即 `exit 1`：

1. 解析脚本自身目录并 `cd` 进去（保证任意位置调用都能找到 `rpms/`）；
2. root 检查（`INSTALL_SKIP_ROOT_CHECK=1` 可跳过，仅测试用）；
3. 检查 `rpms/stress-1.0.4-24.el8.x86_64.rpm` 是否存在；
4. SHA256 校验，与脚本内锁定值比对；
5. `rpm -q stress` 命中 `1.0.4-24.el8` → 输出“已安装”，退出码 0；
6. `rpm -Uvh` 安装：成功输出“stress 安装成功：…”，退出码 0；失败退出码 1。

不产生任何日志文件；`rpm` 的原始输出只打到控制台（`NOKEY` 签名警告属正常）。

### 3.2 verify.sh

1. 检查 A：`rpm -q stress` 输出精确等于 `stress-1.0.4-24.el8.x86_64`；
2. 检查 B：`stress --version` 输出包含 `1.0.4`；
3. 检查 C：执行 `stress --cpu 2 --vm 1 --vm-bytes 256M --timeout 10`，退出码 0 为 PASS；`VERIFY_SKIP_SMOKE=1` 时输出 SKIP；
4. 汇总：全部 PASS → 输出 `PASS`，退出码 0；任一 FAIL → 输出 `FAIL`，退出码 1。

冒烟压测的输出被丢弃（`>/dev/null 2>&1`），不落盘。

### 3.3 disk-mount.sh

#### list（只读）

- 通过 `df /` 找到根文件系统底层设备，再沿 `lsblk` 的 `pkname` 逐层向上解析到 `TYPE=disk` 的整盘（兼容 LVM/mapper），得到“系统盘”；解析失败时用正则去分区号兜底；
- 只收集 `sd*` / `nvme*` 类型的整盘，统计容量、分区数、是否已挂载、首个分区；
- 系统盘及其分区在展示时标注“跳过”，不会进入后续选择；
- **不写 `mount.log`**。

#### mount（有写操作）

1. root 检查；
2. 收集非系统盘；无盘 → 退出码 1；
3. 选择纳入盘：
   - `--disks sdb,sdc`（自动去 `/dev/` 前缀与空白）；
   - 或交互输入逗号分隔盘符 / `all`；
   - 非交互且未给 `--disks` → 退出码 1；
4. 校验：含系统盘 → 拒绝并退出 1；盘不存在或不是非系统盘 → 退出 1；
5. 打印完整执行计划：已挂载盘显示“跳过”，不占用挂载点编号；其余盘按顺序分配 `/mnt/HDD01`、`/mnt/HDD02`…；
6. `DRY_RUN=1` → 打印“（DRY RUN，未执行）”，退出 0，**不写日志**；
7. 单个 `y` 确认；其他输入 → 取消，退出 0；
8. 逐盘执行并写 `mount.log`：
   - 有分区 → 直接挂载**首个分区**到 `/mnt/HDDxx`（其余分区不处理）；
   - 无分区但整盘已有文件系统（`blkid` 探测）→ 直接挂载整盘，不重新格式化；
   - 无分区且无文件系统 → `mkfs.ext4 -m 0` 后挂载整盘；
   - 已挂载盘跳过，不重复挂载；
   - 单盘格式化失败 → 跳过该盘；单盘挂载失败 → 提示后继续下一块盘；这两种情况**不会**把脚本最终退出码改为 1，需查看输出或 `mount.log` 确认。

> 注意：已挂载盘不参与编号。若同时选择“已挂载盘 + 未挂载盘”，未挂载盘可能被分配到已被占用的 `/mnt/HDDxx`。混合选择前建议先 `umount`，或只选择未挂载盘。

#### umount

1. root 检查；
2. 从 `df -P` 收集所有 `/mnt/HDD*` 挂载点；无 → 提示，退出 0；
3. 展示挂载点与设备；`DRY_RUN=1` → 不执行、不写日志；
4. 默认需 `y` 确认，`--all` 跳过确认；
5. 逐个 `umount` 并通过 `run_log` 写 `mount.log`；单盘卸载失败仅提示，继续下一块，最终退出码仍为 0。

### 3.4 stress-test.sh start

`start` 的顺序是**先全量校验、后创建目录与启动进程**，目的是避免校验失败留下孤儿进程或空结果目录。

1. **参数与类型校验**：类型必须是 `cpu|mem|hdd|combo`；`--model/--timeout/--cpu/--vm/--vm-bytes/--hdd-bytes/--dirs` 缺值即退出 1；未知参数退出 1；
2. `--sysdisk` 在 cpu/mem 模式下忽略并提示；
3. **机型解析**：`--model auto`（默认）时按 `MemTotal ≥ 800G → 7380`、否则 `nproc ≥ 120 → 7380`、否则 `nproc ≥ 90 → 7360`、否则 `5380`；显式 `--model` 直接用；
4. **参数预设与覆盖**：未显式指定的参数取机型预设；`--hdd-bytes` 默认 `10G`；
5. **stress 安装检查**：`command -v stress` 失败 → 提示先安装，退出 1；
6. **hdd/combo 盘目录校验**：
   - `--dirs` 显式指定：仅检查目录存在；任一不存在 → 整体退出 1；
   - 默认扫描 `/mnt/HDD*`：`hdd` 模式无目录 → 退出 1；`combo` 模式无目录 → 警告并降级为仅 CPU/内存（或配合 `--sysdisk` 只压系统盘）；
   - 默认扫描得到的目录还必须“确实已挂载且设备不是根设备”（`findmnt` / `df` 校验），否则整体退出 1；
   - 此阶段任一失败：**不启动任何 stress、不建结果目录**；
7. **`--sysdisk` 预检**：`mkdir -p /stresstest-hdd`；要求 `--hdd-bytes` 以 G 为单位；`df -P /` 可用空间 ≥ `hdd-bytes × 1.2`，不足 → 整体退出 1（此时 `/stresstest-hdd` 可能已创建）；
8. **创建结果目录**：根目录默认 `/root/stress-test`；目录名 `<YYYYmmdd-HHMMSS>-<type>`，同秒已存在则顺延 1 秒，绝不覆盖旧结果；
9. **写 `run-config.txt`**（覆盖写，一次）；
10. **写 `info-before.txt`**（覆盖写，一次）；
11. **初始化 `error.log`**：写入表头注释；
12. **清空并写 `stress.pids`**，按类型启动后台进程（均 `nohup sh -c`，记录包装 shell 的 PID）：
    - `cpu`：一个主进程 `stress --cpu N --timeout T`；
    - `mem`：一个主进程 `stress --vm N --vm-bytes X --timeout T`；
    - `hdd`：**没有主进程**，每个盘目录一个 `cd <盘目录> && stress --hdd 1 --hdd-bytes Y --timeout T`，编号 `HDD01…`；
    - `combo`：一个 CPU+内存主进程，加上每个盘一个 hdd 进程；`--sysdisk` 再加一个系统盘进程（在 `/stresstest-hdd` 下运行）；
    - 每个进程结束后由包装 shell 把 `$?` 写入对应 `.exitcode` 文件；
13. **启动 `monitor-loop`**：`nohup bash stress-test.sh monitor-loop <结果目录>`，PID 写入 `monitor.pid`；
14. **写 `operations.log`**：追加一行 `start type=… model=… timeout=… dir=… cmd=…`；
15. 控制台输出结果目录、`status` 查看方式、`monitor.csv` 实时查看方式。

> 顺序要点：`/stresstest-hdd` 的空间预检在第 8 步建结果目录之前；若预检失败，不会产生结果目录，但可能留下空的 `/stresstest-hdd`。

### 3.5 monitor-loop（内部子命令）

1. 初始化 `monitor.csv` 表头；
2. 读取 `/proc/stat`、`/proc/diskstats` 作为差值基线；记录当前存活进程数；只读探测 `dmesg` 可用性，并以当前 ring buffer 行数初始化本批次的行游标 `.dmesg.cursor`（探测失败则后续跳过 OOM 检测）；
3. 进入循环，**每轮先 `sleep <MONITOR_INTERVAL>`（默认 30 秒）**，因此第一行数据在启动约 30 秒后出现；
4. 采样并追加一行 `monitor.csv`：
   - `时间`：本地时间 `YYYY-MM-DD HH:MM:SS`；
   - `load1`：`/proc/loadavg` 第一列；
   - `cpu_usage%`：本轮与上轮 `/proc/stat` 差值的非空闲占比（`user+nice+system+idle+iowait+irq+softirq` 为总量，`idle+iowait` 为空闲），保留 1 位小数；
   - `mem_total/mem_used/mem_avail/swap_used`：单位 kB，其中 `mem_used = MemTotal - MemFree`（**不是** `MemTotal - MemAvailable`）；
   - `disk_read_MBps/disk_write_MBps`：`/proc/diskstats` 全部行第 6/第 10 字段（扇区）差值 × 512 ÷ 间隔 ÷ 1048576，保留 1 位小数；
5. **进程异常退出巡检**：若本轮存活数小于上轮，遍历所有已存在的 `*.exitcode`，内容非 0 时向 `error.log` 追加异常记录；
6. **dmesg 增量 OOM 巡检**：只读执行 `dmesg`（**不清空 ring buffer**），按 `.dmesg.cursor` 取游标之后的新增行，过滤 `oom|out of memory|killed process|Killed`，命中行追加到 `error.log` 并更新游标（ring buffer 回绕/被外部清空时游标归零、从头重读）；多个并发批次各自维护游标、各记一份，互不抢占证据；无权限/无 `dmesg` 时静默跳过；
7. 存活数为 0 → 跳出循环；
8. 跳出后：若所有已存在的 `*.exitcode` 均为 0，且 `error.log` 不含“检测到 stress”，追加一行“压测结束：全部正常（exitcode=0）”；随后监控进程退出。

`monitor-loop` 只由 `start` 后台调用，不对外作为常规命令使用。

### 3.6 status / stop / review

#### status（只读）

- 扫描 `STRESS_TEST_ROOT` 下 `*-cpu`、`*-mem`、`*-hdd`、`*-combo` 目录；
- 仅当 `stress.pids` 中至少一个 PID 存活时才归为“运行中”并展示；
- 每个运行中目录输出：结果目录、stress 存活进程数及 PID、监控进程状态、按“开始时间 + 超时秒数”估算的剩余时长、`error.log` 状态与最近 5 行、`monitor.csv` 最近 5 行；
- 无运行任务输出“无运行中的压测”，退出码 0；
- 不写任何文件。

#### stop

- 扫描上述类型目录；对“stress 仍存活”或“监控仍存活”的目录逐个处理；
- 对每个 `stress.pids` 中的 PID：先 `pkill -TERM -P` 终止其子进程，再 `TERM` 包装 shell；最多等待约 3 秒，仍未退出则 `KILL`；
- 对 `monitor.pid`：先 `TERM`，随后最多轮询 2 秒等待监控把 `state=STOPPED` 落盘到 `status.txt`（循环体每轮开始与 `sleep` 被打断后都会检查停止标记），仍未退出再 `KILL`；监控处理完才停止 stress 进程；
- 每个被停止的目录追加一行 `operations.log`：`stop dir=<结果目录>`；
- 无任务 → 输出“没有运行中的压测，无需停止”。

#### review

1. 未给 `--dir` 时，取根目录下按名称排序的最后一个结果目录（时间戳命名，等价于最新）；
2. 目录不存在或缺 `monitor.csv` → 退出码 1（**运行中的任务也可以 review，但只能得到截至当前的部分数据**）；
3. 从 `monitor.csv` 统计：数据行数、CPU 均值/峰值、`mem_used` 峰值、磁盘读峰值、磁盘写峰值；
4. 监控覆盖时长与覆盖率：以 `run-config.txt` 的 `开始时间` 为锚点，末行时间与开始时间之差为实际跨度 `span`，`expected = max(1, span / 采样间隔)`，`coverage = 行数 × 100 / expected`（展示值封顶 100%）；`coverage < 90` 时 `采样空洞: 是（末行距开始 … 秒，应有 … 点，实际 … 点，覆盖率 …%）`，否则 `采样空洞: 无`；开始时间或末行时间无法解析时两者均为“不可判定”。仅按行数估算会在机器长时间无采样（事故中仅 1 行）时严重高估覆盖率；
5. 从 `run-config.txt` 读取机型、开始时间、计划超时；预计结束时间 = 开始时间 + 监控覆盖时长；
6. 判定结论（优先读 `status.txt`，旧目录无 `status.txt` 时按退出码与 `error.log` 特征行判定）：
   - `state=OK` → `正常`；`state=FAILED` → `异常（退出码非 0）`；`state=ABORTED` 按 `reason` 细分为 `异常（内存耗尽被内核杀死）` / `异常（进程异常退出未留退出码）` / `异常（进程异常退出）`；`state=STOPPED` → `已手动停止`；
   - 无 `status.txt` 时：任一已存在的 `*.exitcode` 非 0、或退出码文件数少于 `stress.pids` 行数、或 `error.log` 匹配 `检测到 stress` 或 `dmesg:` → `异常`；否则 `正常`；
7. 覆盖生成 `summary.txt` 并打印。

## 4. 结果目录与日志全景

默认根目录 `/root/stress-test`（可用 `STRESS_TEST_ROOT` 覆盖）：

```text
/root/stress-test/
├── operations.log                      # 根级：start/stop 操作历史（追加，跨测试）
├── mount.log                           # 根级：挂载/格式化/卸载记录（追加，跨测试）
└── <YYYYmmdd-HHMMSS>-<cpu|mem|hdd|combo>/   # 每次测试独立目录，不覆盖
    ├── run-config.txt                  # 本次参数与命令（覆盖写一次）
    ├── info-before.txt                 # 测试前系统快照（覆盖写一次）
    ├── error.log                       # 错误日志：表头 + 主进程 stderr + 监控巡检记录
    ├── monitor.csv                     # 30 秒一条系统状态（表头 + 追加）
    ├── stress.log                      # cpu/mem/combo 主进程 stdout（hdd 模式无此文件）
    ├── stress.exitcode                 # cpu/mem/combo 主进程退出码（hdd 模式无此文件）
    ├── stress-HDD01.log                # 每个数据盘 hdd 的 stdout
    ├── stress-HDD01.exitcode           # 每个数据盘 hdd 的退出码
    ├── error-HDD01.log                 # 每个数据盘 hdd 的 stderr
    ├── stress-SYSDISK.log              # --sysdisk 时系统盘 hdd 的 stdout
    ├── stress-SYSDISK.exitcode         # --sysdisk 时系统盘 hdd 的退出码
    ├── error-SYSDISK.log               # --sysdisk 时系统盘 hdd 的 stderr
    ├── stress.pids                     # 内部状态：后台包装 shell PID 列表
    ├── monitor.pid                     # 内部状态：监控进程 PID
    ├── .dmesg.cursor                   # 内部状态：dmesg 增量 OOM 检测的行游标（每轮覆盖）
    ├── status.txt                      # 内部状态：监控落盘的结束状态（state/reason/pids/exitcodes/oom/end_time）
    └── summary.txt                     # review 生成（每次 review 覆盖）
```

> 文件是否存在取决于测试类型：`hdd` 模式没有 `stress.log` / `stress.exitcode`；`combo` 是否出现 `stress-HDDxx.*` / `stress-SYSDISK.*` 取决于是否有数据盘及是否加 `--sysdisk`。

## 5. 日志产生规则（逐文件）

通用规则：

- 所有时间戳均为**服务器本地时间**，格式 `YYYY-MM-DD HH:MM:SS`（目录名为 `YYYYmmdd-HHMMSS`）；
- 根级日志（`operations.log`、`mount.log`）**追加写、不轮转、不清理**，跨多次测试共享；
- 结果目录内日志除 `summary.txt` 外均为**追加或一次性覆盖**，不同测试目录之间互不影响；
- 文本为 UTF-8，行尾 LF；`monitor.csv` 为纯文本 CSV，可直接用 Excel 打开；
- 日志不会自动压缩、归档或删除；拷回 U 盘由操作者执行。

### 5.1 operations.log

| 项 | 规则 |
|---|---|
| 写入者 | `stress-test.sh` 的 `log_op` |
| 路径 | `$STRESS_TEST_ROOT/operations.log`（默认 `/root/stress-test/operations.log`） |
| 产生时机 | `start` 在**进程与监控都启动后**追加一行；`stop` 对每个实际停止的结果目录追加一行 |
| 写入方式 | 追加（`>>`），无表头 |
| 不写入 | `status`、`review`、`monitor-loop` |
| 格式 | `[时间] start type=<类型> model=<机型> timeout=<超时> dir=<结果目录> cmd=stress <参数>` / `[时间] stop dir=<结果目录>` |

示例：

```text
[2026-11-13 14:30:00] start type=combo model=7380 timeout=12h dir=/root/stress-test/20261113-143000-combo cmd=stress --cpu 110 --vm 16 --vm-bytes 54G --timeout 12h
[2026-11-14 02:30:05] stop dir=/root/stress-test/20261113-143000-combo
```

用途：核对“谁在什么时候启动了哪次压测、何时停止”，也是 `--dirs` 未被记录时的辅助追溯线索。

### 5.2 mount.log

| 项 | 规则 |
|---|---|
| 写入者 | `disk-mount.sh` 的 `run_log` |
| 路径 | `MOUNT_LOG`（默认 `/root/stress-test/mount.log`），目录不存在时自动创建 |
| 产生时机 | `mount` / `umount` **实际执行命令时**；`list`、`DRY_RUN`、root 检查失败、选择校验失败均不写 |
| 写入方式 | 追加；每条命令先以 `tee -a` 实时写入命令自身输出，再追加一行结果摘要 |
| 格式 | 命令原文输出 + `[时间] cmd: <命令及参数> 结果:<退出码>` |
| 退出码含义 | 摘要中的退出码取命令自身（`PIPESTATUS[0]`），不是 `tee` 的 |

示例：

```text
mke2fs 1.45.6 (20-Mar-2020)
Creating filesystem with ...
[2026-11-13 14:20:11] cmd: mkfs.ext4 -m 0 /dev/sdb 结果:0
[2026-11-13 14:20:12] cmd: mount /dev/sdb /mnt/HDD01 结果:0
[2026-11-13 14:20:12] cmd: umount /mnt/HDD01 结果:0
```

说明：

- 挂载点目录的 `mkdir -p /mnt/HDDxx` 也会被记录；
- 跨轮次追加，不区分测试批次；按时间排查即可；
- `mount` 的“计划”与确认过程不写入，只有真正执行的命令才写入。

### 5.3 run-config.txt

| 项 | 规则 |
|---|---|
| 写入者 | `stress-test.sh start` |
| 产生时机 | 结果目录创建后、任何 stress 进程启动前，写一次 |
| 写入方式 | 覆盖（`>`） |
| 解析方 | `status`（剩余时长）、`review`（机型/开始时间/超时/采样间隔） |

字段顺序固定：

```text
机型: <5380|7380|7360>
类型: <cpu|mem|hdd|combo>
开始时间: <YYYY-MM-DD HH:MM:SS>
超时: <原始 --timeout 文本，如 12h>
超时秒数: <换算后的秒数>
监控间隔: <N>s
结果目录: <绝对路径>
…（按类型追加 CPU worker 数 / VM worker 数 / VM 字节 / HDD 字节）
错误日志: error.log（stderr 实时记录）
命令: stress <参数模板>
```

注意：

- `开始时间` 是写配置的时间，略早于进程真正启动时间，`status` / `review` 的时长估算以此为准；
- `命令` 对 hdd/combo 只是参数模板，**不包含 `cd <盘目录>` 和实际盘目录列表**；实际盘序见 `stress-HDDxx.log` 编号与 `mount.log`；
- 该文件是 `review` 判断“机型/超时”的唯一来源，不要手工改名。

### 5.4 info-before.txt

| 项 | 规则 |
|---|---|
| 写入者 | `stress-test.sh start` |
| 产生时机 | `run-config.txt` 之后、进程启动前，写一次 |
| 写入方式 | 覆盖（`>`） |
| 内容 | `==== lscpu ====`、`==== free -h ====`、`==== df -h ====`、`==== lsblk ====`、`==== stress --version ====` 五段，命令的 stdout/stderr 均写入 |

用途：保留测试前硬件与系统状态基线，便于事后对比“压测前后磁盘/内存/挂载是否变化”。

### 5.5 monitor.csv

| 项 | 规则 |
|---|---|
| 写入者 | `monitor-loop`（由 `start` 后台启动） |
| 产生时机 | 监控启动时写表头；此后每 `MONITOR_INTERVAL` 秒（默认 30）追加一行 |
| 写入方式 | 表头覆盖，数据追加 |
| 表头 | `时间,load1,cpu_usage%,mem_total,mem_used,mem_avail,swap_used,disk_read_MBps,disk_write_MBps` |
| 首行延迟 | 循环先 `sleep` 再采样，故第一行数据在监控启动约 30 秒后出现 |
| 数据量 | 默认约 120 行/小时，12 小时约 1440 行 |

字段解释：

| 字段 | 来源 | 单位/说明 |
|---|---|---|
| `时间` | `date` | 本地时间，秒级 |
| `load1` | `/proc/loadavg` | 1 分钟平均负载 |
| `cpu_usage%` | `/proc/stat` 两次采样差值 | 非空闲占比，含 iowait 为空闲；近似值 |
| `mem_total` | `/proc/meminfo` | kB |
| `mem_used` | `MemTotal - MemFree` | kB；含缓存/缓冲区，不等于应用实际占用 |
| `mem_avail` | `MemAvailable` | kB |
| `swap_used` | `SwapTotal - SwapFree` | kB |
| `disk_read_MBps` / `disk_write_MBps` | `/proc/diskstats` 全部行差值 | MB/s；整盘与分区行会重复计入，属**全局近似值**，不是单盘/单进程精确值 |

注意：

- 监控进程退出或被停止后，`monitor.csv` 停止增长，不补采；
- `review` 必须有 `monitor.csv`，否则直接报错退出；
- 12 小时长测建议用 `tail -f` 观察，或拷回后用 Excel 打开。

### 5.6 error.log

| 项 | 规则 |
|---|---|
| 写入者 | `start`（初始化 + 主进程 stderr）、`monitor-loop`（巡检追加） |
| 产生时机 | 结果目录创建后立即初始化表头；运行期实时追加；结束后可能追加“全部正常”结论 |
| 写入方式 | 表头覆盖一次，其余追加 |
| 表头 | `# 压测错误日志（空=无错误） 开始时间: <时间>` |

记录来源与格式：

| 来源 | 适用类型 | 格式 |
|---|---|---|
| 主 stress 进程 stderr | cpu / mem / combo | stress 原始 stderr 文本，直接追加（`2>>`） |
| 进程异常退出巡检 | 全部类型 | `[时间] 检测到 stress 进程异常退出（存活数 <n1>→<n2>），exitcode=<值>，详见 <对应 .exitcode>` |
| dmesg OOM/系统错误 | 全部类型（需 dmesg 权限） | `[时间] dmesg: <匹配行原文>` |
| 正常结束结论 | 全部类型 | `[时间] 压测结束：全部正常（exitcode=0）` |

关键规则与边界：

- **hdd 模式没有主进程**，因此 `error.log` 不含 stress stderr；每盘 stderr 在 `error-HDDxx.log`，`error.log` 只有表头 + 监控巡检记录；
- `combo` 的 `error.log` 只对应 CPU+内存主进程；各盘 hdd 的 stderr 仍在各自的 `error-HDDxx.log` / `error-SYSDISK.log`；
- 新结果目录的 `error.log` **至少有 1 行表头**，所以 `status` 会显示“error.log（1 行…）”并展示表头，这不代表异常；是否有错以退出码和巡检特征行为准；
- 异常退出巡检在“存活数每下降一次”时遍历所有已存在的非 0 退出码；多进程分批退出时，同一个非 0 退出码可能被重复记录；
- `dmesg` 需要相应权限；不可用时整个 OOM 检测静默跳过，不阻塞监控；监控对 `dmesg` **只读**、从不清空 ring buffer，每个批次按自己的 `.dmesg.cursor` 记录增量，多批次并发时各自留一份证据；
- `review` 优先按 `status.txt` 判定；无 `status.txt` 时按“退出码文件缺失 / 非 0 退出码 / `检测到 stress` / `dmesg:`”判定异常，仅含表头或“全部正常”结论时判为正常；**不扫描** `error-HDDxx.log` 的 stderr 文本，hdd 异常最终通过非 0 退出码体现；
- 若进程被 `kill -9` 导致包装 shell 来不及写 `.exitcode`，退出码文件数会少于 `stress.pids` 行数，`review` 判为“异常”：有 `status.txt` 时为 `ABORTED`/`missing-exitcode`，无 `status.txt` 时由缺失退出码直接判异常（见第 7 节）。

### 5.7 stress*.log 与 error-*.log

| 文件 | 内容 | 产生条件 |
|---|---|---|
| `stress.log` | 主进程 **stdout**（`dispatching hogs`、`successful run complete` 等） | cpu / mem / combo |
| `stress.exitcode` | 主进程退出码 | cpu / mem / combo |
| `stress-HDDxx.log` | 第 xx 块数据盘 hdd 进程 **stdout** | hdd / combo 且有数据盘 |
| `stress-HDDxx.exitcode` | 对应盘 hdd 退出码 | 同上 |
| `error-HDDxx.log` | 对应盘 hdd **stderr** | 同上 |
| `stress-SYSDISK.log` / `.exitcode` / `error-SYSDISK.log` | 系统盘 hdd 的 stdout / 退出码 / stderr | `--sysdisk` |

规则：

- 每个进程的 stdout 与 stderr **分流**：正常信息进 `stress*.log`，报错信息进 `error*.log`；
- `xx` 从 `01` 开始，按实际纳入的盘顺序编号；默认 `/mnt/HDD*` 按 shell glob 字典序，`--dirs` 按用户给定顺序；
- hdd 进程通过 `cd <盘目录>` 后运行，stress 的压测文件写在该盘目录下；
- `error-HDDxx.log` 即使为空也会被创建（重定向行为）；
- 这些文件在进程存活期间持续写入，可用 `tail -f` 实时查看；
- 进程结束后不再变化；不自动清理压测留在盘上的临时文件。

### 5.8 *.exitcode

| 项 | 规则 |
|---|---|
| 写入者 | 每个 stress 启动命令的包装 shell：`echo $? > <对应>.exitcode` |
| 产生时机 | 对应 stress 进程结束后 |
| 内容 | 单个数字 + 换行；`0` = 正常跑完 `--timeout`；非 0 = 失败或被中断 |
| 缺失情况 | 包装 shell 被 `kill -9`、机器重启/断电、进程尚未结束 |
| 解析方 | `monitor-loop`（异常巡检）、`review`（结论与退出码段） |

注意：

- `hdd` 模式**没有** `stress.exitcode`，只有每盘的 `stress-HDDxx.exitcode`；
- `combo` 的 CPU+内存进程用 `stress.exitcode`，各盘/系统盘各自独立；
- `stop` 手动停止时，退出码通常非 0，也可能因包装 shell 被终止而缺失；两种都按“被中断”理解。

### 5.9 stress.pids 与 monitor.pid

| 文件 | 内容 | 写入规则 |
|---|---|---|
| `stress.pids` | 本次测试所有 stress 包装 shell 的 PID，每行一个 | `start` 时先清空，再按启动顺序追加 |
| `monitor.pid` | 监控循环进程 PID，单行 | `start` 时覆盖写入 |

说明：

- 记录的是 `nohup sh -c '...'` 包装 shell 的 PID，真正的 `stress` 是其子进程；`stop` 会先杀子进程再杀包装 shell；
- 这两个文件是脚本内部状态，`status` / `stop` / `monitor-loop` 依赖它们判断存活；
- 不要手工编辑；手工删除会导致 `status`/`stop` 无法识别该次测试。

### 5.10 summary.txt

| 项 | 规则 |
|---|---|
| 写入者 | `review` |
| 产生时机 | 每次执行 `review` 时生成；不随测试结束自动生成 |
| 写入方式 | 覆盖（同一目录多次 review 只保留最后一次） |
| 前置条件 | 结果目录存在且含 `monitor.csv` |

内容结构：

```text
==== 压测复盘总结 ====
结论: <正常|异常>
异常点: …（仅异常时列出非 0 退出码与 error.log 特征）
生成时间 / 结果目录 / 类型 / 机型 / 开始时间 / 计划超时 / 预计结束时间
监控采样行数 / 监控覆盖时长
运行状态: <state>（<reason>）    ← 有 status.txt 时；否则“未记录（无 status.txt）”
OOM: <是|否>                      ← 仅在有 status.txt 时输出，取自 oom= 字段
采样空洞: <是（…覆盖率 …%）|无（覆盖率 …%）|不可判定（…）>
CPU 使用率: 均值 …%，峰值 …%
内存峰值 (mem_used): … kB
磁盘读峰值: … MB/s
磁盘写峰值: … MB/s

== 退出码 ==
<各 .exitcode 文件名>: <值>
（0 表示 stress 正常结束，非 0 表示异常或被中断）

== 错误日志 ==
error.log 共 N 行
<最多展示前 20 行>

原始数据: monitor.csv / run-config.txt / info-before.txt / stress*.log / error.log
```

注意：

- “预计结束时间”按监控覆盖时长推算，不是精确的实际结束时间；
- 统计只来自 `monitor.csv`，不含 `stress*.log` 内容；
- 对运行中的任务执行 `review`，得到的是截至当前的部分数据，退出码段可能显示“未找到退出码文件”；
- 结论优先按 `status.txt` 判定，无 `status.txt` 的旧目录才按“已存在的退出码 + 退出码文件缺失 + error.log 特征行”判定。

## 6. 一次 combo 测试的日志时间线

| 时间点 | 事件 | 产生的日志/文件 |
|---|---|---|
| T0 | 参数解析、机型检测、盘目录与系统盘空间校验 | 无（`--sysdisk` 时可能创建 `/stresstest-hdd`） |
| T1 | 创建结果目录 | `<时间戳>-combo/` |
| T2 | 写运行配置 | `run-config.txt` |
| T3 | 写测试前快照 | `info-before.txt` |
| T4 | 初始化错误日志 | `error.log`（表头） |
| T5 | 启动 CPU+内存主进程、各盘 hdd 进程 | `stress.pids`；`stress.log`、`error.log`、`stress-HDDxx.log`、`error-HDDxx.log`（及 `--sysdisk` 对应文件） |
| T6 | 启动监控 | `monitor.pid`；`monitor.csv`（表头） |
| T7 | 写操作记录 | `operations.log` 追加 start 行 |
| T+30s | 第一次采样 | `monitor.csv` 追加首行 |
| 每 30s | 持续采样 | `monitor.csv` 追加；异常时 `error.log` 追加巡检记录 |
| 进程结束 | 包装 shell 写退出码 | `stress.exitcode` / `stress-HDDxx.exitcode` / `stress-SYSDISK.exitcode` |
| 全部结束 | 监控最后一轮巡检、追加正常结论（如全 0） | `error.log` 追加结束行；监控进程退出 |
| 手动/到期后 | 执行 review | `summary.txt` |

## 7. 判定与显示规则

### 7.1 review 结论

优先级：结果目录存在 `status.txt`（由 `monitor-loop` 落盘的结束状态）时，先按 `state` 映射；无 `status.txt` 的旧目录才回落到退出码 / `error.log` 特征行判定。

| `status.txt` 的 state / reason | 结论 |
|---|---|
| `OK` | 正常 |
| `FAILED` | 异常（退出码非 0） |
| `ABORTED` + `reason=oom-killed` | 异常（内存耗尽被内核杀死） |
| `ABORTED` + `reason=missing-exitcode` | 异常（进程异常退出未留退出码） |
| `ABORTED` + 其他 reason | 异常（进程异常退出） |
| `STOPPED` | 已手动停止 |
| 无 `status.txt`：任一已存在 `*.exitcode` 非 0、退出码文件数少于 `stress.pids` 行数、或 `error.log` 含 `检测到 stress` / `dmesg:` | 异常 |
| 无 `status.txt` 且以上都不成立 | 正常 |

补充：

- `status.txt` 的 `oom=` 字段会在 summary 的 `运行状态` 行下方额外输出一行 `OOM: 是/否`；即使结论因退出码非 0 优先显示“异常（退出码非 0）”，也能看到是否发生过 OOM；
- `error.log` 只有表头或只有“压测结束：全部正常” → 不影响结论；
- `error-HDDxx.log` 中的 stderr 文本不直接参与结论判定，hdd 异常通过非 0 退出码体现；
- **退出码文件缺失会被判为异常**：无 `status.txt` 时，退出码文件数少于 `stress.pids` 行数即判 `异常`（含 `kill -9` 未及写退出码）；有 `status.txt` 时由 `ABORTED` / `missing-exitcode` 明确给出结论，summary 同时保留“未找到退出码文件”提示供人工复核；
- `review` 不在运行时检查进程是否存活，运行中 review 的结论仅供参考。

### 7.2 status 显示

- 只展示 `stress.pids` 中仍有存活 PID 的测试目录；测试已结束的目录不显示；
- 剩余时长 = `开始时间 + 超时秒数 - 当前时间`，到期后显示“已到期，等待退出”；
- 监控进程已退出但 stress 仍存活时，会显示“监控进程: 已退出”，属异常信号，需检查；
- `error.log` 存在且非空（含仅表头）时显示行数与最近 5 行；旧目录无 `error.log` 时显示“未生成（旧版本目录）”。

### 7.3 人工判定建议

- 优先看 `summary.txt` 的 `== 退出码 ==`：任一非 0 → 异常；
- 退出码文件缺失 → 视为强制中断（`kill -9`、重启、断电）；
- `error.log` 出现 `dmesg:` → 重点排查 OOM/内核报错；
- `error-HDDxx.log` 非空 → 对应盘 hdd 进程有 stderr，即使退出码为 0 也建议查看。

## 8. 保留、覆盖与清理

| 对象 | 规则 |
|---|---|
| 结果目录 | 按 `<时间戳>-<类型>` 命名，同秒冲突顺延 1 秒，**永不覆盖旧目录**；多次 start 产生多个目录，可横向对比 |
| `operations.log` / `mount.log` | 根级追加，不轮转、不自动清理；长期使用需人工归档 |
| `summary.txt` | 每次 review 覆盖；需要保留多版结论时自行另存 |
| `monitor.csv` / `stress*.log` / `error*.log` / `*.exitcode` | 仅在本次结果目录内，进程结束后不再变化 |
| `/stresstest-hdd` | 系统盘压测目录，**测试结束后脚本不自动清理**；确认结果已拷回后手动 `rm -f /stresstest-hdd/*`（压测运行期间勿删） |
| `/mnt/HDDxx` | 挂载点不自动卸载；硬盘测试完成后按需 `disk-mount.sh umount` |
| 机器重启 | 进程不会自动恢复；已落盘日志保留；需重新 start |

## 10. 已知边界与注意事项

1. **控制台输出不落盘**：`install.sh` / `verify.sh` / `start` / `status` / `stop` / `review` 的控制台文本不会自动保存；需要留档时自行 `| tee` 或重定向。
2. **run-config 不记录实际盘目录**：hdd/combo 的 `命令:` 是参数模板，不含 `cd <盘目录>` 与 `--dirs` 展开结果；需要追溯盘序时结合 `stress-HDDxx.log` 编号与 `mount.log`。
3. **disk IO 为全局近似值**：`/proc/diskstats` 所有行求和，整盘与分区行重复计入，不能当作单盘或单进程的精确 IO。
4. **mem_used 含缓存**：`MemTotal - MemFree`，不代表应用真实占用；评估内存压力应同时看 `mem_avail`。
5. **monitor.csv 首行有延迟**：启动后约一个采样间隔才有第一行；短于间隔的测试也可能只有 1 行。
6. **error.log 表头导致“非空”**：新目录 `status` 会显示 1 行表头，不代表报错；判定看退出码与特征行。
7. **异常记录可能重复**：多进程分批退出时，同一非 0 退出码可能被巡检重复写入 `error.log`。
8. **hdd stderr 不汇总**：每盘 stderr 独立在 `error-HDDxx.log`，`review` 的“错误日志”段只展示 `error.log`。
9. **退出码缺失判异常**：`kill -9` / 重启可能导致 `.exitcode` 缺失，退出码文件数少于 `stress.pids` 行数时 `review` 判为异常（有 `status.txt` 时为 `ABORTED`/`missing-exitcode`，否则由缺失直接判异常），仍需结合 `error.log` 确认原因。
10. **手动 stop 的退出码**：通常非 0，也可能缺失；按“被中断”理解。
11. **mount 单盘失败不改变退出码**：格式化/挂载/卸载单盘失败仅提示并继续，脚本最终退出码可能仍为 0，需查看输出与 `mount.log`。
12. **已挂载盘不占挂载编号**：混合选择已挂载盘与未挂载盘时，可能出现 `/mnt/HDDxx` 分配冲突；建议先卸载或只选未挂载盘。
13. **并发压测不阻止**：脚本允许同时启动多个测试；同一块盘同时跑多个 hdd 会互相干扰，结果不可比。
14. **dmesg 只读、不清空**：监控在启动时以当前 ring buffer 行数初始化 `.dmesg.cursor`，之后每轮只读游标之后的新增行，**从不执行 `dmesg -c`**，不会清空内核环形缓冲区，也不影响其他依赖 `dmesg` 的工具；多个并发批次各自维护游标、各自记录一份 OOM 证据。
15. **时间依赖本机时钟**：`status` 剩余时长与 `review` 预计结束时间都按系统时间计算；压测中途改系统时间会导致估算偏差。
16. **运行中 review 是部分数据**：不会等待结束，退出码可能尚未生成；正式复盘应在测试结束后执行。
