# 压测输出日志解读方案（判定方法与流程）设计

- 日期：2026-11-14
- 版本：v3（修订内容：C 闸门由"隔离性/降级"改为"指标口径"，新增 4.3 混合模式判定；混合会话可判 `OK`，不再因并发降级）
- 状态：已确认（v1 2026-11-14，v2 待评审）
- 适用对象：`tmp/stress-test*` 各批次结果目录（脚本版本不限）
- 需求来源：用户需要对"测试中/已完成"的压测输出日志形成一套**可复用的解读方法**，明确"这批数据是否正常"，且要求**先出方法、不直接下结论**；判定必须能区分"数据可用"与"数据无效"。
- 本文档只定义方法、流程、判据与输出格式，**不包含任何针对具体批次的结论**。

## 1. 目标与非目标

### 1.1 目标

- 给出一套固定的解读顺序：先核验前置事实，再抽取事实，再过有效性闸门，最后才读性能指标。
- 对任一"批次目录"能稳定产出六态之一：**可用 / 有条件可用 / 进行中 / 已中断 / 数据无效 / 证据不足**。
- 对"进行中"的批次能产出中途健康态：**正常 / 带瑕疵正常 / 异常 / 不可判定**，并带明确时间点。
- 每条产出都必须附带证据（文件、时间点、字段）与确定性等级。
- 把"不得下结论"的情形写成硬规则，避免用"看起来正常"补位。
- **规则必须可直接执行**：给定一个批次目录（可附带现场采集文件），按本方案无需再做任何判断，即可产出第 6 章固定字段的结果。

### 1.2 非目标

- 不修改 `stress-test.sh` 及其产物格式（相关修复另立设计）。
- 不新增依赖、不引入自动判定的服务或定时任务。
- 不自动给出性能达标结论；达标阈值需按机型/验收标准单独确认。
- 不改写历史批次目录中的任何文件。

### 1.3 交付形态（已确认）

- 交付物为**手册 + 模板**：本文档 + 第 6 章两张卡。
- 不交付自动分析脚本；阶段 2.5 所需的现场信息由使用者按清单执行并回填。
- 若后续要脚本化（离线解析或现场采集），另立设计，不并入本方案。

## 2. 关键概念

| 术语 | 定义 |
|---|---|
| 容器 | 一个 `stress-test-N` 目录（一台机/一次导出的拷贝容器，本身不参与判定） |
| 批次 | 容器内的一个 `<时间>-<类型>` 子目录（一次 `start` 产生，**判定单元**） |
| 任务 | 批次内一次 `stress` 进程运行（cpu / mem / hdd 单盘 / sysdisk） |
| 对象 | 被压测的实体：CPU、内存、某块盘、系统盘 |
| 快照 | 从服务器拷贝到本地的副本；**快照时间 ≠ 批次结束时间** |
| 拷贝时刻 | 用户执行拷贝的真实时间（本机时间）+ 服务器时间锚点换算后的值；用于判断"拷贝时是否仍在运行" |
| 覆盖异常 | 缺测（任务数 < 已挂载盘）/ 超测（任务数 > 已挂载盘）/ 无法对应（数量相等但无逐盘证据） |
| 直接证据 | 日志原文、退出码、`/proc` 现场输出 |
| 间接证据 | `monitor.csv` 曲线、`df` 等周期性采样 |
| 无证据 | 未采集或采集被丢弃的项 |

**确定性三级**：`确定`（有直接证据）/ `推定`（仅间接证据且无矛盾）/ `不可判定`（证据缺失或互相矛盾）。

**中途判定与最终验收是两套判据**：中途只回答"是否在跑、有无明显异常"，不回答性能是否达标。

## 3. 现状约束与已知盲区

解读方法必须显式处理以下约束（这些是工具/环境的固有特性，不是对某一批次的评价）：

| 编号 | 约束 | 对判定的影响 |
|---|---|---|
| L1 | 服务器时间可能与本机时间存在固定偏移（时区或时钟设置），且文件拷贝时间不能作为基准 | "运行了多久""是否中断"必须靠内部时间自洽性判断，绝对时长标 `不可判定` |
| L2 | `monitor.csv` 的磁盘读写为整机 `/proc/diskstats` 汇总，含分区与 dm，可能重复计数 | 不得据此给出单盘吞吐；只能作为"整机活动量" |
| L3 | `run-config.txt` 不记录实际测试目录；hdd 日志名 `stress-HDD01.log` 为循环序号 | 覆盖性无法从文件反查，需现场 `/proc/<pid>/cwd` 或命令历史 |
| L4 | 监控循环每轮清空 `dmesg` 且仅保留 OOM 相关关键字 | 其他内核事件可能已丢失，`无报错` 不等于 `无内核故障` |
| L5 | `stress --hdd` 顺序写后立即 unlink，无读回校验；大内存机型下写入可能停留在 page cache | 写吞吐低/为零时可能是"未真正落盘"，也可能是"落盘后未采样到"，需按观测有效性闸门处理 |
| L6 | 无 `.exitcode` 可能是"仍在运行"，也可能是"被强杀"；两者外观相同 | 必须结合采样是否仍在增长与现场进程状态区分 |
| L7 | 旧版本批次可能缺少 `error.log` / `info-before.txt` / `summary.txt` | 字段缺失需登记为证据缺口，不得当作"无异常" |
| L8 | `stress` 正常收尾会输出 `successful/failed run completed in Ns`；无此行说明未走完正常收尾 | 该行是运行完整性的关键直接证据 |

## 4. 解读流程

### 阶段 0：前置核验（只采集，不判定）

| 编号 | 事项 | 采集内容 |
|---|---|---|
| 0.1 | 时间基准 | 目录名时间、`run-config` 开始时间、`monitor.csv` 首末行、外部时间锚点（现场 `date`/`timedatectl`，若有） |
| 0.2 | 版本与文件清单 | 是否存在 `run-config.txt`/`info-before.txt`/`info-after.txt`/`error*.log`/`summary.txt`/`*.exitcode`/`*.pids` |
| 0.3 | 并发识别 | **同一容器内**各批次（子目录）的开始时间与 `monitor.csv` 区间两两求交；跨容器不比较（不同机器） |
| 0.4 | 测试声明 | 类型、超时秒数、监控间隔、机型、命令、HDD 字节 |

**关卡 A（时间可用性）**

- 走时准确：`(末行−首行)` 与 `(行数−1)×间隔` 偏差 ≤1%（或 ≤2 个采样间隔）→ 走时正常。
- 绝对时间：存在外部锚点才可换算真实时间。
- 无锚点时：**不得**用"快照时间 − 末行时间"推断停机时长；相关结论标 `不可判定`。

### 阶段 1：单批次事实抽取（只填表，不评价）

| 编号 | 来源 | 抽取内容 |
|---|---|---|
| 1.1 | `run-config.txt` | 机型/类型/开始时间/超时/间隔/命令/HDD 字节/结果目录 |
| 1.2 | `operations.log` | 事件序列：start / stop / umount（含时间戳） |
| 1.3 | `info-before.txt` / `info-after.txt` | CPU、内存、磁盘清单、挂载点、文件系统、可用空间 |
| 1.4 | `stress-*.log` | 启动行、收尾行、正常输出行 |
| 1.5 | `error*.log` | 文件大小、是否有正文、按任务分别记录 |
| 1.6 | `monitor.csv` | 行数、首末时间、间隔一致性、空字段/负数行、swap 非零行、内存低值行 |
| 1.7 | `*.pids` / `*.exitcode` | 进程号、退出码是否存在及取值 |
| 1.8 | `summary.txt` | 存在则记录其结论字段（旧版本可能无） |

### 阶段 2：有效性闸门（决定"能不能用"，这里不读性能）

| 闸门 | 判据 | 不通过时的处置 |
|---|---|---|
| B 运行完整性 | 按 4.2.1 的证据分级（B1~B4）逐任务判定 | B4 时不得判结束，转入 4.2.3 区分 `RUNNING` / `ABORTED` / `UNKNOWN` |
| C 指标口径（原隔离性） | 同容器内与本会话时间重叠的任务，按**共享资源**区分：同类型且对象不同 → 合法并行；**跨类型**（cpu/mem/hdd 同时跑）→ **混合模式**，这是设计上的组合压力，**不算缺陷** | 混合会话**不影响状态**；仅把单项指标标 `N/A(混合)`，整机聚合指标照常可用（见 4.3） |
| D 覆盖性 | 按 4.2.2 判：缺测 / 超测 / 无法对应 | 缺测、超测 → `OK_LIMITED` 并列出缺口；无法对应 → 覆盖列填 `不可判定` |
| E 观测有效性 | 该类型特征指标确有变化（见 5.2）。hdd 无单盘列，只能用整机写吞吐作**代理** | 不达标 → 该类型指标标 `N/A(空跑)`，状态最高 `OK_LIMITED` |

#### 4.2.1 B 闸门的证据分级

| 级别 | 条件 | 处置 |
|---|---|---|
| B1 | 每个任务 `exitcode=0` **且** 有收尾行 | 判"正常结束"（确定） |
| B2 | 仅 `exitcode=0`，或仅收尾行 | 判"正常结束"（推定） |
| B3 | 两者皆无，但有时间锚点且采样末点 ≥ 开始时刻+超时−2 个采样间隔 | 判"超时结束"（推定） |
| B4 | 两者皆无且不满足 B3 | 不得判结束，转 4.2.3 |

#### 4.2.2 D 闸门的覆盖异常

| 类型 | 判据 | 处置 |
|---|---|---|
| 缺测 | 数据盘任务数 < 已挂载数据盘数 | `OK_LIMITED`，列出未覆盖的盘 |
| 超测 | 数据盘任务数 > 已挂载数据盘数 | `OK_LIMITED`，并检查会话内根分区已用增量（>5G → 标注"疑似写入系统盘"） |
| 无法对应 | 数量相等，但无 `/proc cwd`、活动文件或命令历史证据 | 覆盖列填 `不可判定`，不得写"已覆盖" |

#### 4.2.3 未收尾批次的三种处置

| 条件 | 状态 |
|---|---|
| 采样末点距拷贝时刻 ≤2 个采样间隔，或现场 `pgrep` 有对应进程 | `RUNNING`（进行中，不得判结束） |
| 有终止证据：采样末点远早于拷贝时刻（>2 个间隔），或现场 `pgrep` 无进程 | `ABORTED`（已中断） |
| 拷贝时刻无锚点且无现场进程证据 | `UNKNOWN`（证据不足） |

**硬规则 R-01（快照边界 ≠ 事件时点）**

> **快照末行时间早于该批次的计划结束时间时，必须先确认快照抓取时刻；在未确认之前，不得推断"中断""被杀""故障"。**

理由：快照末行只代表"数据被复制到这一刻"，不代表"进程在这一刻停止"。二者在离线数据上完全等价，无法区分。历史事故：2026-11-14 的 `20261114-11xx` 批次末行停在 21:15:46，被误判为"整体中断/被 kill"，实际任务跑满 36001s 且 `exitcode=0`，只是快照在 21:15:46 抓取。

执行要求：

1. 末行 < 计划结束时间 → 该批次**一律先记 `UNKNOWN`**，并在解读卡"未知项"中写明 `末行早于计划结束 X 分钟，快照时刻待确认`；
2. 可用于确认抓取时刻的锚点（按可信度从高到低）：
   - 用户明确的拷贝时间；
   - 现场 `date` + 目录 mtime 联合判断；
   - 拷贝目录本身（非文件）的 mtime；
3. **禁止**使用单个文件的 mtime 推断抓取时刻——`cp -a`/`rsync -a`/`scp -p` 会保留源文件的写入时间，mtime 只反映"文件何时被写"，不反映"何时被复制"；
4. 抓到新快照后若出现 `.exitcode` 与收尾行，按 4.2.1 重新定级（本规则不阻止升级为 `OK`）。

**六态判定（每批次只能落一个）**

| 状态码 | 名称 | 条件 |
|---|---|---|
| `OK` | 可用 | B1/B2，且 D、E 通过（**混合会话同样可判 OK**） |
| `OK_LIMITED` | 有条件可用 | B1/B2，但 D 或 E 受限（覆盖不全 / 疑似空跑），对应指标标 `N/A(原因)` |
| `RUNNING` | 进行中 | B4 且满足 4.2.3 第一条 |
| `ABORTED` | 已中断 | B4 且满足 4.2.3 第二条 |
| `INVALID` | 数据无效 | 任一任务 `exitcode≠0`、stress 日志出现 `failed run completed`、或写错误 |
| `UNKNOWN` | 证据不足 | 关键文件缺失（`run-config.txt`/`monitor.csv`），或无法区分 RUNNING 与 ABORTED |

### 4.3 混合模式判定（当会话内 cpu/mem/hdd 同时运行时启用）

混合模式是**组合压力测试**的常态，判定目标从"单项达标"改为"整机在组合负载下是否稳定，且负载是否真的加上去了"。

**状态判定（与单类型一致，不因混合降级）**

| 项 | 判据 |
|---|---|
| 运行完整性 | 同 4.2.1（B1~B4） |
| 覆盖 | 同 4.2.2（缺测/超测/无法对应） |
| 负载达成（替代 E 的单项判据） | 见下表 |

**负载达成度（混合模式）**

| 维度 | 判据 |
|---|---|
| CPU | 会话内 `%CPU` 均值 ≥90%（混合负载下应接近满载） |
| 内存 | `used` 峰值 ≥ 目标占用的 **80%**（设计约定：压到设计值的 80% 左右即视为达成）；且 swap 未打满、无 OOM 记录 |
| 磁盘 | 整机写吞吐非零窗口占比 ≥70% |
| 稳定性 | 无 `exitcode≠0`、无 `failed run completed`、无新增 `error.log` 正文 |

**指标口径（混合模式）**

| 指标 | 可用性 |
|---|---|
| 整机 CPU 使用率、load、整机磁盘读写吞吐、内存总量/可用量 | ✅ 可用（组合口径） |
| 单盘吞吐、单类型 CPU 达标率、单任务内存占用 | ❌ 标 `N/A(混合)` |

> 结论表述固定为"**组合负载下整机稳定/不稳定**"，不得写成"CPU 达标 / 磁盘达标"这类单项结论。



**必须使用增量证据 + 现场信息**；用旧快照判断"现在"的状态不成立。

**输入清单**

| 编号 | 输入 | 来源 |
|---|---|---|
| I1 | 最新批次目录快照 | 重新拷贝批次目录 |
| I2 | 当前时间与时间基准 | `date; date -u; timedatectl` |
| I3 | 进程与工作目录 | `for p in $(pgrep -x stress); do echo "$p $(readlink /proc/$p/cwd)"; done` |
| I4 | 采样是否增长 | 前后两次 `wc -l monitor.csv` |
| I5 | 错误日志大小 | `ls -l error*.log` 与上次快照比对 |
| I6 | 资源边界 | `free -g`、`df -h / /mnt/HDD*` |
| I7 | 内核事件抽样 | `dmesg -T \| tail -50` |

**判定维度（逐项只记 通过 / 不通过 / 无法判断）**

| 维度 | 判据 |
|---|---|
| 进程存活 | 进程数 = 声明任务数；cwd 与声明对象一一对应 |
| 采样连续 | 末行时间距现场当前时间 ≤ 2 个采样间隔；行数单调递增 |
| 时间自洽 | 首末差与"行数×间隔"偏差 ≤1% |
| 观测有效 | 特征指标非零窗口占比达标（5.2） |
| 错误增量 | `error*.log` 大小与上次一致、无新增正文 |
| 资源边界 | swap=0、MemAvailable 高于安全线、系统盘剩余 > 2×测试文件、无 OOM 行 |
| 结束信号 | 未到超时时间**不应**出现 `.exitcode`；出现即提前结束 |
| 覆盖完整 | 每个声明对象都能在 `/proc/<pid>/cwd` 或活动文件中找到对应 |

**中途四态**

| 状态 | 条件 |
|---|---|
| 正常（进行中） | 8 项全部通过 |
| 带瑕疵正常 | 进程与采样正常，但覆盖不完整或观测有效性不足 |
| 异常 | 进程消失 / 采样停更 / 错误日志增长 / 边界告警 / 提前出现 exitcode |
| 不可判定 | 时间基准未确认或缺现场信息 |

**硬约束**

- 中途正常 ≠ 最终通过。
- 输出必须带时间点："截至 <服务器时间>（真实时间 <锚定值或不可判定>），状态为 <四态>"，否则结论很快失效。

### 阶段 3：指标解读（仅对 `OK` / `OK_LIMITED` 执行）

1. **先写死口径**：指标是整机汇总还是按对象；是否存在整盘/分区/dm 重复计数；采样间隔能捕捉的最短峰值。
2. **统计规则**：剔除启动预热与收尾窗口；同时给均值、峰值、"零值窗口占比"；`OK_LIMITED` 只给趋势。
3. **异常事件**：`error*.log` 正文、退出码、环境基线变化（`info-before` vs `info-after`）。
4. **表述格式**：`结论 + 依据（文件/时间点/字段）+ 确定性（确定/推定/不可判定）+ 未覆盖项`。

### 阶段 4：跨批汇总

- **覆盖矩阵**：对象 × 批次，每格标 `测过 / 未测 / 不可判定`。
- **时间换算表**：服务器时间 ↔ 真实时间，逐批列出；无锚点则整列 `不可判定`。
- **横向对比**：仅允许在"同版本脚本 + 无并发 + 同为 `OK`"的批次之间做。

### 阶段 5：禁止结论清单（硬规则）

出现以下任一情况，禁止给出对应结论：

1. 无 `.exitcode` 且无正常收尾行 → 不得说"通过 / 跑完"；须先按 4.2.3 判为 `RUNNING` 或 `ABORTED`。
2. 跨类型混合 → 不得给单项性能数字，但**不得因此判不合格**；按 4.3 给"组合负载"结论。
3. 指标为整机汇总 → 不得给单盘吞吐。
4. 时间基准不明 → 不得说"跑满 10h / 中途停了 N 小时"。
5. 覆盖无法一一对应 → 不得说"所有盘都测过了"。
6. 仅"日志无报错" → 不得说"设备没问题"（须同时列 L4/L5 盲区）。
7. 观测有效性未通过 → 不得把该类型指标写入验收结论。
8. 快照末行早于计划结束时间且抓取时刻未确认 → **不得推断中断/被杀/故障**，一律先记 `UNKNOWN`（见 R-01）。

## 5. 判据参数（默认值，可调）

### 5.1 通用

| 参数 | 默认值 | 说明 |
|---|---|---|
| 走时偏差容差 | ≤1% 或 ≤2 个采样间隔 | 首末差 vs 行数×间隔 |
| 采样覆盖下限 | ≥90% | 实际行数 / 理论行数 |
| 并发判定 | 重叠 >1 个采样间隔 | |
| 预热/收尾剔除 | 首尾各 2 个采样点 | 避免启动与退出抖动 |
| 会话归并阈值 | 120s | 同容器内启动间隔 ≤120s 归为同一会话 |
| 强制分会话 | 两次启动之间已挂载盘集合发生变化 | 防止把"挂载修复前/后"合并（见 `stress-test-6`） |
| 未收尾判定窗口 | 2 个采样间隔 | 见 4.2.3 |
| 根分区增量告警 | >5G | 超测时判定"疑似写入系统盘" |

### 5.2 按类型

| 类型 | 观测有效性判据 | 资源安全线 |
|---|---|---|
| hdd | 整机写吞吐（作为代理）非零窗口占比 ≥70%；单盘吞吐一律标 `不可判定` | 系统盘剩余 > 2×测试文件；目标盘剩余 > 2×测试文件 |
| cpu | 采样 `%CPU` 与"线程数/总线程"落差 ≤5 个百分点 | — |
| mem | `used` 峰值 ≥ 目标占用 **80%**（设计约定：80% 左右即视为达成） | swap=0；MemAvailable ≥ 50G |

> 说明：以上为通用默认值，其中内存 80% 一项已于 2026-11-14 由用户确认（原 90% 过严，与"压到 90% 左右"的设计意图不符）。其余机型的验收阈值需另行确认，本文档不预设"多少算达标"。

## 7. 方法与流程的自检

用**已知答案的历史批次**做回归，验证六态判定正确，而不是验证性能数字：

1. 一个跑满超时、`exitcode=0`、有收尾行的批次 → 应判 `OK` 或 `OK_LIMITED`。
2. 一个无 exitcode、无收尾行，但采样末点距拷贝时刻 ≤2 个间隔且现场 `pgrep` 有进程 → 应判 `RUNNING`。
3. 一个无 exitcode、无收尾行，采样末点远早于拷贝时刻（>2 个间隔）→ 应判 `ABORTED`。
4. 一个 `exitcode≠0` 或日志出现 `failed run completed` 的批次 → 应判 `INVALID`。
5. 两个时间区间重叠且类型不同的批次 → 状态最高 `OK_LIMITED`，指标标 `N/A(并发)`，不得输出单项数字。
6. 一个缺 `error.log`（可选文件）的旧版本批次 → 关键文件齐全时判 `OK_LIMITED`，否则 `UNKNOWN`，并登记证据缺口。
7. 一个观测有效性不达标的批次（如写吞吐零值窗口过半）→ 最高 `OK_LIMITED`，且禁止写入验收结论。
8. 中途体检：对同一批次相隔 30 分钟取两份快照，第二次行数应增长；未增长则判"异常"。
9. **快照边界回归**：一个末行早于计划结束时间 8 分钟、无 exitcode、无现场进程证据的批次 → 必须判 `UNKNOWN` 并在未知项写"快照时刻待确认"，**不得**写成 `ABORTED`、中断、被 kill 或盘故障。再取一份含 `exitcode=0` 与收尾行的新快照后，应可升级为 `OK`。

## 8. 测试结束后的执行清单

### 8.1 执行顺序（不可颠倒）

1. **现场采集**（只读，见 8.2）→ 得到 `stress-evidence-<时间>.txt`
2. **拷贝结果目录** → 记录拷贝时刻（本机时间）
3. **阶段 0/1**：时间基准、文件清单、会话归并、事实抽取
4. **阶段 2**：B 分级 → C 隔离 → D 覆盖 → E 观测 → 六态
5. **阶段 3**：仅对 `OK` / `OK_LIMITED` 读指标
6. **输出**：`result.csv`（每批一行）+ `report.md`（每会话一节）

> 若时间基准为"不可判定"，则 B3 不成立，只能用 exitcode / 收尾行 / 现场进程三条证据判结束。

### 8.2 现场采集命令（整段复制执行，只读）

```bash
{
  echo "== date =="; date; date -u; timedatectl 2>/dev/null | head -8
  echo "== uptime =="; uptime; uptime -s
  echo "== stress procs =="; pgrep -a stress || echo NONE
  for p in $(pgrep -x stress); do echo "$p cwd=$(readlink /proc/$p/cwd)"; done
  echo "== df =="; df -h / /mnt/HDD* 2>/dev/null
  echo "== active stress files =="; ls -lh /mnt/HDD*/stress.* 2>/dev/null
  echo "== monitor mtime =="; ls -l /root/stress-test/*/monitor.csv 2>/dev/null | tail -20
  echo "== exitcodes =="; ls -l /root/stress-test/*/*.exitcode 2>/dev/null
  echo "== error logs =="; ls -l /root/stress-test/*/error*.log 2>/dev/null
  echo "== dmesg tail =="; dmesg -T | tail -80
  echo "== smart =="; for d in /dev/nvme*n1 /dev/sd?; do echo "-- $d"; smartctl -a "$d" 2>/dev/null | grep -iE 'Media and Data|Percentage Used|Available Spare|Temperature|Reallocated|Pending|Uncorrectable|Power_On'; done
} > /root/stress-evidence-$(date +%Y%m%d-%H%M).txt 2>&1
echo "saved: /root/stress-evidence-$(date +%Y%m%d-%H%M).txt"
```

## 10. 验收标准

- 按本流程对任一批次能产出 6.1 格式的解读卡，且每个字段都有来源或标 `不可判定`。
- 对进行中批次能产出 6.2 格式的体检卡，含明确时间点与 8 维结论。
- 批次状态必须落在六态之一，且每条的判定依据可回溯到 4.2.1~4.2.3。
- 任一结论若触犯第 5 章任一条，即视为方案执行错误。
- 用第 7 章的 8 个场景回归，六态判定全部正确。
